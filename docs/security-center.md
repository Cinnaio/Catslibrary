# 安全与风控中心

入口为 `/admin/security`，六个视图通过 `view=overview|service|policy|mail|events|restrictions` 寻址。初版 API / Web `0.9.0` 与 Web `0.9.1` 导航修复已发布，实际记录见 `docs/releasing.md`；本轮邮件安全配置入口为 API / Web `0.10.0` 源码候选，尚未构建或部署，iOS 交付状态不变。

## 权限和界面

超级管理员可查看全部视图并调整策略、核对预算、取消待发任务、核实未知结果、添加与解除限制。敏感写入必须具有近期密码或 Passkey 身份确认，填写原因，记录脱敏前后状态。普通管理员仅能查看当前普通读者的邮件与关联事件，不能查看管理账号记录、全站匿名事件或修改策略。服务端与导航、深链使用同一权限边界。

安全概览显示本站日/月预占与消耗、普通额度、拦截、待发与未知结果、近两周趋势及当前告警。70%、90% 和达到上限分别提示；未配置密钥、强制验证未就绪、工作进程心跳中断、连续失败冷却、备份恢复核对和未知结果合并为当前告警。告警只在后台展示，不发送额外告警邮件；问题恢复后对应提示消失。

邮件服务复用原 SMTP 配置，保留旧站点设置入口；切换视图保留未保存草稿。连接测试不发信。真实投递测试只发送至操作人本人已验证邮箱，并计入普通预算。配置密码不回显，修改原因及脱敏前后配置进入审计。配置文件写入与数据库不是同一事务，因此先持久化 pending 审计，再替换文件，最后更新结果；异常中断的 pending 需人工核对实际配置。

邮件记录区分服务商已受理、收件服务器已接收和用户实际阅读，后者不作推断。结果未知的任务支持核实已受理或失败；两种核实均保留额度且不会重发。风控事件按来源、账号、场景、规则和 15 分钟窗口聚合，可直接对脱敏来源添加当前场景的 24 小时限制，不禁用目标账号。普通列表保留搜索、分页、过渡反馈、整页行阶梯入场及减少动态支持。

界面打磨（2026-11-07）：六视图沿用站点设置的默认分段导航、页头和面板布局；概览用普通键值信息显示预算与服务状态，近两周申请通过共享表格按需查看。策略改为双栏具名字段，校验预算关系；列表沿用共享筛选工具栏和数据面板，不重复显示标题。邮件详情用键值记录呈现投递过程，保留即时加载、失败重试和焦点恢复。外部用量核对默认收起，恢复保护时自动展开；限制表单只提供后端支持的例外组合。跨分区草稿与账号隔离保留，邮件配置未保存、本人邮箱未验证或发送尚未就绪时，真实测试显示对应提示。这轮仅修改 Web 及文档，继续纳入 `0.9.0` 候选；界面统一源码为 `5addd272`，父提交 `fce38471`；未推送、构建或部署。

## 默认预算与规则

升级兼容（2026-11-07）：早期开发库可能已记录 072／073，但缺少 `security_events.target_id`、`mail_jobs.budget_at`、`mail_jobs.had_unknown`，导致事件查询或邮件队列处理失败。新增迁移 074 会补齐三个字段；API 启动或 `npm run db:migrate --workspace api` 使用同一迁移流程。旧邮件预算按创建时间回填，未知发送状态依据任务及尝试记录保守恢复，既有预算与数据不清空。无法确定账号归属的历史事件仅供超级管理员查看。本地开发库已应用并验证查询恢复，生产环境尚未应用；详见发布记录。

| 控制 | 默认值 |
| --- | --- |
| 全站日/月预算 | 80 / 2400，按 UTC 日/月重置 |
| 日/月应急预留 | 20 / 400，普通发送最多占用 60 / 2000 |
| 普通发送每小时 | 10 封，滚动一小时 |
| 账号冷却 | 60 秒；同账号、收件人、用途合并待发任务 |
| 账号每 15 分钟 / 每天 | 3 / 5 封；每天为滚动 24 小时 |
| 新账号每天 | 注册首 24 小时最多 2 封 |
| 收件邮箱每天 | 跨账号累计 5 封 |
| 各场景请求 IP / 标识限流 | 每 15 分钟 20 / 6 次 |
| 全站各场景请求保护 | 每分钟 300 次，优先检查以约束写入量 |
| 队列发送节奏 | 所有进程共用最短 5 秒间隔 |
| 详细记录保留 | 30 天，可配置 1–180 天 |

请求计数与邮件预算独立。格式错误、无账号、被拒绝的申请不占用邮件预算。邮件任务、令牌与预算预占在一个数据库事务中提交；账号锁后取得全局风控事务锁，所有实例遵守同一顺序。额度账本独立于详细日志，不随日志清理回退。

只有经过管理员身份确认、权限检查和原因填写的协助恢复可使用应急预算。匿名重置、本人邮箱绑定与真实测试不能使用。应急操作仍遵守暂停、收件人停发、全站上限和管理员一分钟冷却。公开找回返回统一结果并等待至少 250ms；内部账号条件、预算或投递失败不向匿名调用者回传。此响应时长下限不等于任意负载下严格恒定时序。

限制可按账号、邮箱和 IP 以及用途设置，默认 24 小时、可设 1–720 小时。阻止规则优先于验证例外。例外只免除人机验证，不免除限流、收件人保护或预算；账号例外仅适用于已登录的邮箱绑定，不能靠匿名填写账号获得。IP、邮箱只存 HMAC 和脱敏提示，需保留稳定的会话哈希盐。代理部署必须正确设置可信代理边界。

## 邮箱域名黑白名单

超级管理员在“防护策略 → 邮箱域名”配置，覆盖邮箱绑定与更换、密码找回、管理员协助重置和真实测试邮件。复用现有策略保存、近期身份确认、原因、修订冲突与审计流程。默认黑白名单为空、白名单关闭，不预填任何服务商域名；启用白名单时必须至少填写一个有效域名。

黑名单始终优先：同一域名同时命中两份名单时拒绝发送。关闭白名单时，黑名单之外的域名可使用账号邮件；开启后，仅白名单内且未命中黑名单的域名可申请。白名单不会豁免人机验证、请求限流、邮件频率、预算、暂停或收件人停发；管理员应急邮件也遵守域名限制，原有应急额度和频率规则保持不变。

每行一个纯英文域名，例如 `example.com`，每份名单最多 200 个；保存时忽略大小写、首尾空格和空白行并去重。拒绝完整邮箱、`@` 前缀、网址、通配符和无效域名。默认只精确匹配；开启“同时匹配子域名”后，两份名单中的 `example.com` 同时匹配 `mail.example.com` 等子域名，但不匹配 `fakeexample.com` 或 `example.com.other.test`。Web 即时显示错误并阻止保存，服务端独立执行同样的名单校验；切换分区保留未保存草稿，名单输入区保持固定初始高度且可纵向调整。

入队前先检查域名，再处理重复申请、预占预算和邮件链接；拒绝申请不会创建任务、令牌或占用邮件额度。工作进程在发送前按最新策略再次检查，已有待发任务不能绕过新规则；未尝试发送的任务取消并退回预占，曾有未知结果的任务保留未知状态、额度及有效链接且不重发。被拦截的申请和队列任务记录 `mail_domain_blocked` 或 `mail_domain_not_allowed`，后台显示中文原因；匿名找回继续返回统一响应，不暴露账号或邮箱是否存在。已提交给服务商的发送不能撤回，域名配置不改变密码／Passkey 登录或已发出的链接消费规则。

配置存入现有 `security_policy.value.emailDomains`，无需新增数据库迁移。旧策略缺少该字段时使用默认配置；旧客户端保存其他策略时若不提供该字段，服务端保留现有域名名单。显式提交格式错误、空的已启用白名单或 `null` 时拒绝保存，不静默取消限制。新 Web 配置界面需配套本次 API；iOS 沿用统一账号邮件接口，由服务端执行规则。

## 客户端验证

找回密码默认强制验证；登录、注册和已登录邮箱变更默认观察；可逐场景关闭、观察或强制。观察只记录验证命中，不关闭其他保护。`GET /api/security/challenge?action=...` 返回当前场景配置，提交时后端仍独立验证令牌用途、域名及成功状态，客户端配置不能豁免后端校验。

Web 统一弹窗接入原申请流程，取消或失败保留输入；验证期间切换账号不提交旧申请。iOS 使用同一 HTTPS API 源上的 `/api/security/native-challenge` 页面，限定主框架与消息来源；令牌仅在内存中交回原请求。旧客户端在启用强制验证的场景会收到更新客户端或网页操作提示；新 Web/iOS 需要配套新 API。Passkey 登录继续使用原有协议，不追加此类验证码。

## 可靠投递与反馈

数据库迁移 `072_security_center.sql` 创建策略、计数、事件、限制、队列、预算、尝试和回调记录；`073_security_delivery_feedback.sql` 增加可处置来源哈希与投递反馈元数据。后者单独递增，兼容开发服务器已提前执行 072 的情形。API 启动时应用迁移，队列每 5 秒领取任务。

队列正文使用 AES-256-GCM 加密，任务 ID 作为认证关联数据；终态立即移除正文。待发窗口 10 分钟，领取租约 90 秒。发送前重查账号状态、凭据、邮箱、邮件令牌、管理员权限、限制与投递配置；失效任务取消。邮箱验证链接 24 小时、重置链接 30 分钟；同地址重复申请不作废之前的有效链接，换绑其他地址会废弃之前的换绑链接，成功确认或改密撤销该账号全部旧链接及会话。

SMTP 临时明确拒绝和 Resend 临时错误有限退避，最多 3 次；SMTP 结果未知直接等待人工核实。Resend API 未知结果仅在同一预算日、同一任务及 10 分钟队列有效期内使用相同幂等键和正文重试；不跨预算日盲目重试。发送前取消可释放预占；第一次明确拒收可退回额度；曾经出现未知、跨日边界或多次尝试则保守保留。服务商回调先于响应时不倒退状态；发送尝试仍保留。

Resend API 使用已保存的 `smtp.resend.com` 密码作为 API 凭据。Webhook `/api/security/resend-webhook` 使用后台保存的回调签名密钥（未保存时使用 `RESEND_WEBHOOK_SECRET`）验证原始正文及 Svix 签名，事件 ID 去重，乱序不倒退投递终态，无标签早到事件在取得服务商 ID 后补记。永久退信、投诉和服务商停发触发本站停发；临时退信只记失败，不长期封禁。相关失败邮件链接失效。服务商停发名单需在其控制台另行处理，本站解除不会自动解除外部名单。

## 邮件安全配置入口

超级管理员进入“安全与风控 → 邮件服务 → 队列加密”，可直接“生成并启用加密密钥”，或在“使用已有密钥”中填写 32 字节随机密钥的标准 Base64。队列加密与 Resend 投递回调使用和 SMTP 相同的独立设置面板，下方“投递测试”核对实际投递。生成在服务器执行，密钥原值不回传浏览器。已有生效密钥不可通过页面替换或清除；服务器配置格式错误时须修正原变量，密钥缺失而队列仍有加密正文时须恢复原密钥，禁止初始化导致旧邮件无法解密。

同一区域可填写 Resend Webhook 的 `whsec_…` 签名密钥，留空保留原值。回调地址根据已保存的邮件链接站点生成，可聚焦全选复制；不会从请求 Host 推导。需在 Resend 控制台配置此 HTTPS 地址和事件，再在本站防护策略选择 Resend API。SMTP 发信本身不要求回调配置，签名已配置也不等于外部回调已连通。

`GET/PUT /api/admin/security/mail-settings` 只允许超级管理员，写入沿用近期身份核实、4–300 字原因、账号／风控锁、修订冲突和脱敏审计。GET 与 PUT 响应禁止缓存，只返回配置状态、来源和地址。私有文件替换前先持久化 pending 审计，异常中断须核对文件实际状态；接口不记录或返回原始密钥。跨分区保留草稿，失败保留输入与原因，换账号清除；有未保存的安全配置时禁止刷新及真实投递测试。

私有文件默认位于 `data/mail-security-config.json`，可用 `MAIL_SECURITY_CONFIG_FILE` 指定持久目录；POSIX 新文件权限为 0600，目录创建权限为 0700，使用临时文件、同步写入与原子替换，不允许静态目录、损坏文件或符号链接文件。后台保存的对应字段优先于环境变量；未保存队列密钥时依次使用 `MAIL_QUEUE_ENCRYPTION_KEY`、`SITE_SETTINGS_ENCRYPTION_KEY`，未保存回调密钥时使用 `RESEND_WEBHOOK_SECRET`。损坏文件不会静默回退环境配置。

保存立即被队列加解密、工作进程、概览及回调验证读取，无需重启。此文件不进入数据库备份、Git 或静态构建产物；多实例必须共享同一私有文件，迁移服务器及重建容器时须保持文件持久化并单独安全备份。页面不修改进程环境变量、站点通用加密密钥或其他配置。

## 启用与恢复

1. 配置 SMTP、发件身份与固定 HTTPS 邮件链接 origin，或使用既有后台邮件配置。本站不自动创建服务商账号、验证发信域名或设置外部 Webhook。
2. 在邮件服务页生成并启用队列密钥，或设置稳定的 `MAIL_QUEUE_ENCRYPTION_KEY`（32 随机字节的 Base64），也可复用已有 `SITE_SETTINGS_ENCRYPTION_KEY`；所有实例保持一致且在私有位置备份，不写入 Git。缺少密钥时事务回滚，不能创建发送任务。
3. 配置 Turnstile 的站点 key、secret 和允许域名；默认强制找回密码在配置缺失时拒绝申请。敏感管理员恢复仍走身份核实与应急额度路径。
4. 如需 Resend 投递反馈，在邮件服务页保存签名密钥，在服务商控制台配置 HTTPS 回调，订阅 sent、delivered、bounced、complained、failed、suppressed，再在防护策略选择 Resend API。建议在服务商域名配置关闭账号邮件的打开与点击追踪。
5. 首次启用前核对服务商当前日/月用量及其他项目共享消耗，在概览录入包含待发和未知任务的保守总量。该操作只允许上调账本，不自动恢复发送。本站统计不是服务商账户完整用量。
6. 在后台核对队列加密、验证、工作进程心跳，按需执行已授权的真实投递测试，再查看受理／投递结果。

恢复备份会清除会话和邮件令牌、取消恢复出来的待发／发送中任务、清空其正文、结束关联 pending 审计，并暂停邮件。不会重发备份里的旧任务。核对外部日/月额度、录入保守总量解除恢复核对标记后，还需手动恢复发送；预算与未知消耗不自动退回。安全策略与限制变更参与恢复影响检查，队列计数和 5 秒心跳不让影响报告不断过期。

## 验证与边界

使用隔离 PGlite 数据库、合成账号和邮件 mock 验证事务回滚、预算、重复申请、请求保护、权限、未知结果核实、租约恢复、乱序回调与停发；Web 使用 jsdom 验证确认、取消、账号切换和草稿保留。没有实际发信、修改服务商设置或操作线上库。真实 PostgreSQL 多进程竞争、实际备份恢复、真实 Turnstile/Resend 回调以及 iOS Xcode 编译和真机操作仍需发布环境验收。

官方协议依据：Cloudflare Turnstile 服务端验证 `https://developers.cloudflare.com/turnstile/get-started/server-side-validation/`；Resend 幂等 `https://resend.com/docs/dashboard/emails/idempotency-keys`；退信字段 `https://resend.com/docs/webhooks/emails/bounced`。
