# 单本书的更新与来源

小说管理和追更任务列表的单书设置统一进入「更新与来源」。TXT／EPUB 等文件导入属于内容来源记录，不限制后续绑定网页或参考目录。

## 来源用途与操作

- **网页追更**：绑定作品目录链接，支持站点自动采用内置规则；自定义选择器与编码放在高级配置。只有配置完整时展示自动追更、频率及网页检查结果。没有配置时展示绑定入口，不展示不可用的频率或网页检查按钮。
- **附加文件更新**：只展示当前作品的绑定、来源检查结果和候选版本。查看候选版本进入现有文件预览流程；新增绑定固定到当前作品，核对文件书名与作者后确认。目录检查频率和开关仍由共享来源统一管理，编辑时明确提示影响所有绑定书籍。
- **章节名与顺序**：显示已保存的参考目录和上次融合时间，沿用已有融合预览、人工映射、确认与历史撤回流程。仅生成目录预览不等于已确认融合，也不会启动正文抓取。

全局「附加更新源」入口保留。文件候选数量和文件名中的更新数字不作为实际新增章节数；需下载、解析并预览后确认。检查失败或目录未读全均独立显示。

## 网页来源保存与任务

新增管理员动作 `POST /api/scrape`，`action=followup-source-save`，参数为 `novelId`、`sourceUrl`，可选 `selectors` 和 `encoding`。

保存时锁定作品，拒绝在活动抓取任务期间更换配置。保存更新抓取配置，并明确暂停该书网页追更；保留原检查间隔，标记为用户配置，避免默认策略重新开启。原网页检查快照、待入库统计和失败状态重置，等待新配置检查，不沿用旧来源的结果。不会创建抓取任务，不修改书名、作者、原作品来源地址、章节或参考目录。开启自动追更仍需要明确保存开关；网页配置失效的作品也能手动暂停。

未知站点必须提供目录与正文规则；内置规则采用完整域名匹配。保存配置只说明规则完整，网络访问、源站权限及实际正文仍在检查任务中验证。

## 文件导入与网页追更的衔接

网页去重与待入库计数均识别已确认的章节融合映射。拆分成多个本地章节的网页章，只有对应部分全部存在时才判为已入库。预览状态、已撤回映射和不完整拆分关系不会据此跳过网页章。

文件导入作品开始网页增量更新时，如果目录与现有章节没有可靠对应关系，任务停止并提示先读取参考目录、确认融合；如果未知条目位于已匹配章节之前，任务停止并提示核对中间章节。可靠尾章继续增量入库，重复检查不重复新增。显式失败章节重试沿用原流程。

附加文件入库继续保留已融合的标题与本地顺序，尾章追加、正文版本选择、插章冲突和打赏章保留规则见[附加源说明](supplementary-sources.md)和[导入联动验证](import-source-linkage-validation-2026-10-18.md)。

## 验证边界
