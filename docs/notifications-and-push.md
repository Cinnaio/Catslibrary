# 消息中心与推送

2026-11-26 源码候选：API 1.15.0、Web 1.14.0；iOS 沿用尚未交付的 1.4.0 / build 31。源码为包含本节的本地提交，父提交为 `3a7dbe11`，实际构建及交付状态见 [发布记录](releasing.md)。

## 使用入口

Web：个人中心或头像菜单 → 消息中心 → 通知设置。iOS：我的 → 消息中心 → 通知设置。消息列表提供全部／未读、分页、刷新、全部已读及详情。已读状态保存在账号下，两端重新进入或刷新时同步；Web 前台列表每 30 秒刷新，个人中心计数每 60 秒刷新，隐藏页面暂停。列表最多每页 30 条，消息保留 90 天。

- 评论回复：别人回复自己的评论且内容可见后入箱，自己回复自己不通知；隐藏或删除原评论／回复后不再展示。Web 点击可定位对应主评论及回复，iOS 展示回复内容并提供网页对话入口，网页需要自己的登录会话。
- AI 任务：任务从排队／运行变为完成或失败时入箱，仅归发起人。任务被删除或失去管理员权限后入口失效。分析任务可打开原报告；其他任务进入任务中心并打开对应任务详情。iOS 也可打开原生任务详情。反复写入终态不会重复创建消息，取消任务不通知。
- 追更：在通知设置中为收藏作品单独订阅。仅接入已有的书源追更任务结算，不自动修改站点抓取计划。每轮按实际保存的新 URL 合并数量，订阅时已有目录中的旧章、文件导入和普通章节编辑不会触发。未知目录或更换书源的首次检查建立基线，之后才通知。移出收藏自动停止订阅；未开启定时检查的作品会明确提示，检查时效由原有书源任务决定。
- iOS 本机阅读提醒：在通知设置中选择时间与星期，主动保存时申请系统通知权限。安排在本机执行，无需联网；按站点和账号分别保存偏好，退出账号清除安排与已显示提醒，重新登录恢复已经授权的安排。提醒不含书名或账号信息，点开进入原生 App。

## 主屏幕网页推送

iPhone／iPad 使用 Safari 打开同源 HTTPS 站点，添加到主屏幕，再从该入口打开、登录，在通知设置中主动点击「开启推送」。最低系统条件是 iOS／iPadOS 16.4；原生 App 本身仍受项目的 iOS 部署目标约束。网页推送不使用原生 APNs entitlement 或 Apple Developer Program 证书；原生 App 不会因此获得远程推送能力。

通知点击进入网页版消息详情。站点提供 manifest 和根作用域 `/sw.js`，Worker 仅处理推送，不缓存正文、登录页面或 API，不提供离线网页阅读。不支持推送的浏览器仍能使用消息中心。API 与 Web 必须同源，跨域部署会阻止开启推送并给出说明。

默认锁屏只显示「你有一条新消息」。开启预览后才显示消息类型和书名，不包含评论正文、AI 输出或错误详情。推送载荷仅含消息 ID；Worker 通过当前 HttpOnly Cookie 读取安全模式预览，登出、访问撤销、内容变为受限或离线时仅显示通用提示。通知已显示在锁屏后，服务器无法保证即时撤回；主屏幕网页本机退出时会尽力关闭已显示的网页通知。

每账号最多 10 个订阅，可分别移除。订阅绑定当前登录会话，会话注销、全端退出、撤销或过期后停止投递；再次登录需主动重新连接。浏览器更换账号时创建新订阅，不把其他账号的 endpoint 转移给当前账号。发送测试通知仅针对当前会话绑定的设备，每设备至少间隔一分钟。

## 服务端配置与发布

1. 应用 `api/src/db/migrations/099_notifications.sql`，再发布 API，然后 Web／iOS。迁移不补发历史消息。开发服务已有数据库时也需要迁移，否则消息接口不可用。
2. 超级管理员打开「管理后台 → 站点设置 → 消息推送」（`/admin/site-settings?view=push`），填写真实联系邮箱或 HTTPS 联系页面，选择「自动生成新密钥」并点击「生成并保存」。也可导入已有公私钥。私钥在服务器生成与保管，不回传；手动导入成功后清空私钥输入。保存后立即生效，无需重启。配置完成后在消息中心开启当前设备，再主动发送测试通知。
3. 整套后台配置保存在服务端私有文件 `data/web-push-config.json`，优先于 `WEB_PUSH_PUBLIC_KEY`、`WEB_PUSH_PRIVATE_KEY`、`WEB_PUSH_SUBJECT` 环境变量；未保存后台配置时继续兼容环境变量。可用 `WEB_PUSH_CONFIG_FILE` 指定持久化私有路径。部署账号须有目录写入权限；文件按 0600 权限原子替换（Windows 使用目录 ACL），禁止位于静态目录，不进入数据库备份或仓库。迁移服务器时须另行安全迁移此文件；多 API 实例需共享该持久化路径。环境变量改动仍需重启。私钥不要写入日志或 `VITE_` 变量。配置缺失、损坏或不匹配时停止远程投递，消息中心继续可用。当前后台发送使用 HTTPS 直连，需要服务器能访问 Apple／Google／Mozilla／Windows 推送服务。
4. 确保反向代理将 `/sw.js`、`/manifest.webmanifest` 和 `/messages` 交给 Web／API 静态服务，不把 Worker 返回为 HTML；部署时保持脚本 `Cache-Control: no-cache`。Vite 构建会复制公共资源，API 的静态路由已包含它们。

修改联系地址默认保留密钥；暂停推送保留密钥与订阅，且不会回退到环境变量。生成或导入不同密钥需确认：旧订阅停止投递，各设备需重新进入消息中心并开启推送，浏览器自动更换旧密钥订阅；正在发送的请求可能已交给服务商。保存带版本检查，冲突时保留草稿，撤销后可重新读取。配置写入只对超级管理员开放，并记录不含私钥的操作审计。

新增数据：`notifications`、`notification_settings`、`notification_subscriptions`、`notification_deliveries`、`notification_book_watches`。评论与 AI 任务数据库触发器让事件和业务写入处于同一事务，消息插入再原子排入设备队列；追更沿用既有事务。网络发送由独立后台队列完成，不阻塞评论请求或 AI 网络执行。每条消息／设备只保留一份投递记录；使用租约、退避重试，最多五次，404／410 移除失效订阅。已读、失去访问权限、关闭的类别、超过一天的消息跳过推送。

免打扰使用账号指定的 IANA 时区，跨夜与夏令时均按当地时间计算；结束后发送尚未读且仍有效的消息，测试通知不受免打扰影响。服务商接受不等于设备已展示；系统可延后展示。进程在发送成功后、落库前崩溃时可能重试，使用稳定 notification tag 尽量替换同一提醒，不承诺严格恰好一次展示。备份恢复会清空会话并级联清除旧推送订阅及其投递，须重新登录并开启；订阅和投递不参与恢复影响快照比较。

## 验证与待验收

已执行隔离数据库下的账号隔离、事务回滚、重复终态、已读同步、隐藏／受限／权限撤销、设置版本冲突、设备解绑、失败重试、过期 endpoint、测试限频、跨夜与夏令时、追更基线与旧章排除测试。Worker 使用模拟浏览器环境验证 Cookie 预览降级、同源跳转及实际静态资源响应。Web 回归覆盖消息详情、失败保留、账号切换及追更设置；原生仅做 Swift 语法和导航静态检查。

真实设备验收需要部署后执行：主屏幕网页订阅 → 关闭页面 → 触发一条评论回复／任务结果 → 锁屏收信 → 打开正确消息 → 在原生 App 刷新确认已读；再核对拒绝权限、退出账号、免打扰、后台进程重启、追更及本机定时提醒。当前未发送真实 Web Push、未操作生产数据库、未做浏览器视觉验收或 iPhone 锁屏验收；Windows 无法完成 Xcode 类型检查、XCTest 或 IPA 构建。
