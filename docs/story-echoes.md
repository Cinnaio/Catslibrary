# 故事里的回声

在 Web 或 iOS 在线阅读器中选一句正文，打开「故事里的回声」，再点击「查找前文的回声」。打开面板不自动生成。结果最多三组，每组包含可回读的前文引句和明确标记为「可能的呼应」的解释；跳回原文后可返回最初选段。

## 范围和引用

- 接收同一段落的 4–200 个 UTF-16 单元。客户端长选段取前 200；Web 跨段划选沿用现有阅读器规则取占比最大的段内部分，iOS 分页跨段划选提示重新选择。
- API 先核对章节权限、段落编号、段落指纹及选句。只取目录 `(sort_order, id)` 严格在前的章节，以及当前章选句之前的文字。同段多次出现完全相同的选句时，以最早出现位置作为边界。
- 从选句分词及少量中文单字物件词中取最多 12 个检索词。筛选最多 60 个相关前文章节，每章最多保留 3 个候选，连同本章前文排序后最多发送 20 处、每处最多 440 字符，并附最多 1,200 字符的选句上文。检索会遗漏没有相同关键词的语义呼应；空结果不表示前文没有呼应。
- 模型不接收书名、章节标题、全书摘要、故事档案、本章选句之后的文字或后续章节。原文仅作为资料，提示词要求不执行其中命令，不使用书外知识，不断言作者意图。
- 结果逐条核对候选编号和连续引句，去除虚构、超长、重复或缺少解释的条目；不会把尚未核验的模型流直接显示给读者。解释属于模型推测，逐字核验不能证明其文学判断正确。
- 查看原文和返回选段都会重新读取章节（含同章跳转），再使用段落编号和指纹定位；同编号不再匹配时只接受唯一指纹。无法消歧或正文变化时提示无法定位，避免跳到其他同句。兼容 HTML 段落、Web 自动拆开的长段落、CR 历史锚点及归一化空白。iOS 请求使用 `sourceFormat: "text"` 获取与原生搜索跳转一致的文本段落锚点。

## 接口、额度与缓存

- `GET /api/ai/status` 新增可选能力字段 `features.storyEchoes`。需要登录、文本 AI 配置和现有 `recapEnabled` 开关；旧 API 缺少字段时客户端隐藏入口。
- `POST /api/ai/story-echoes` 接收 `chapterId`、`paragraphIndex`、`paragraphHash`、`selectedText` 和可选的 `sourceFormat: "text"`，返回 `anchor`、`items`、`cached`、`generated`、候选覆盖信息和模型名称。响应为 `private, no-store` JSON。
- 与其他读者 AI 共用 `dailyQuota`。没有候选时不调用模型；缓存命中不新增额度；完成调用后即便模型格式错误或正文变更导致结果丢弃，仍如实计费。上游结果不确定时沿用读者 AI 的额度预留规则。
- 缓存按数据库实例、账号、选段、模型及所有前文章节的编号、次序、标题和正文版本隔离，进程内最多 128 条、30 分钟过期；重启、多进程或缓存淘汰后可能重新生成。缓存不写入数据库。
- 同一进程内，同账号相同请求合并，其他并行选段返回冲突提示。生成前、完成后和复用缓存时重新核对正文范围；返回前再次核对作品访问权限。前文章节的修改、添加、删除或目录排序变化使缓存失效。
- Web 和 iOS 在账号、内容权限或面板生命周期变化后丢弃旧响应；iOS 离线阅读不开放入口。关闭面板后服务器可能仍完成已开始的调用，再打开可复用短期结果。

## 交付与验证

本功能无新增数据库迁移。先更新 API，再发布 Web 与 iOS。纳入现有 API `1.10.0`、Web `1.10.2`、iOS `1.4.0 / build 31` 源码候选；本次不交付 IPA。

隔离数据库与模型响应桩覆盖阅读边界、引文核验、锚点错误、空结果、配额、缓存失效、并发合并、生成期间目录/权限变更、HTML 跨端定位及异常结果计费。Web 定向回归覆盖显式生成、零额度缓存、过期选段、账号切换、关闭后迟到响应、空结果、重复引文、虚拟段落、空白归一化定位，以及同章／跨章回读时刷新正文和返回选段。

实际检查、构建和部署状态记录于 [发布与版本管理](releasing.md)。Swift 语法解析不能替代 Xcode 类型检查、模拟器或真机验收；真实模型的呼应质量仍需实际阅读时确认。
