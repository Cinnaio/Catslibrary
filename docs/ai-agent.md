# 对话创作

第一版面向管理员，在一本小说内通过持续对话查阅材料、讨论情节、生成和修改草稿、构思并生成封面。复用现有文本／图像服务、后台任务、草稿发布与封面候选接口，没有增加 Agent 框架；助手回复使用 `react-markdown` 与 `remark-gfm` 呈现 Markdown。

## 从哪里进入

后台「创作工作区 → 对话创作」，或作品工作区的「对话创作」入口。地址为 `/admin/ai?sub=agent&novel=<作品ID>&session=<会话ID>`。

1. 选择作品和续写起点，建立对话；不指定时绑定创建当时的最新章节，无章节的作品从新写开始。
2. 可以先说「先了解这本小说，和我讨论下一章的走向」，再通过对话调整方向。
3. 明确要求生成后，任务进度和结果出现在「产出与采纳」。例如「按照刚才第二个方案写一章」或「把上一版的冲突再收敛一点」。
4. 在草稿、改写建议或封面候选上预览，确认后才覆盖草稿、发布章节或替换封面。聊天中的“确认”会引导到保存的预览卡，不直接执行采纳。

桌面并排展示对话与产出，800px 以下通过按钮切换。Enter 直接发送，Shift + Enter 换行，也支持 Ctrl / ⌘ + Enter 发送；输入法选词和长按重复按键不会触发发送，空消息及正在提交／回复时不重复提交。已提交对话保存在服务端，页面刷新或离开不会清空记录或停止后台任务。尚未发送的输入仅保存在当前页面。

新旧助手回复均支持 Markdown 标题、加粗、列表、引用、表格、任务清单、链接与代码块；宽表格和代码块可横向滚动。原始 HTML 不执行，不安全的链接协议会被过滤。用户输入、任务状态、错误详情及草稿预览仍保留原文，服务端保存内容不变。

消息输入位于正文面板下方，是独立的紧凑浮动卡片，两者通过留白分隔。PC 端正文区增高，输入时不会被卡片覆盖或挤压；输入单行起步，多行时自动增高，超过视口相关上限后在框内滚动。卡片左侧可以选择“模型与服务”中已保存的文本预设；默认项跟随当前文本服务。模型选择随消息请求保存，同一回合及由助手提交的文本生成任务使用同一预设，封面生成仍使用图像端点；正在处理的回合不能切换模型。

## 模型与上下文

- 使用输入区所选文本预设，或跟随「系统设置 → 模型与服务」中当前文本模型；它必须支持 OpenAI 兼容 Chat Completions 的 `tools`、`tool_calls` 和工具结果消息。只通过普通文本连接测试不能证明工具调用可用。
- 封面生成使用现有图像服务及其配置。协调助手本身只读文字材料和候选描述词，不读取图像像素。
- 每个会话固定一本书与起点章节。正式正文和有效档案按该起点取材，章节原文支持分段读取和字面搜索；不能跨作品或越过起点读取正式章节。需要按新发布章节继续时，新建对话选择新起点。
- API `1.2.0` 候选在每轮开始读取未被摘要覆盖的近期事件；超过 60 条、序列化后超过 9 万字符，或存在尚未读取的旧记录时，将连续旧记录分批整理，保留最近最多 20 条且约 4 万字符的原文窗口。每批最多 60 条、通常不超过 6 万字符；单条超过 9 万字符时明确失败并保留原文。游标只推进到成功整理的最后一条，后续积累到阈值才再次摘要。预算按字符估算，不是供应商精确 token 计数。
- 「创作约定与偏好」供当前会话持续参考，保存时检查编辑版本；会话进行中的调整需要等待或停止回复。沿用已有 `contentPreferences` 字段和服务端验证，任务级偏好与作品分级保持各自的含义。

## 可执行的操作

| 能力 | 结果与确认方式 |
| --- | --- |
| 查阅小说、章节、有效文风／情节／关系档案 | 只读取材；信息不足或材料不完整时需要继续读取 |
| 单章续写／新写 | 生成未发布草稿，预览并确认后追加为正式章节 |
| 整章或选段改写 | 生成建议并保留原文；可沿着上一版未采纳建议继续调整 |
| 采纳改写与恢复草稿 | 保存前后版本，并校验当前正文修订号；已变化或已发布的草稿不会被旧预览覆盖 |
| 封面构思与生成 | 保存为候选，确认时再次检查封面版本；复用现有封面历史 |
| 显式更新小说分析 | 创建现有情节／关系档案任务，按正式章节分析，不把聊天假设变成事实 |
| 查阅历史任务与对话 | 通过任务和事件 ID 精确定位；已有采纳记录可继续查看 |
| 提出作品记忆 | 只保存待确认约定，作者在记忆面板确认后才跨对话生效 |

发布仍执行原有作品分级、草稿状态与事务检查；若站点原本启用了发布后故事档案更新，该现有行为也会继续执行。

第一版不直接修改已发布章节，不做跨作品批量操作，不提供任意网络、SQL 或系统命令工具。封面调整属于重新生成，不承诺保留原图的局部编辑或人物一致性；助手文字支持流式预览，封面图片在完成后显示。

## 流式回复与任务进度

助手生成期间逐段显示 Markdown，按任务与模型轮次区分临时预览和已保存消息，避免同一段文字重复出现。停留在消息底部时跟随输出，向上阅读时保持当前位置。工具参数完整返回并校验后才执行，不显示未完成参数或原始推理内容。

对话及其派生任务通过只读事件流更新进度；断线或刷新重新读取同一任务，不重新提交生成。失败后的部分文字标为未完成，不进入正式草稿或有效档案。后台任务列表、详情与事件流均校验 Agent 账号归属。站点其他文本功能、模型兼容回退和配置开关见 [AI 文本流式输出](ai-streaming.md)。

## 持久化、重复请求与停止

迁移 `078_ai_agent.sql` 新增四张表：`ai_agent_sessions`、`ai_agent_events`、`ai_agent_artifacts` 和 `ai_agent_actions`。新增数据与既有故事档案分开保存，会话接口按管理员账号及所属作品校验。`agent_chat` 任务纳入原有任务中心和用量记录；业务生成、改写采纳和封面采纳继续经过原有应用中间件及相应审计机制，草稿恢复另有会话版本记录。

消息请求 ID 保证响应丢失后重试同一消息不会重复启动一轮。单个会话同时运行一轮，同一账号最多同时运行两轮，每轮最多 2 项生成请求。每次协调调用超时 120 秒，不自动重放失败的协调调用；同一轮中参数完全相同的生成工具重复调用复用原回执。以上是协调层限制，子任务继续遵循各自既有超时和重试设置，不代表固定金额上限。

API `1.1.1` 已按发布记录交付取消固定 8 次协调模型调用上限的修复，允许继续读取章节、使用工具，直到模型返回正式答复、用户停止或发生异常；不按次数强制关闭工具。进度随实际调用增长，保留完整的同轮工具结果及思考上下文；每次请求仍有既有的 18 万字符上下文保护，不代表整本小说可以无限装入模型。只读章节不会产生草稿或封面，失败时保留此前操作并标记未完成，不再提示空产出区已有结果。历史会话不会自动重跑。

采纳只接收服务端保存的操作 ID，不信任客户端另传的正文、作品或候选。草稿发布和封面替换在既有事务中再次检查版本；已完成的确认可以重放结果。采纳执行中断后，执行占用到期可在卡片重新核对并继续。草稿恢复与其完成记录在同一事务内保存。

「停止回复」终止协调轮次；已经提交的写作或封面任务在产出区单独停止。后台任务使用现有租约与心跳机制；进程重启后保留对话、操作记录和已有产物，中断任务按现有机制标记失败，不自动重新付费生成。

## 作品记忆与对话摘要（1.2.0 API 候选）

在 Web 对话上方或 iOS 会话工具栏打开「作品记忆」。可以直接添加文风／叙事约定，也可以明确告诉助手“请记住”；助手仅能提出待确认条目，须在面板内确认。生效条目在同一账号、同一本书的新旧对话中共享，从下一轮回复起参考；不会传给其他账号或作品，也不会修改内容尺度、授权或正式章节事实。

每个账号、每部作品最多 24 条生效约定和 24 条待确认提议，生效条目全部进入上下文，不静默截断。编辑生效约定生成新版本；替换提议在确认时检查旧条目是否仍生效，发生冲突保持原状。移除采用软归档，仍可查看历史，接口不提供自动复活。会话删除后保留长期约定，已删除的来源不再可读。确认和移除可安全重放；调整记忆与新一轮发送按同样的会话／账号加锁顺序串行检查，同一账号、同书任一回复运行中时拒绝调整。

摘要仅属于本次会话，包含目标、已选方案、已否定方案、未解决问题、下一步和来源引用；可能有遗漏，涉及重要旧决定仍须回查原始消息。摘要与旧聊天里的记忆状态不覆盖当前生效清单。原文完整保留，失败、截断或取消时不保存该批次的摘要；已成功完成的早前批次可以保留检查点。摘要使用当前回合选择的文本模型，每次最多等待 120 秒，不自动重试付费调用，用量类型为 `agent_summary`，调用审计显示「对话摘要」。整理失败会结束当前回合并提示重试，原始记录仍可查看。

摘要失败活动新增可选 `metadata.summaryDiagnostic`，记录准备、请求、用量保存、校验或摘要保存阶段及原因、批次范围和必要计数，不记录失败响应原文或上游错误详情。界面提示可以再次发送“继续”手动重试；单条历史消息过长时提示另建对话，避免无效重复。生效约定清单为空不能推断旧条目处于待确认或归档状态，助手不应据此主动恢复约定。

这一阶段不引入向量检索、多 Agent 或自动恢复中断的工具执行，也不更换已有 Chat Completions 服务。摘要在用户轮次之间整理，单轮工具上下文仍受既有容量限制；真实摘要质量不由格式校验保证。

管理接口（均沿用管理员鉴权、账号和作品归属验证）：

- `GET /api/ai/agent/sessions/:id/memories?offset=0`：每页 50 条，待确认／生效优先，返回本会话摘要及 `hasMore`。
- `POST /api/ai/agent/sessions/:id/memories`：手动保存 `{title, content}`，标题最多 100、内容最多 1000 个 Unicode 码点。
- `PATCH /api/ai/agent/sessions/:id/memories/:memoryId`：`edit | confirm | archive` 与正整数 `expectedRevision`；编辑需提供标题和内容，版本冲突为 409。
- `GET /api/ai/agent/sessions/:id/memories/:memoryId/source`：按当前账号／作品读取原作者消息；不存在来源时返回 `null`。

迁移 `079_ai_agent_memory.sql` 增加两个独立表，整库 `public` schema 备份沿用既有流程。新客户端入口依赖新 API，旧客户端可忽略会话详情新增的可选 `memories`／`summary` 字段。自动回归、真实模型样本与尚未完成的场景见 [Agent 评估记录](ai-agent-evaluation.md)。

## 人物、情节检索与查阅依据（第二阶段本地候选）

`search_story` 在当前作品、续写起点及之前的正式章节和有效情节／人物关系档案中检索。输入 1–6 个以空格或常见中文标点分隔的关键词，总长不超过 160 个 UTF-16 单元，可选择全部、章节、情节或关系档案。按标题与正文的字面匹配排序，不使用向量数据库或语义嵌入；未命中只能表示本次检索没有找到，不能据此断言事实不存在。已有 `search_chapters` 保留整句字面搜索含义。

章节按 `(sort_order, id)` 共同确定起点边界，同序号时也不会越过起点；原本没有章节的会话保持空范围，起点被删除则要求新建会话。目录最多返回最近 25 章及起点章开头的来源片段，不代表已阅读全部正文。

每页最多检索 6 个命中章节，每章保留 1 个片段；情节和关系档案各最多 2 个片段，合计最多 10 个来源快照，每段最多 900 个 UTF-16 单元。单份材料仅检查每个关键词的前 6 次出现位置，再按匹配程度选取不重叠窗口，因此不是穷尽检索。结果提供命中章节总数、`nextChapterOffset`、本轮候选窗口中省略的片段数及 `limited` 标记；重要结论需要调整关键词、翻页或继续阅读。

来源快照由服务端从实际材料生成，保存标题、片段、范围、内容版本与来源类型；模型不能自行编造活动记录中的来源。`readMore` 返回继续读取的工具参数，章节同时提供阅读器链接。`read_chapter` 每次最多读取 12,000 个 UTF-16 单元，`read_story_memory` 每种档案每次最多读取 10,000 个；均返回后续偏移，可带 `expectedRevision` 检查期间资料是否改变，过期版本与越界偏移会被拒绝。档案分段读取须指定类型，沿用既有有效性检查及人工修订优先规则，过期或未完成档案不进入有效内容。

Web 的成功查阅活动下新增默认收起的「查阅依据」。展开可看本次读取时的快照，章节标题打开当前阅读器；正文、自动分析档案与人工修订档案分别标注，档案覆盖至某章不等于逐句原文出处。当前章节可能已修改，快照保留读取当时的内容。新增 `metadata.sources` 是可选字段，旧事件正常展示，iOS 继续忽略未知字段；本轮没有添加原生来源面板或构建 IPA。

## 中断恢复与发送回执（第三阶段本地候选）

最新一轮失败或停止后，Web 显示读取会话、摘要、模型回复、查阅、提交操作或保存阶段，以及已保存的对话、未完成预览与产出。保存失败终止本轮，不伪装成工具调用失败后继续请求模型。服务重启与执行租约过期由既有回收机制标为失败；刷新、回到页面和联网只恢复 GET／SSE 读取，不重新调用模型。保存的终态不会被较旧的运行进度覆盖。

「继续整理回复」须在弹窗确认新的文本模型用量。后端仅为当前最新的失败／停止轮次创建一个新的查阅与答复任务，沿用原文本预设 ID（预设内容以当前配置为准）；默认服务同样使用当前配置。服务端过滤工具并在执行前校验整个工具批次，只允许现有查阅工具，不允许生成、记忆修改或准备采纳；已有独立生成任务和采纳卡片不变。恢复不是执行检查点续跑，也不会自动补齐未完成草稿。需要重新生成时，作者另发明确要求。单条历史消息过长时关闭恢复入口，提示新建对话。

恢复请求按来源任务派生固定请求标识，并在会话锁内检查是否已接收。并发点击和丢失回执后的重试复用同一任务；旧任务已被新轮次取代时拒绝创建新的恢复任务。正在运行的独立生成任务仍需在产出区查看／停止，原有发布与采纳确认保持独立。

Web 使用当前标签页的 `sessionStorage` 按已验证账号、作品、会话保存未确认送达的消息、原请求 ID 和文本预设。刷新后先核对服务端回执，原消息不在最近一页历史中也能定位；没有回执只表示本次查询未找到，不自动重发。手动「重试原消息」始终发送原内容与预设，不受后来输入和模型选择影响；期间编辑的新输入保留。「放弃重试」只清除本页记录，不取消已受理的服务端任务。浏览器存储不可用时仅当前页面内存保留，关闭标签页不保证恢复。

新增可选会话字段 `recovery`、`messageReceipt`，事件可返回 `requestId`；任务参数记录 `agentPhase`／`recoveryFromTaskId`，错误事件记录 `failurePhase`。使用既有表与 JSON 字段，无新增迁移、依赖。接口：

- `GET /api/ai/agent/sessions/:id?requestId=...`：按账号和会话核对消息回执，返回 `{requestId, taskId}` 或 `null`。
- `POST /api/ai/agent/sessions/:id/tasks/:taskId/resume`：请求体须为 `{confirmModelCall: true}`，返回 `{taskId, created}`；拒绝非终态、跨账号／会话、已被取代或不可恢复的来源。

本轮只实现 Web 入口，iOS 忽略新增可选字段，不构建 IPA；API `1.2.0`／Web `1.4.0` 继续沿用未交付候选。定向回归及浏览器验证使用隔离数据库与模拟模型，不代表真实供应商质量或旧摘要问题已修复，验证结果见 [发布记录](releasing.md)。

## 版本与验证

iOS 原生入口位于底部「创作」、管理后台「AI 服务」与书内「管理这本书」，仅管理员可见；`1.2.0 / build 24` 已通过 Core 测试与 Release 编译，未签名 IPA 已下载核对，真机交互仍待验收。原生端使用相同的作品会话、模型预设、任务 SSE 和操作预览接口，聊天正文与自适应输入独立占位。未确认送达的消息保留原请求 ID、内容与模型，由用户手动重试；重新打开页面只恢复读取，不自动生成。详见 [原生接入说明](../ios/docs/ai-agent-2026-11-09.md)。

上一轮发布记录为 Web `1.3.0`／API `1.1.1`、源码 `94dcbd9c`，包含迁移 078；记忆、摘要与本轮检索共用尚未交付的 API `1.2.0`／Web `1.4.0` 候选。本地 Windows API/Web 生产模式构建已通过，未部署；iOS 保持 `1.3.0 / 27` 源码候选，暂停构建 IPA。第二阶段没有新增迁移或依赖，未来交付仍需迁移 079。实际版本、构建与生产证据见 [发布记录](releasing.md)。

自动回归使用隔离 PGlite 数据库及模拟上游，API Agent／检索合计 78 项、Web 记忆／对话／来源合计 17 项通过；覆盖既有会话与采纳契约，以及检索边界、分页、版本、来源持久化和摘要失败诊断。本地真实浏览器连接隔离 API，验证记忆管理、刷新恢复、来源展开、章节链接及 390px 窄屏布局。Web 与浏览器结果来自前轮同一界面实现，收尾再次通过 API 类型、Lint 与构建。当前验证结果见 [发布记录](releasing.md)。

另使用现有文本预设完成少量真实模型样本，观察到记忆继承、长对话修正保留、长章节线索定位与资料伪指令处理的预期行为。也保留了一次摘要失败和有限检索被表述为不存在的质量问题；这不是完整准确率评测，未覆盖所有供应商或真实设备交互。模型用量、失败记录与范围见 [Agent 评估记录](ai-agent-evaluation.md)。
