# 对话创作

Web 保留与其他后台页面一致的标题和说明；下方的作品选择、会话信息、对话与输入区靠左对齐并铺满页面可用宽度。作品工具栏提供「历史对话」「找书入库」「新对话」，当前会话标题只显示一次，下面显示续写起点。历史弹窗可切换「本书／全部最近」，按已载入的对话标题、作品或章节搜索，并继续加载更早记录；删除仍需二次确认，失败保留记录，成功移除两种范围内的同一对话。未选择作品时也能从全部最近打开对话。

API 1.6.0 候选将生效作品约定和版本保存到生成任务，任务级重试沿用提交时的约定。可在 Web 或 iOS 的「产出与采纳」打开草稿后选择「核对草稿」，将任务保存的作者要求与草稿正文对照。问题需附草稿和来源引文，可选择「带到对话中修改」填入当前输入框。本章篇幅使用服务端实际字数。

发布预览显示稿件承接的章节和书中当前实际追加位置。新章节抢先发布、导致末章变化时，请在产出区重新预览后确认。位置无法从旧稿追溯时，预览显示当前实际发布位置。Agent 读取局部改写任务时可按同一版本分段查阅拼接后的整章。

本会话已发布的产出可以继续在原对话里改写，即使它在续写起点之后。助手按发布记录定位正式章节并读取当前正文，确认「写回原章节」后更新同一章，保留修改历史。作品目录显示的章号、目录第几项与章名自带的编号可能不同；同名时可以指定页面章号。发布新稿用于追加章节。

在 Web 或 iOS 的原章改写预览里，可选择后续 1 至 10 章，再点击「检查后续影响」。检查使用该预览中实际将写回的改动，按书中顺序查阅指定数量的已发布章节，末尾不足时按实际章数。疑点显示改动引文和后文原句，章节标题可打开阅读器。「带到对话中修改」把一项疑点填入输入框。超出对话可编辑范围的后文可以在该章另开对话处理。写回仍从原预览单独确认。

每份预览保留上次完整结果，检查范围与后文章节版本一致时可复用。切换范围或重新勾选改动后需检查对应预览，正在检查时正文变化会使结果失效。引文无法核对的条目省略并提示重试；所选原文超过单次容量时可缩小范围。检查使用当前默认文本服务并记录实际用量。书末没有后文时直接返回，无需调用模型。

第六阶段本地候选新增原话精确回查、完整原句的记忆提议校验及摘要版本／失败留档（迁移 081）。严格 schema 的实测没有通过，产品摘要仍保持原请求默认与严格本地校验；真实作品的多次修正及摘要人工验收尚未完成，详见 [第六阶段报告](ai-agent-phase6.md)。

第一版面向管理员，在一本小说内通过持续对话查阅材料、讨论情节、生成和修改草稿、构思并生成封面。复用现有文本／图像服务、后台任务、草稿发布与封面候选接口，没有增加 Agent 框架；助手回复使用 `react-markdown` 与 `remark-gfm` 呈现 Markdown。

## 发布后继续下一章

在 Web 或 iOS 确认发布后，可以从发布结果或采纳记录点「继续下一章」。系统用这次发布的正式章节作起点，即使书中后来增加了章节。章节已删除或撤回时，请另选可用起点。

可以从对话摘要的待讨论问题、后续安排和最近作者原话中，挑选最多六条仍适用的事项，也可以补充最多 1200 字。默认空选，两项都可以留空。点击开启后进入新对话，可展开「承接的创作事项」回看。所选内容作为后续创作参考，新对话中的明确要求优先，待讨论问题仍保留未决状态。新对话使用本书默认创作设置。开启时只创建对话，发送写作要求后才进入正常的讨论或生成流程。

同一发布记录的重复请求返回已建立的对话。等待期间承接事项变化时，刷新后可重新勾选，手写补充仍保留。旧 API 缺少入口所依赖的能力字段时隐藏功能。部署前需应用迁移 092。

## 多章大纲与写作进度（API 1.13.0 / Web 1.12.0 源码候选）

Web 和 iOS 从「章节计划 → 多章大纲」安排未来 3 至 5 章。可以手动填写标题、目标和情节步骤，也可以点击「请助手拟定多章大纲」。助手先读取当前大纲、关联草稿及发布进度，在本轮只提交待核对大纲，不生成正文。已有稿件的大纲条目不能被助手省略或换掉标识；作者可以手动调整安排。

同一账号、同一本书共用大纲。每项保存稳定标识，修改或调整顺序不改变已有关联。显示「待写」「已有草稿」「已发布」及对应稿件和创作对话；正式章节已删除时显示「发布位置已变化，需核对」。只有包含本次功能元数据的新稿件会自动关联，历史稿件不按标题猜测匹配。旧客户端若未传回章节标识，不能覆盖已有稿件关联的大纲，请升级客户端后再编辑。大纲在写作后变化时提示核对，已提交计划快照和稿件保持原样；这条版本提示不等同于已判定具体情节冲突。

选定一项并确认设为当前章节计划，会带入该章目标和步骤，把后续目标写入本章约束，避免提前完成后章安排。已有计划时提示替换，写作仍需另行确认。发布结果中的「继续下一章」以该次实际发布的章节为起点；若能定位其大纲标识，会将后面第一项尚未完成的安排放进新对话的待确认章节计划。只有开启对话，不会自动调用模型写作。若大纲项已移除，则保留原有手动选择流程。

「请助手核对进度并完善大纲」会调用当前文本模型，要求核对实际稿件、指出后续需要调整的安排，再保存建议；建议仍需作者审阅，不保证语义判断正确。旧 API 没有 `outlineWorkflowAvailable` 时不显示新的助手入口。先应用迁移 `097_ai_agent_writing_workflow.sql` 并更新 API，再发布客户端。

## 星图线索进入章节计划

在 Web 或 iOS 的「章节计划 → 线索安排」读取当前续写起点的有效星图。可打开星图查看完整来源，再回到线索列表安排「本章推进」「安排到后面」「暂时搁置」，也可写说明。线索及报告依据由服务端从有效星图取回，不接收客户端自行拼接的事实。报告引文仍是分析材料，不是章节原句；可沿章节入口回读原文。

安排按账号和作品隔离，每本书最多保留 40 项，每章最多选入 6 项。点击「保存本章线索选择」才更新当前章节计划，后续确认写作会保存完整快照。清空本章选择可以解除关联。变更安排后必须重新保存本章选择；星图或起点变化会标注旧来源，需核对后从有效星图重新加入。开始新的写作前还会复核来源和安排版本；已接受任务及其同次重试沿用原快照。

「请助手核对进展」会在对话里查阅安排及实际草稿或已发布正文，给出依据和未能确认的部分，不自动修改状态。作者在「调整安排」中选择「已回收」并点击「确认已回收」后才记录。这个标记只是作者自己的工作安排，不会改写正文、分析报告或星图。移除安排需确认，既有任务和计划快照仍保留。

没有有效星图时不会自动花费 Token 生成；请先打开故事星图，按相同起点明确生成。旧 API 没有 `storyThreadPlansAvailable` 时隐藏线索入口。

## 从哪里进入

后台「创作工作区 → 对话创作」，或作品工作区的「对话创作」入口。地址为 `/admin/ai?sub=agent&novel=<作品ID>&session=<会话ID>`。

要找尚未选定或未收录的书，可在作品选择旁打开「找书入库」。输入书名、`帮我找《书名》` 或补充作者。先显示书库里的同名匹配，查不到才搜索已有书源。选择外部候选后复用书籍导入预览，至少选择一章正文并确认，系统会再次检查同一本书是否已入库。导入完成且目录已有章节时，可以「开始对话」。Web 也可直接进入 `/admin/ai?sub=agent&findBook=1`，iOS 已打开的对话可通过「更多」进入。

1. 选择作品和续写起点，建立对话；不指定时绑定创建当时的最新章节，无章节的作品从新写开始。
2. 可以先说「先了解这本小说，和我讨论下一章的走向」，再通过对话调整方向。
3. 明确要求生成后，任务进度和结果出现在「产出与采纳」。例如「按照刚才第二个方案写一章」或「把上一版的冲突再收敛一点」。原章节增补与改写也直接在对话里提出，可用章名、章号或引用原文指定位置；Web 输入区不再另设改写入口。
4. 在草稿、改写建议或封面候选上预览，确认后才覆盖草稿、发布章节或替换封面。Web 改写建议默认展示新版，可切换原文，或在「查看差异」的大弹窗里按段落核对改动；继续调整与采纳预览固定在侧栏底部。聊天中的“确认”会引导到保存的预览卡，不直接执行采纳。

桌面并排展示对话与产出，800px 以下通过按钮切换。Enter 直接发送，Shift + Enter 换行，也支持 Ctrl / ⌘ + Enter 发送；输入法选词和长按重复按键不会触发发送，空消息及正在提交／回复时不重复提交。已提交对话保存在服务端，页面刷新或离开不会清空记录或停止后台任务。尚未发送的输入仅保存在当前页面。

新旧助手回复均支持 Markdown 标题、加粗、列表、引用、表格、任务清单、链接与代码块；宽表格和代码块可横向滚动。原始 HTML 不执行，不安全的链接协议会被过滤。用户输入、任务状态、错误详情及草稿预览仍保留原文，服务端保存内容不变。

消息输入位于正文面板下方，是独立的紧凑浮动卡片，两者通过留白分隔。PC 端正文区增高，输入时不会被卡片覆盖或挤压；输入单行起步，多行时自动增高，超过视口相关上限后在框内滚动。卡片左侧可以选择“模型与服务”中已保存的文本预设；默认项跟随当前文本服务。模型选择随消息请求保存，同一回合及由助手提交的文本生成任务使用同一预设，封面生成仍使用图像端点；正在处理的回合不能切换模型。

## 章节计划卡（API 1.9.0 / Web 1.10.0 候选）

输入区工具栏新增「章节计划」，每段对话保存一张当前计划。可以「请助手拟定计划」，或直接填写标题、章节目标、情节步骤、人物与关系变化、结尾悬念、本章约束和目标字数。已保存的计划支持阅读、编辑及「请助手完善计划」；未决定的可选内容留空。手动编辑先保存，再核对后点击「确认计划并写作」，会使用当前文本模型和已选写作参考生成一章草稿，后续采纳仍沿用原有流程。

拟定／完善计划会调用文本模型，该轮只开放查阅、章节计划和多章大纲提议工具，服务端拒绝正文、封面等生成及其他写入。普通对话也可提出计划；同轮提出后不能直接开始生成。已有计划的会话须在 Web 计划入口明确确认后生成章节，未使用计划的原有写作流程不变。计划属于待创作方案，不计入已发生的正文事实或长期作品记忆。

计划按账号和会话隔离，刷新会恢复已保存内容；未保存编辑只留在当前页面。保存与确认均校验版本，冲突时保留编辑内容并提供刷新入口。进行中的对话轮次锁定手动编辑。确认时服务端将计划完整快照保存到轮次，随后传给正文任务的创作材料；标题、情节步骤、目标字数和完整约束沿用该快照。之后再改计划不影响已提交任务及其重试。发送失败沿用原请求标识、规划模式和计划版本，重复生成请求使用同一写作操作标识。

新增迁移 `090_ai_agent_chapter_plan.sql`，API 启动时自动应用；部署顺序为迁移/API、Web。新 Web 在旧 API 未提供计划字段时隐藏入口。继续并入未发布的 API 1.9.0 / Web 1.10.0 候选，无新增依赖。iOS 暂无计划编辑／确认界面；已创建计划的对话需从 Web 确认写作。命名备选和切换见下方「剧情分支对比」，当前计划仍只有一张；未增加完整版本历史或任意旧版恢复。删除对话会一并删除当前计划，已生成草稿与任务快照按既有规则保留。

## 剧情分支对比（API 1.9.0 / Web 1.10.0 候选）

在「章节计划」保存并退出编辑后，点击「分支对比」。每段对话最多保留 8 个命名分支，名称限 60 字；每个分支保存当时的完整计划，后续修改当前计划不会覆盖它。

1. 为当前已保存的计划命名，例如「独自赴约」，点击「保存当前计划为分支」。
2. 返回当前计划，手动编辑或请助手完善另一种情节走向，保存后再次打开分支对比；也可给新走向保存另一个名称。
3. 选择一个已保存分支，按标题、目标、情节步骤、人物变化、结尾悬念、约束和目标字数与当前计划对照；「只看不同」可收起相同字段。桌面左右对照，窄屏上下阅读。
4. 点击「设为当前计划」后返回计划阅读页，核对后另行点击「确认计划并写作」。切换本身不会调用模型或提交正文任务，保存与移除分支也不会调用模型。

切换到不同内容会递增当前计划版本，并记录来源分支。如果当前走向还没有保存在任一分支中，会先自动保存一份「切换前」快照；分支已满时拒绝切换并保留原计划，先移除不需要的分支即可继续。内容相同的分支无需切换。移除须确认具体分支名称，移除后无法恢复该分支记录，但当前计划及已提交任务的计划快照仍然保留。

分支按账号和会话隔离，保存和切换校验当前计划版本；助手仍在处理消息时可阅读，暂不能保存、切换或移除。网络失败且结果不确定时，在分支面板内重试沿用同一次操作标识，迟到的重试不会把后续编辑回退；关闭面板或刷新页面后重新读取服务端状态，未完成请求标识不跨页面保存。版本冲突时先刷新核对再操作。删除对话会一并删除分支和请求回执，已提交写作任务继续遵循原有快照与保留规则。

新增迁移 `091_ai_agent_plan_branches.sql`，API 启动时自动应用。先更新迁移/API，再更新 Web；新 Web 仅在 API 返回 `chapterPlanBranchesAvailable` 时提供入口。继续并入未发布的 API 1.9.0 / Web 1.10.0 候选，无新增依赖；iOS 也可在章节计划中管理分支。本期只支持同一对话中的计划备选及当前计划与单个分支对比，未增加对话分叉、分支树、多份正文并行生成或完整计划版本历史。

## 按改动选择采纳（API 1.9.0 / Web 1.10.0 候选）

草稿改写与原章节改写的「查看差异」窗口支持勾选每处改动，默认全部采用，可「全部采用」或「全部保留原文」。取消勾选后保留该处原文；新增、删除和替换共用同一规则。「只看改动」及窄屏版本切换不会改变选择。相邻改写段落数量一致时按位置逐段选择；段落数量不同且无法用共同原文分开的改动作为一组显示；超长文本对齐超过预算时也合并为整块，不承诺每句话都能独立选择。

选择变化后，侧栏「合并结果」可阅读将要采用的文字。「预览所选结果」把选择保存为服务端操作预览，最后点击「确认采纳」或「确认写回原章节」才更新正文。全部保留原文时不可提交。关闭差异窗口保留本页选择；刷新或重新打开会话恢复已保存预览的选择，尚未准备预览的选择不跨刷新保存。已采纳及正在执行的记录锁定选择，旧预览依然按其保存的正文执行。

接口仅接收 `selection: { version: 1, revision, acceptedChanges }`；`revision` 来自产物的 `selectionRevision`，`acceptedChanges` 是从 0 起、只计变更块的索引。API 和 Web 共用对齐算法，服务端从任务保存的原文与建议重建正文，拒绝重复／越界／空选择及旧版本；不接受客户端拼接正文。确认仍只使用操作 ID，沿用原文修订检查、幂等回执及恢复历史。原句的跨轮锁定尚未加入。

无新增迁移或依赖；继续并入未发布的 API 1.9.0 / Web 1.10.0 候选。API 应先升级，新 Web 在旧 API 缺少 `selectionRevision` 时保留整份采纳。iOS 在 API 提供 `differences` 和 `selectionRevision` 时支持相同的逐处选择，使用服务端划分的改动块，不在原生端重新对齐。可全部采用、全部保留、只看改动、阅读合并结果；iPad 宽窗口并排展示前后文字，窄窗口和大字号纵向展示。已保存预览可跨端恢复选择，进行中或已采纳的记录锁定；旧 API 保留整份采纳入口。新接口只新增可选字段，不影响旧客户端。

## 写作参考库（API 1.8.0 / Web 1.9.0 候选）

在 Agent 输入区旁打开「写作参考」，新建并填写名称、标签、参考正文和可选的使用说明。正文由作者自由组织，可保存情节、氛围、节奏、细节或表达方式；参考库按账号隔离，同一账号可跨作品选择使用。没有预填卡片。iOS 也可从输入区或「更多 → 写作参考」搜索、创建、编辑、移除并选择参考；服务端缺少 `writingReferencesAvailable` 时隐藏原生入口。

1. 在列表中勾选本轮需要的参考，关闭弹窗后随下一条消息带入；输入区显示已选名称与使用范围。
2. 默认只用于本轮。勾选「持续用于当前对话」后，在下一条消息被接受时保存选择，以后各轮沿用；新建其他对话不会继承这些选择。
3. 每轮发送时读取卡片的最新保存版本。编辑、保存或移除参考不会改写已经提交的任务；服务端消息元数据记录当轮使用的名称与版本。
4. 清空选择并保持「持续用于当前对话」勾选，再发送消息，即可停止后续轮次使用。只取消持续勾选属于单轮覆盖，之前保存的对话默认选择仍会在后续轮次恢复。
5. 保存失败保留编辑内容；版本冲突提示刷新核对，移除需要确认。发送结果不确定时保留请求标识、所选 ID 与范围，重复提交返回原任务，不改用重新编辑后的卡片内容。

参考以独立资料块传给协调助手及其新写、续写、草稿改写和原章节改写任务，并带有明确约束：保留原书人物性格、关系、截至续写起点的认知及已发生事实；参考中的人物、关系和事件不自动成为本书事实。冲突时默认沿用原文并指出差异，作者明确要求修改设定时才调整。卡片不能改变内容偏好、工具权限、作品记忆确认或正文采纳流程。这些是提示与材料分层约束，实际模型是否准确保持人物仍需作者核对草稿。

个人库最多 300 张；每张名称最多 100、正文 8,000、使用说明 1,000 个 UTF-16 字符，最多 12 个标签且每个最多 32 个字符。每轮最多 6 张，名称、标签、正文与说明合计最多 24,000 个 UTF-16 字符。搜索支持名称、标签和正文，每页 30 张。服务端在接纳消息的事务中再次检查所有权、数量和总长度；超额或明确选择的参考已移除时拒绝本轮，避免静默漏带。已移除的对话默认参考在读取时跳过，不影响打开会话。

新增迁移 `87_ai_agent_writing_references.sql` 保存个人参考及会话默认 ID；实际内容和版本冻结在 `agent_chat` 任务参数及派生写作任务上下文，手动只读恢复沿用原快照。删除对话不移除个人参考库。

接口均需现有管理员权限，且只操作当前账号：

- `GET /api/ai/agent/writing-references?q=...&offset=0`：返回 `{ references, hasMore }`。
- `POST /api/ai/agent/writing-references`：提交 `{ title, tags, content, usage? }`。
- `PATCH /api/ai/agent/writing-references/:id`：提交上述完整字段及 `expectedRevision`；冲突返回 409。
- `DELETE /api/ai/agent/writing-references/:id`：提交 `{ expectedRevision }`，软删除参考。
- 消息接口新增可选 `referenceSelection: { ids, scope: 'turn' | 'session' }`；省略时沿用当前会话默认，显式空数组可覆盖本轮或清空默认。会话详情新增可选 `writingReferences`，会话新增 `writingReferenceIds`，事件元数据按需增加名称／版本与选择范围；无参考时保持原消息元数据格式。

新 Web 入口依赖 API 1.8.0 及迁移 087，升级顺序应先 API 再 Web。旧客户端可忽略新增可选响应字段；框架不新增外部依赖。构建、迁移与部署状态见 [发布记录](releasing.md)。

## 模型与上下文

- 使用输入区所选文本预设，或跟随「系统设置 → 模型与服务」中当前文本模型；它必须支持 OpenAI 兼容 Chat Completions 的 `tools`、`tool_calls` 和工具结果消息。只通过普通文本连接测试不能证明工具调用可用。
- 封面生成使用现有图像服务及其配置。协调助手本身只读文字材料和候选描述词，不读取图像像素。
- 每个会话固定一本书与起点章节。常规正文和有效档案按该起点取材，章节原文支持分段读取和字面搜索。明确查阅或改写时也可定位本会话在起点之后发布的正式章节。需要按新发布章节继续时，新建对话选择新起点。
- API `1.2.0` 候选在每轮开始读取未被摘要覆盖的近期事件；超过 60 条、序列化后超过 9 万字符，或存在尚未读取的旧记录时，将连续旧记录分批整理，保留最近最多 20 条且约 4 万字符的原文窗口。每批最多 60 条、通常不超过 6 万字符；单条超过 9 万字符时明确失败并保留原文。游标只推进到成功整理的最后一条，后续积累到阈值才再次摘要。预算按字符估算，不是供应商精确 token 计数。
- 顶部「创作设置」打开独立的「创作约定与偏好」弹窗，入口保留已保存的内容尺度与未保存状态。关闭窗口会保留当前对话的编辑草稿，保存成功关闭，冲突时保留输入；切换会话后各自重新读取设置。「创作约定与偏好」供当前对话参考。保存时默认勾选「同时设为本书新对话的默认设置」，同一账号此后为这本书创建的对话自动带入已保存的设置。取消勾选可只保存到本次对话；清空创作约定并关闭成人内容后可把这组设置保存为本书默认。已经创建的对话各自保留保存时的值，已确认的「作品记忆」仍独立生效。保存时检查会话和作品默认设置的版本，回复期间请先等待或停止。内容偏好沿用服务端验证，作品发布仍按现有分级执行。

## 可执行的操作

| 能力 | 结果与确认方式 |
| --- | --- |
| 查阅小说、章节、有效文风／情节／关系档案 | 只读取材；信息不足或材料不完整时需要继续读取 |
| 单章续写／新写 | 生成未发布草稿，预览并确认后追加为正式章节 |
| 整章或选段改写 | 生成建议并保留原文；可沿着上一版未采纳建议继续调整 |
| 采纳改写与恢复草稿 | 保存前后版本，并校验当前正文修订号；已变化或已发布的草稿不会被旧预览覆盖 |
| 封面构思与生成 | 保存为候选，确认时再次检查封面版本；复用现有封面历史 |
| 显式更新小说分析 | 创建现有情节／关系档案任务，按正式章节分析，不把聊天假设变成事实 |
| 查阅历史任务与对话 | 通过任务和事件 ID 精确定位；已有采纳记录可继续查看 |
| 提出作品记忆 | 只保存待确认约定，作者在记忆面板确认后才跨对话生效 |

发布仍执行原有作品分级、草稿状态与事务检查；若站点原本启用了发布后故事档案更新，该现有行为也会继续执行。

第一版不直接修改已发布章节，不做跨作品批量操作，不提供任意网络、SQL 或系统命令工具。封面调整属于重新生成，不承诺保留原图的局部编辑或人物一致性；助手文字支持流式预览，封面图片在完成后显示。

## 流式回复与任务进度

助手生成期间逐段显示 Markdown，按任务与模型轮次区分临时预览和已保存消息，避免同一段文字重复出现。停留在消息底部时跟随输出，向上阅读时保持当前位置。工具参数完整返回并校验后才执行，不显示未完成参数或原始推理内容。

对话及其派生任务通过只读事件流更新进度；断线或刷新重新读取同一任务，不重新提交生成。失败后的部分文字标为未完成，不进入正式草稿或有效档案。后台任务列表、详情与事件流均校验 Agent 账号归属。站点其他文本功能、模型兼容回退和配置开关见 [AI 文本流式输出](ai-streaming.md)。

## 持久化、重复请求与停止

迁移 `078_ai_agent.sql` 新增四张表：`ai_agent_sessions`、`ai_agent_events`、`ai_agent_artifacts` 和 `ai_agent_actions`。新增数据与既有故事档案分开保存，会话接口按管理员账号及所属作品校验。`agent_chat` 任务纳入原有任务中心和用量记录；业务生成、改写采纳和封面采纳继续经过原有应用中间件及相应审计机制，草稿恢复另有会话版本记录。

迁移 `085_ai_agent_book_settings.sql` 按账号和作品保存对话默认设置。旧版只记录会话的活动时间，升级时从有创作约定或非默认内容偏好的旧对话中，选用最近活动的一条作为初始设置。保存后的默认设置独立于来源会话，删除对话后仍可继承。

消息请求 ID 保证响应丢失后重试同一消息不会重复启动一轮。单个会话同时运行一轮，同一账号最多同时运行两轮，每轮最多 2 项生成请求。每次协调调用超时 120 秒，不自动重放失败的协调调用；同一轮中参数完全相同的生成工具重复调用复用原回执。以上是协调层限制，子任务继续遵循各自既有超时和重试设置，不代表固定金额上限。

API `1.1.1` 已按发布记录交付取消固定 8 次协调模型调用上限的修复，允许继续读取章节、使用工具，直到模型返回正式答复、用户停止或发生异常；不按次数强制关闭工具。进度随实际调用增长，保留完整的同轮工具结果及思考上下文；每次请求仍有既有的 18 万字符上下文保护，不代表整本小说可以无限装入模型。只读章节不会产生草稿或封面，失败时保留此前操作并标记未完成，不再提示空产出区已有结果。历史会话不会自动重跑。

采纳只接收服务端保存的操作 ID，不信任客户端另传的正文、作品或候选。草稿发布和封面替换在既有事务中再次检查版本；已完成的确认可以重放结果。采纳执行中断后，执行占用到期可在卡片重新核对并继续。草稿恢复与其完成记录在同一事务内保存。

「停止回复」终止协调轮次；已经提交的写作或封面任务在产出区单独停止。后台任务使用现有租约与心跳机制；进程重启后保留对话、操作记录和已有产物，中断任务按现有机制标记失败，不自动重新付费生成。

## 作品记忆与对话摘要（1.2.0 API 候选）

在 Web 对话输入框下方、模型选择旁边，或 iOS 会话工具栏打开「作品记忆」。Web 有待确认提议时，入口显示待确认数量；点击后在面板中选择「确认记住」。可以直接添加文风／叙事约定，也可以明确告诉助手“请记住”；助手仅能提出待确认条目，须在面板内确认。生效条目在同一账号、同一本书的新旧对话中共享，从下一轮回复起参考；不会传给其他账号或作品，也不会修改内容尺度、授权或正式章节事实。

每个账号、每部作品最多 24 条生效约定和 24 条待确认提议，生效条目全部进入上下文，不静默截断。编辑生效约定生成新版本；替换提议在确认时检查旧条目是否仍生效，发生冲突保持原状。移除采用软归档，仍可查看历史，接口不提供自动复活。会话删除后保留长期约定，已删除的来源不再可读。确认和移除可安全重放；调整记忆与新一轮发送按同样的会话／账号加锁顺序串行检查，同一账号、同书任一回复运行中时拒绝调整。

摘要仅属于本次会话，包含目标、已选方案、已否定方案、未解决问题、下一步和来源引用。涉及重要旧决定仍须回查原始消息。摘要和旧聊天里的记忆状态不覆盖当前生效清单。摘要使用当前回合选择的文本模型，每次最多等待 120 秒，用量类型为 `agent_summary`，调用审计显示「对话摘要」。失败批次保留游标和原文。摘要请求或校验失败时，助手可基于最近成功的摘要和近期消息继续回复，提示尚未整理的历史范围，并按需分段回查原话。五分钟内的新消息沿用此方式，之后从失败处重新尝试摘要。用户停止或摘要存储故障仍会结束本轮。

摘要失败活动的可选 `metadata.summaryDiagnostic` 记录阶段、原因、批次范围和必要计数。单条历史消息超出摘要输入上限时，会话仍可继续，原消息可以分段读取。生效约定清单为空不能推断旧条目处于待确认或归档状态。

这一阶段不引入向量检索、多 Agent 或自动恢复中断的工具执行，也不更换已有 Chat Completions 服务。摘要在用户轮次之间整理，单轮工具上下文仍受既有容量限制；真实摘要质量不由格式校验保证。

管理接口（均沿用管理员鉴权、账号和作品归属验证）：

- `GET /api/ai/agent/sessions/:id/memories?offset=0`：每页 50 条，待确认／生效优先，返回本会话摘要及 `hasMore`。
- `POST /api/ai/agent/sessions/:id/memories`：手动保存 `{title, content}`，标题最多 100、内容最多 1000 个 Unicode 码点。
- `PATCH /api/ai/agent/sessions/:id/memories/:memoryId`：`edit | confirm | archive` 与正整数 `expectedRevision`；编辑需提供标题和内容，版本冲突为 409。
- `GET /api/ai/agent/sessions/:id/memories/:memoryId/source`：按当前账号／作品读取原作者消息；不存在来源时返回 `null`。

迁移 `079_ai_agent_memory.sql` 增加两个独立表，整库 `public` schema 备份沿用既有流程。新客户端入口依赖新 API，旧客户端可忽略会话详情新增的可选 `memories`／`summary` 字段。自动回归、真实模型样本与尚未完成的场景见 [Agent 评估记录](ai-agent-evaluation.md)。

## 人物、情节检索与查阅依据（第二阶段本地候选）

`search_story` 在当前作品、续写起点及之前的正式章节和有效小说分析中查找原文。Agent 可用 1–6 个原文关键词，再补充最多 4 个动作或情节近义词。像「她何时开始怀疑师父」这样的问题，也可以用目录正序查看命中，再逐章回读确认本次查到最早的场景。

原文查找支持「林岚又名阿岚」「阿岚本名林岚」等明确身份句。别名扫描按关键词分批读取有限数量的候选章，每批最多 24 章，超长章仍可用普通关键词查阅；同一个别名在已检查候选里指向不同人时跳过。扩展关键词和别名只用于定位，结论仍由章节原句支持。`search_chapters` 保留整句字面匹配。未命中只说明本次查找范围内未找到。

章节按 `(sort_order, id)` 共同确定起点边界，同序号时也不会越过起点；原本没有章节的会话保持空范围，起点被删除则要求新建会话。目录最多返回最近 25 章及起点章开头的来源片段，不代表已阅读全部正文。

每页最多检索 6 个命中章节，每章保留 1 个片段；情节和关系档案各最多 2 个片段，合计最多 10 个来源快照，每段最多 900 个 UTF-16 单元。单份材料仅检查每个关键词的前 6 次出现位置，再按匹配程度选取不重叠窗口，因此不是穷尽检索。结果提供命中章节总数、`nextChapterOffset`、本轮候选窗口中省略的片段数及 `limited` 标记；重要结论需要调整关键词、翻页或继续阅读。

来源快照由服务端从实际材料生成，保存标题、片段、范围、内容版本与来源类型；模型不能自行编造活动记录中的来源。`readMore` 返回继续读取的工具参数，章节同时提供阅读器链接。`read_chapter` 每次最多读取 12,000 个 UTF-16 单元，`read_story_memory` 每种档案每次最多读取 10,000 个；均返回后续偏移，可带 `expectedRevision` 检查期间资料是否改变，过期版本与越界偏移会被拒绝。档案分段读取须指定类型，沿用既有有效性检查及人工修订优先规则，过期或未完成档案不进入有效内容。

Web 的成功查阅活动下新增默认收起的「查阅依据」。展开可看本次读取时的快照，章节标题打开当前阅读器；正文、自动分析档案与人工修订档案分别标注，档案覆盖至某章不等于逐句原文出处。当前章节可能已修改，快照保留读取当时的内容。新增 `metadata.sources` 是可选字段，旧事件正常展示，iOS 继续忽略未知字段；本轮没有添加原生来源面板或构建 IPA。

## 中断恢复与发送回执（第三阶段本地候选）

最新一轮失败或停止后，Web 显示读取会话、摘要、模型回复、查阅、提交操作或保存阶段，以及已保存的对话、未完成预览与产出。保存失败终止本轮，不伪装成工具调用失败后继续请求模型。服务重启与执行租约过期由既有回收机制标为失败；刷新、回到页面和联网只恢复 GET／SSE 读取，不重新调用模型。保存的终态不会被较旧的运行进度覆盖。

「继续整理回复」须在弹窗确认新的文本模型用量。后端仅为当前最新的失败／停止轮次创建一个新的查阅与答复任务，沿用原文本预设 ID（预设内容以当前配置为准）；默认服务同样使用当前配置。服务端过滤工具并在执行前校验整个工具批次，只允许现有查阅工具，不允许生成、记忆修改或准备采纳；已有独立生成任务和采纳卡片不变。恢复不是执行检查点续跑，也不会自动补齐未完成草稿。需要重新生成时，作者另发明确要求。

恢复请求按来源任务派生固定请求标识，并在会话锁内检查是否已接收。并发点击和丢失回执后的重试复用同一任务；旧任务已被新轮次取代时拒绝创建新的恢复任务。正在运行的独立生成任务仍需在产出区查看／停止，原有发布与采纳确认保持独立。

Web 使用当前标签页的 `sessionStorage` 按已验证账号、作品、会话保存未确认送达的消息、原请求 ID 和文本预设。刷新后先核对服务端回执，原消息不在最近一页历史中也能定位；没有回执只表示本次查询未找到，不自动重发。手动「重试原消息」始终发送原内容与预设，不受后来输入和模型选择影响；期间编辑的新输入保留。「放弃重试」只清除本页记录，不取消已受理的服务端任务。浏览器存储不可用时仅当前页面内存保留，关闭标签页不保证恢复。

新增可选会话字段 `recovery`、`messageReceipt`，事件可返回 `requestId`；任务参数记录 `agentPhase`／`recoveryFromTaskId`，错误事件记录 `failurePhase`。使用既有表与 JSON 字段，无新增迁移、依赖。接口：

- `GET /api/ai/agent/sessions/:id?requestId=...`：按账号和会话核对消息回执，返回 `{requestId, taskId}` 或 `null`。
- `POST /api/ai/agent/sessions/:id/tasks/:taskId/resume`：请求体须为 `{confirmModelCall: true}`，返回 `{taskId, created}`；拒绝非终态、跨账号／会话、已被取代或不可恢复的来源。

本轮只实现 Web 入口，iOS 忽略新增可选字段，不构建 IPA；API `1.2.0`／Web `1.4.0` 继续沿用未交付候选。定向回归及浏览器验证使用隔离数据库与模拟模型，不代表真实供应商质量或旧摘要问题已修复，验证结果见 [发布记录](releasing.md)。

## 单轮用量与可重复评测（第四阶段本地候选）

会话详情新增可选 `turnUsage`，按真实 `taskId` 返回最近八轮用量。包含当前轮次的 `agent_chat` 和 `agent_summary`，不含派生草稿、封面、分析任务；这些任务仍在原调用与用量页面查看。调用次数指已保存的记账行，未回传或未能保存的调用可能缺失。输入／输出 Token 缺失与明确的 0 分开，费用只采用上游回传或原有精确账单查询，不猜测币种、不混合不同币种、不把未知费用算成免费。历时是创建至结束／当前时刻的墙钟时间，不是模型响应延迟。

迁移 `080_ai_agent_usage.sql` 为 `ai_usage` 添加 `task_id`、`token_usage_reported` 及轮次查询索引。新轮次参数记录 `agentUsageVersion=1`；旧记录没有精确关联，不按相近时间补填。取消或流式中断后已收到的用量仍关联原轮次；普通 JSON 兼容响应的进度保存失败也保留已收到用量。升级 API 前执行迁移，完整候选需要 079 和 080；旧客户端忽略新增可选字段。

Web 的「本轮用量」入口保留已记录调用次数与历时，点击弹窗查看明细；历史轮次及用量提醒设置默认收起。关闭弹窗不清空当前页面的提醒输入草稿。可设置单轮输入加输出 Token 的提醒值，默认留空／0 为关闭，按已验证账号保存在此浏览器。达到阈值的文字提示保留在弹窗外，由作者手动停止或继续；没有新增八轮上限或自动中断预算。统计在会话刷新时更新，不是实时逐 Token 计费器；账号切换不会沿用另一账号提醒。

`npm run eval:agent` 默认仅输出 12 场景计划，不读取模型配置或发送网络请求。`--live` 才使用当前文本配置执行合成作品评测，默认每个场景三次、总计最多 160 次真实补全请求、每个场景最多 20 次、每次场景限时 180 秒。仅开放所选补全端点，其他出站请求和业务生成／发布适配器拒绝；使用独立内存 PGlite，不连接生产数据库。失败样本保留且不自动重试；逐轮保存回复、工具和来源、摘要、实际模型、耗时与已记账用量，程序约束结果与语义复核分别记录。

Q11 注入一次摘要中断，验证回复仍能继续和冷却期内的新消息不再调用摘要模型。Q12 只有实际观察到超过八轮取材才通过程序条件。评测边界只作用于这个离线脚本，不改变产品运行策略。脚本类型检查为 `npm run eval:agent:check`，真实模型评测不加入自动发布门禁，避免自动产生费用。历史结果见 [评估记录](ai-agent-evaluation.md)。

输出报告默认保存在 `.tmp/agent-evaluation/`，指定的报告路径必须不存在，复测不能覆盖旧样本。报告记录基准提交、差异摘要及源文件散列（含未提交文件），仅保留合成对话与模型完成内容，不保存凭据或请求头；原始报告用于本地诊断，公开或提交前另行筛选。当前模型质量仍有波动，摘要必须通过完整性及字符串数组结构检查，非法工具批次在执行前被拒绝。提示词明确格式和单批至多四个工具的现有边界；单轮总取材次数仍没有固定八次上限。

## 多次摘要与长材料验证（第五阶段本地候选）

增量摘要同时携带所引用任务的最新状态，只查询同账号、同作品且属于本会话的任务，最多 128 个；只提供 ID、类型、状态与更新时间，不带任务正文、错误详情或生成参数。每一批重新读取状态，已完成的回复不应继续作为待办，生成完成也不等于发布或采纳。未出现在快照中的任务仍需查证，不能推断不存在或一直运行。

摘要提示明确区分作者决定、助手假设、持续否定与后续修正；待办只保留作者明确要求且未完成的行动。回复提示收紧条件句／传闻的证据边界，要求记忆提议忠于原话、直接回答当前问题、以自然语言和章节标题呈现依据。这些是模型约束，不能保证每次遵循，也没有通过删改回复文本掩盖内部编号。

新增 `--suite long-context`，默认仍是原有 12 场景的 `baseline`；两套均默认不联网。长材料套件使用 92,825 字符合成章节和固定讨论，包含三次摘要后修改决定、第二批摘要断流后复用已存检查点，以及超过首段读取长度的章末证据与冻结起点。材料中的环境段落由固定模板扩展，不能替代真实长篇或独立人工验收。每轮额外记录回复长度和疑似内部引用，识别时保留章节链接目标；这些诊断不修改回复，也不是语义评分。

```powershell
npm run eval:agent -- --suite long-context
npm run eval:agent -- --live --suite long-context --repetitions 1 --max-requests 30 --case-timeout-ms 300000 --output .tmp/agent-evaluation/new-long-context.json
```

第二批摘要的受控中断不调用供应商。回复完成后，评测在隔离库模拟冷却期结束，核对下次摘要从未保存的批次开始。每个场景的多轮讨论共用 20 次请求上限，总预算耗尽会留下评测主动取消记录；这与供应商失败分开。边界只约束评测脚本，不给产品恢复固定工具轮次上限。

可显式添加 `--summary-reasoning disabled`，仅在 DeepSeek 兼容预设上对摘要请求试验既有 `thinking: disabled`／`reasoning_effort: none` 参数；其他模型在联网前拒绝该实验。默认 `inherit` 不改请求参数，聊天协调请求不受此实验影响。这是评测传输层开关，产品摘要仍跟随供应商；当前小样本虽能完整返回 JSON，语义仍出现退化，不能默认推广。
