## 首屏依赖与样式

使用固定 Node `22.23.4`、锁文件 Vite `7.3.6`，在既有隔离干净依赖副本中构建；未重装根目录或 Web 开发依赖。分析脚本统计入口及其静态依赖、最终落盘 JS/CSS 原始与 gzip 字节，模块 `renderedLength` 只用于压缩前归因，不能相加当下载体积。

| 首次静态资源 | 同环境改动前 | 本次改动后 | 减少 |
| --- | ---: | ---: | ---: |
| JS | 566,300 B | 535,885 B | 30,415 B（5.4%） |
| JS gzip | 181,364 B | 172,782 B | 8,582 B（4.7%） |
| CSS | 204,105 B | 189,186 B | 14,919 B（7.3%） |
| CSS gzip | 34,185 B | 32,353 B | 1,832 B（5.4%） |

此前约 600 KB / gzip 191 KB 的数字来自另一份本地依赖树，不与本次锁文件产物直接作差。这里统计入口所有静态依赖，拆分后仍立即加载的文件也计入总量。

JS 主要来源仍为 React DOM、Tailwind Merge、React Router、Sonner、共享 API 模块、Radix 与 Floating UI、首页和工作区外壳。首页的 `Pagination` 未传 `pageSize`，拆出该选择器后，Radix Select 不再进入入口。首页及应用级验证流程保留，不为了压包体修改认证机制或替换框架。

CSS 来自全局设计令牌、基础规则、生成的工具类，以及工作区外壳、首页、分页、主题菜单、弹窗和表单组件样式。较大的直接源码包括工作区样式 15.5 KB、首页 8.3 KB、分页 6.1 KB、主题菜单 5.3 KB；这些是未压缩源码归因，不能与产物字节逐项相加。Tailwind 显式扫描 `web/src` 和 `web/index.html`，排除测试；开发组件展厅仍可使用其真实组件样式。已有路由 CSS 拆分继续生效。

`index.html` 仍使用外部 Noto Serif SC 字体及 `display=swap`。本次没有 DevTools 性能追踪能力，也没有实体手机连接，未采集 LCP、INP、CLS、网络瀑布或 CPU trace。不能把 gzip 减少量换算成实际首屏提速秒数。后续在同一手机/网络下比较冷缓存和热缓存，分别检查字体、封面、API 请求及脚本执行；需同时覆盖公开书库、登录后书库、详情与阅读页。

## 大书搜索基准与取舍

`scripts/benchmark-book-search.mjs` 创建独立 PostgreSQL 集群、只监听 loopback，固定随机种子生成 1,000 / 5,000 / 10,000 章，每章约 3,120 字；包含中文、HTML、实体、字面 `%_`、英文大小写、稀疏命中。一次预热后单页测 7 次，整书与冷缓存测 3 次，记录中位数及最大值。使用同一次运行中的旧算法参考实现与新实现比较；整书耗时不包含 HTTP、限流和客户端操作，不能代表手机搜索等待时间。

最终测量使用 PostgreSQL `18.4`（Windows x64）、UTF-8 编码、数据库字符分类 `Chinese_China.936`、Node `22.23.4`。单页使用无命中关键词“无此词语”完整扫描 200 章，整书使用稀疏关键词“青铜古城”；以下均为服务函数与本地数据库耗时中位数。

| 章节数 | 原算法单页 | 热缓存单页 | 冷缓存单页 | 原算法整书循环 | 热缓存整书循环 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 199.25 ms | 33.05 ms | 252.18 ms | 992.10 ms | 148.03 ms |
| 5,000 | 158.75 ms | 30.45 ms | 240.66 ms | 3,920.05 ms | 1,325.52 ms |
| 10,000 | 172.33 ms | 32.48 ms | 253.27 ms | 6,912.35 ms | 1,108.11 ms |

热缓存单页减少约 81%–83% 的耗时；首次填充增加了批量写入，单页比原算法慢约 27%–52%。短样本和主机负载会造成波动，不能用 5,000 与 10,000 章的结果反推线性容量。最终缓存表含索引、TOAST 和基准反复填充后的占用为 125,542,400 B（约 125.5 MB）；这不是备份压缩体积或所有真实书籍的固定存储成本。

实现保留每请求 200 章、最多 20 条结果及继续游标。字符匹配仍是原来的 Unicode 不区分大小写字面正则；HTML 解码、跨行内标签匹配、片段与阅读器文本语义不变。新缓存位于独立表，避免既有 `SELECT c.*` 的阅读请求把正文多拉一份；正文版本和清理器版本同时匹配才可读取。触发器覆盖手工编辑、导入、抓取、回滚等写入路径，迟到的旧缓存不会成为有效结果。清理规则改变时必须递增 `BOOK_SEARCH_TEXT_VERSION`。

缓存按实际搜索覆盖的章节填充，不在迁移/启动时扫描整库；单次待写缓存限制 4 MiB，超大章节仍可检索但可能不缓存。新增正文序号与 id 的复合索引，保证同序号章节游标稳定。缓存会增加磁盘及备份体积；恢复影响报告排除该派生表，读者搜索不应让恢复确认失效。

当前 Web 的“继续搜索”是显式下一批操作；登录账号每分钟 30 次、IP 每分钟 60 次搜索的原有限流不变。10,000 章稀疏查询可能需约 50 批，若连续请求仍受限流约束。本次解决重复清理成本，没有把服务层整书循环基准包装成一次 HTTP 请求的搜索表现。后续索引需同时解决查询候选、短关键词、中文字符分类、分页契约和实际限流预算。

中文索引评估覆盖普通 `pg_trgm` 和显式 ICU 中文 collation；在数据库 `LC_CTYPE=C` 的第一轮，中文没有得到有效 trigram。给表达式加中文 collation 不足以修正该环境的字符分类，因此不能只创建一个 GIN 索引就宣称中文搜索已优化。另用中文数据库字符分类复测，完整执行计划保存在基准 JSON。生产未安装或更改任何扩展、数据库 locale 或索引策略。

| 10,000 章查询 | 默认中文数据库索引 | 显式 ICU 中文索引 | 实际计划 |
| --- | ---: | ---: | --- |
| 青铜古城（四字、稀疏） | 0.47 ms | 0.71 ms | Bitmap Index Scan |
| 海风（二字） | 508.13 ms | 478.26 ms | Seq Scan |
| 猫（一字） | 460.64 ms | 446.05 ms | Seq Scan |
| `%_`（字面标点） | 448.51 ms | 529.95 ms | Seq Scan |
| 无此词语（四字、无命中） | 0.35 ms | 0.44 ms | Bitmap Index Scan |

两个索引各占 46,522,368 B，建立分别用时约 23.9 / 22.5 秒。这里测的是数据库一次全文查询，不含现有片段生成、命中计数、Unicode 大小写字面复核和 HTTP 分页；因此不直接与上方单页接口耗时比较。当前迁移仅交付文本缓存与目录排序索引，不安装该实验 GIN 索引。

1–2 字子串及标点是当前功能的合法输入，不能改成只支持分词匹配。若继续建设索引，可比较应用生成的 Unicode 二元组候选索引（保留字面复核、单字回退）与受控中文 `pg_trgm` 环境；需先测候选选择率、索引/写入体积、极短关键词和 Unicode 大小写一致性，再决定方案。

## 目录规模与兼容性

合成 10,000 章目录的现有 JSON 为 1,227,833 B，gzip 85,917 B，不含任何正文；真实标题与来源 URL 更长时还会增长。1,000 / 5,000 章分别为 120,830 / 612,830 B。阅读器已经有虚拟列表、短期目录上下文缓存，且正文渲染不必等待完整目录，因此不重复实现。

详情页用现有 `Pagination` 组件限制至 100 个章节链接，先全量筛选再分页；“定位到阅读位置”清除筛选并进入所在页，在渲染完成后聚焦对应章节。列表保留轻量阶梯入场和检索过渡态；减少动态时取消入场位移及平滑滚动。10,000 章回归验证了第 101 章翻页、末章标题搜索、第 9999 章定位及 100 条渲染上限。

API 默认响应和 iOS 完整目录契约保留，排序统一 `sort_order,id`。当前先处理确定存在的 DOM 放大问题；服务端分页若实施，需要额外提供全目录标题搜索、指定章邻居及按章定位能力，不能只截断现有数组。未加入跨账号共享目录缓存，权限撤销仍走原有检查与刷新流程。

## AI 租约与恢复边界

每次进程启动生成随机归属标识，创建任务即取得 5 分钟租约，现有一分钟心跳负责续租；任务进展写入同样续租。使用数据库时钟判断到期，失效租约无法被原心跳或进度更新复活。读取进度、列表及管理员取消保持现有 API 字段与授权。

启动只终结无有效租约的写作/图像等任务；有效任务保留。到期的可恢复 `cover_prompt` 按活动状态及到期时间直接领取，使用数据库行锁和 `SKIP LOCKED`，不从最近 100 条记录里再筛选。每个实例同一时刻只恢复一项，每轮至多 10 项，后续定时继续；恢复不阻塞服务监听。

归属历史禁止某进程第二次执行同一个任务，避免 A → B → A 后 A 的旧回调重新有权写入。同进程内过期任务终结，人工重试生成新任务 id。写作草稿、封面候选、划选图片在保存事务中检查有效租约；分级循环同时检查任务活跃性。已有故事档案自己的检查点/租约机制保留。

这不是整站多实例交付。写作并发计数仍非全局原子配额，抓取/追更/备份等调度需分别审查；租约也不能保证外部模型调用恰好执行一次。恢复封面提示词可能再次请求上游，写作和图片任务不自动重放。首次从 `0.10.0` 升级须停止旧服务再迁移；旧执行器不认识归属字段，不能混合版本滚动部署。
