# 书籍导入边界复核

TXT 预览先运行确定性解析，AI 仅审核存疑行。模型不会生成正文、章节编号或导入匹配键。AI 复核仍需在参数设置中开启；人工边界修正不依赖 AI。

解析规则版本 5 支持无冒号、跨空行的独立「内容简介」段落，以及带「食用须知」「剧情简介」「ps」等小标题的分段简介；支持「题名」「Tag列表」导出字段，避免长简介占用首页和推偏后续序号。元信息之后、首个可靠第 1 章之前的连续编号说明列表归入前置信息；正常点分章节中间有正文时不受影响，人工强制边界优先。

点分、英文和紧贴数字章名参与编号诊断；回填长章名时要求编号尚未识别，且候选按顺序位于原文前后章节之间。打赏数量、`1v1` 标签和「第一回合／第一节课」不直接切成章节。有明确、可识别章名的空正文条目（如「第0009章 打赏章，随缘！」）保留，字数为零，参与目录和编号统计，不按特定章名关键词处理；只有编号或误判的数量提示空条目继续过滤。缺号、重号均在诊断中提示，文件名进度不作为补章依据。

同一卷内的章节编号、有效章名及非空正文均一致的重复条目只保留首次出现项，正文比较仅忽略空白排版，诊断记录合并数量与原文行号，原始快照保留。明确双层编号使用作者内层编号辨认版本，保留导出标题展示。不同卷重新编号的章节、不同编号的同名占位正文、空公告不会仅因内容相同而合并；人工强制的标题边界可保留指定副本。

同章存在实际文字差异，或同编号下包含「错章／修订」等明确标记时，保留版本候选，默认不选。管理员可展开原文比较并选择一个版本；前端同组互斥，服务端按锁定的解析快照重新检查，拒绝同时提交多个版本及不含版本信息的旧预览。选择后出现的修订版仍使用该章首次出现的位置，已有章节更新则保留已匹配序号，避免阅读顺序改变。选择版本不表示文件名进度或缺失编号已得到补齐。

导入与融合共用已有章节时，完整正文唯一一致可作为标题、序号变化后的补充匹配证据，默认仍不勾选已有变化。同一本地章节不能被多条导入记录重复对应，共用文件地址也不能被视作唯一章节地址；附加文件的 `#chapter=N` 只是切分位置，不能覆盖修正边界后的标题、正文证据。

## 管理员操作

作品匹配只接受清理导出标记后的完整书名一致，或来源地址一致；书名包含关系不再视为同一本书。同名但已知作者不同的候选不会自动选中，需人工确认。候选列表始终提供「新建作品」，选择后按新书生成差异并提交，不会回退到唯一候选。

在「核对导入内容」展开解析诊断，可查看异常、待复核范围、累计复核进度和原文保留期限。每次 AI 复核处理一批未复核行，包含与规则一致的结论也会记录为已复核；「继续复核下一批」不会重新发送这些行。当前最多展示 300 条待复核证据，剩余行会在后续扫描中处理。没有存疑行不等于切分一定正确，仍应检查章节列表。

AI 建议可逐条取消勾选，通过「比较所选修正」查看合并/拆分前后的章节标题、字数和内容片段，再采纳所选建议。未选建议继续保留。人工修正按原文行号操作：查看附近原文，选择标题或正文，预览影响后应用。所有修正累计保留；可以撤销单条修正，或恢复原始解析并清空复核进度。

重新切分会重建差异预览，章节和作品信息勾选回到默认状态，提交前必须重新核对。复核期间禁止在当前弹窗提交、返回或关闭。其他标签页改变预览时，旧版本操作返回冲突，可加载最新预览后继续。

## 输出与审计

复核仅接受包含整数候选行号的 JSON `{"headings":[12,47]}`；空数组是有效的全部正文判定。格式错误、候选之外的行号、空回复、截断和结构化拒答不会生成可采纳建议。上游成功返回的用量在验证结论之前记入 `ai_usage`，包括这些失败结果；网络失败或上游没有返回用量时不虚构 token 和费用。每次复核的运行、完成或失败状态写入 `book_import_review_attempts`，保留 90 天。

## 快照与保留

迁移 `054_import_review_state.sql` 增加版本、原文哈希、租约、过期时间和轻量历史摘要。修改目标、复核、采纳、人工修正和提交请求必须携带当前 `revision`。服务端使用条件更新检查版本，提交在事务加锁后再次检查并读取最新快照。数据库租约阻止同一预览的重复模型调用；服务意外退出后的租约最多保留 10 分钟。

未提交预览保留 7 天；导入完成后解析快照保留 30 天。服务启动时及每小时清理到期的 `source_text`、`payload_json`、`preview_json`；未提交的记录标记为已过期，不再允许提交。历史摘要、原文哈希、状态和安全撤回依赖的 `changes_json` 继续保留，因此清理不会关闭回滚能力。历史列表只查询摘要，不加载原文、整本章节或回滚正文。

存量记录会按原创建/导入时间回填保留期限与摘要；没有原文的旧记录无法补做边界复核。发布时应同时部署 API、Web 和迁移；旧客户端不携带版本的变更请求会被拒绝，并提示重新预览。

早期执行过 054 的数据库可能仍保留不含 `expired` 的旧状态约束，导致启动清理报 `23514 / book_import_runs_status_check`，随后出现 Vite API 代理错误。迁移 055 独立更新约束，兼容这些数据库及全新安装。更新代码后重启 dev 服务会自动迁移，也可先运行 `npm run db:migrate`；不要删除迁移记账或重新执行整个 054。
