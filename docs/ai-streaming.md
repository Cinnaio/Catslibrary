# AI 文本流式输出

本轮纳入 Web `1.3.0` / API `1.1.0` 源码候选。文本模型默认使用流式请求，浏览器逐步显示可预览的内容或生成进度；完整响应仍经过原有校验、记账与保存流程。图片生成沿用原图像接口，普通查询、保存和发布接口保持 JSON。

## 覆盖范围

| 场景 | 生成期间 | 完成后 |
| --- | --- | --- |
| 对话创作 | 助手文字按片段更新并解析 Markdown，工具执行显示阶段 | 保存会话消息和工具产物，同轮预览自动去重 |
| 续写、新写、大纲、改写 | 显示有限长度的文本预览、思考／输出字符数 | 校验后保存草稿或改写建议，原有采纳流程保持 |
| 情节方向、标题、风格、草稿检查、故事关系图 | 普通文字可预览；结构化输出只显示阶段与计数 | 完整解析并校验后显示候选、报告或图谱 |
| 情节／关系档案 | 订阅任务进度，显示当前生成状态及已保存章节范围 | 重新读取有效档案；阶段内容不自动成为续写材料 |
| 前情提要、阅读回顾 | 页面内显示文本预览 | 使用完整结果与既有缓存、配额规则 |
| 封面描述词 | 同步生成显示文本处理进度；后台封面任务推送描述词阶段与计数 | 显示已验证的描述词；图片仍在生成完成后显示 |
| 导入 AI 复核、内容分级分析 | 显示生成阶段与计数，保留批次状态核对 | 显示通过校验的建议，仍需原有人工审核 |

## 配置与兼容

新配置及缺失配置的 `writingStreamEnabled`、`storyMemoryStreamEnabled` 默认开启。已有明确保存为 `false` 的值继续生效，不自动覆盖用户选择。需要全站启用时，在「模型与服务」的参数配置中打开「正文与大纲实时预览」「关系与情节档案实时预览」并保存。

文本上游按 OpenAI 兼容 Chat Completions 请求 `stream: true` 与用量结束帧。供应商忽略流式参数而返回 JSON 时仍能读取完整结果；只有明确以 400／422 拒绝流式参数时才回退一次普通请求。无关的参数错误不触发回退。成功接收响应后，即使首段文字尚未到达，也不因断线或超时自动重新发起同一流式生成。

工具名称、调用 ID 和参数按流式索引拼接，完整返回并通过原有工具白名单、参数及权限检查后才执行。未完成参数不能触发业务操作。原始推理内容和工具参数不会作为用户可见的实时预览；界面只显示推理字符数，模型续接所需的推理字段留在服务端。

## 连接与恢复

- 同步生成接口通过 `Accept: text/event-stream` 协商，发送进度、心跳及携带原 HTTP 状态和业务数据的最终结果事件。不带该请求头的旧客户端仍收到原 JSON 和状态码。权限中间件先于流建立执行。
- 后台任务使用已有 `/api/ai/tasks/:id/stream`。进程内推送即时状态，定期读取数据库核对；慢连接合并为最新进度，避免无限排队。文字预览有长度上限，通用任务检查点限频保存；后台封面构思计数为即时状态，原有描述词检查点与最终结果格式保持。
- 浏览器断线后只重新读取、订阅原任务，不重新提交模型生成。刷新或离开页面不停止已经提交的后台任务；暂停仍由用户显式操作。流连接定期重建以复核登录和任务权限；Agent 任务只对所属账号可见。
- 同步生成连接中断时，服务端可能仍在完成操作；它没有统一的后台任务恢复能力，浏览器也不会自动续接该 POST。应先检查对应缓存、报告、档案或结果，再决定是否重新生成。服务器重启后的任务处理仍遵循原有租约与恢复策略，不能把刷新恢复与进程崩溃恢复等同。
- 前端按账号、作品、草稿版本及请求轮次忽略过期响应；两个独立档案任务分别读取最终结果，不相互取消刷新。未完成预览不覆盖正式正文、已采纳内容或有效故事档案。

流式缩短的是看到内容的等待时间，不保证模型总耗时更短，也不能消除供应商、反向代理或浏览器的总时长限制。代理应允许 SSE 持续传输；接口使用 `no-store, no-transform` 和 `X-Accel-Buffering: no`，仍需部署环境实际验证。中断时收到的用量按已接入服务的原审计上下文记录，未上报金额保持未知，不根据预览长度估算费用。

本轮没有新增依赖或数据库迁移；对话创作原有迁移 078 的要求不变。检查与实际交付状态见 [发布记录](releasing.md)。
