## 第五阶段：长对话、多次摘要与长材料（2026-11-09，本地候选）

本阶段仍在 `codex/agent-quality-usage` 独立工作区进行，未提交、合并、推送、部署或执行生产迁移；另一个 chat 对主工作区的小说分析修改保持隔离。实现新增三项边界：摘要批次会按同账号、同作品及当前会话归属读取引用任务的最新状态；摘要提示明确要求修正优先、待办必须来自作者明确要求、助手假设和条件句不能升级为决定或事实；评测脚本新增 `--suite long-context`，并保留可选的 `--summary-reasoning disabled` 兼容性试验。产品默认不改变供应商思考模式，严格摘要校验、原文保留和显式恢复仍有效。

长材料套件包含固定生成的七章、92,825 字符合成正文，冻结起点为第六章。前六章各约 1.5 万字符，由重复环境段落扩展，关键证据放在首段 12,000 字符读取之外；三组场景分别验证 153 条种子讨论中的三次摘要修正、145 条种子讨论中已有检查点后的第二批断流恢复，以及章末关键证据、条件句和起点外后续章节。合成环境不是现实长篇，也不能替代作者或独立人工验收。

两次默认提示运行共 9 个样本、66 次真实请求、输入 396,748、输出 50,455 Token；其中 7 个样本通过可执行条件，2 个样本在真实摘要截断或评测请求上限后保留失败记录。摘要失败均没有推进游标、没有自动重试；已有检查点和原始消息保留，显式恢复从失败批次继续。费用接口没有返回金额，未知费用不记作免费。真实返回模型为 `deepseek-v4.1-flash`，配置预设为 `deepseek-v4.1-flash-tiancai`。

单独的三次摘要思考模式试验使用 `thinking: disabled`／`reasoning_effort: none` 发送了 14 次请求；三次摘要都完整结束并记录 `reasoning_tokens=0`，但评测请求预算在最后答复前耗尽，因此不能把它当作整场景通过，也没有把该选项写进产品默认。该试验还显示模型仍可能把“助手假设未被作者采纳”压缩成“作者否定”，或在目标中保留旧地点；这类语义问题不能靠关闭思考模式直接解决。

修改后两次复测中，L01 第一次在第二次摘要时真实截断（`finish_reason=length`、输出 4,096 Token、正文通道仅 515 字符），旧检查点保持不变；第二次完整经过三次摘要，保留最后地点、持续“不立即和解”和“不毁掉物件”。L02 两次只读恢复完成，L03 两次都取回第二、四、五、六章的尾部证据，判断条件句不能证明交接，并未把第七章发给模型。完成的复测摘要未再自行添加待办，任务状态快照让已经答复的核对请求可按服务端状态标记完成。

仍存在的缺口：L01 部分回复展示 `#消息编号`，L02 恢复回复仍长达 506／830 字符，有无必要逐页查阅的差异，个别回复扩展了不需要的档案或产出说明。关闭思考的实验摘要更出现“未采纳假设”变成“已否定”及目标保留旧地点。提示词改进没有证明通用可靠性；程序条件不是准确率或质量排名，也没有进行 OpenAI／Claude 横评。

本阶段总计 80 次真实请求、20 次真实摘要请求，输入 488,761、输出 53,622 Token；另有三次不请求供应商的断流注入、两次评测预算触发停止，费用未知。基线 L03 和思考实验 L01 的最后答复分别因预算停止，不能算供应商故障或语义通过。旧评测中 L01 在第二阶段失败后尚未播种第三阶段，`all_153_seed_messages_retained=false` 表示未完成全程，并非丢失已保存消息；实际 108 条种子消息保留。现脚本将“已播种消息保留”和“三阶段全部执行”分开检查，原报告不改写。思考实验当时通过临时产品代码发送参数，记录了该源码散列；现已撤回，只保留脚本显式开关，未做额外付费复测。

筛选后的长材料报告保存在 [agent-long-context-evaluation-2026-11-09.json](diagnostics/agent-long-context-evaluation-2026-11-09.json)，包含各轮摘要、失败、工具来源、用量和请求边界诊断，但不含凭据、请求头或完整原始请求。首次阶段报告与既有第四阶段报告保持不变。下一步应由人工抽查真实长篇或作者提供的安全样本，重点看多次修正、任务状态语义、内部编号隐藏和摘要截断后的恢复；在此之前定位仍是“有监督的小规模试用”。

## 第四阶段：可重复真实评测与单轮用量（2026-11-09）

当前实现已经具备持久会话、按账号／作品隔离的长期约定、结构化摘要、按起点取材及来源、显式采纳、只读恢复和按轮次用量；适合作为有作者监督的创作助手进行小范围试用。真实模型的格式遵循、证据范围与回答简洁度仍有波动，不能称为成熟的无人监督代理，也没有与 OpenAI／Claude 进行同题模型对比。

本轮在 `codex/agent-quality-usage` 独立工作区完成，基于 `946af13c`。新增 `api/scripts/evaluate-agent.ts` 和 12 项合成场景，每项独立准备作品与账号、执行三次；Q02 使用手动保存的生效约定，不复用 Q01 结果，确认接口另由自动回归覆盖。Q03 每次同时测试另一账号及另一作品；Q11 先注入不调用供应商的摘要断流，再显式发起只读恢复；Q12 使用十个各含独有线索的短章，要求逐章查阅。报告保留所有失败，不自动重试或仅挑成功样本。

文本预设为 `deepseek-v4.1-flash-tiancai`，所有已捕获上游模型名为 `deepseek-v4.1-flash`。仅允许当前补全端点，业务生成／发布适配器记录并拒绝；使用内存 PGlite，未读取生产小说、聊天或业务数据库。费用补充端点在本次评测中禁用。默认计划不读取模型配置或联网，运行方式：

```powershell
npm run eval:agent
npm run eval:agent:check
npm run eval:agent -- --live --output .tmp/agent-evaluation/new-baseline.json
```

默认每项三次、总计最多 160 次真实补全、每项最多 20 次、每项 180 秒，显式 `--cases`／`--repetitions`／`--max-requests` 可缩小范围。输出路径必须不存在，复测另存文件。程序检查只验证实际状态、权限边界、游标和工具执行，不用关键词命中率假装语义质量；原始报告的 `review.status=needs_review` 保留独立人工审阅要求。以下为本次代码助手逐条读取后的观察，并非人工盲评或供应商排名。

下一步优先级：

1. 用更长、包含真实修正与多次摘要的作品做独立人工审阅，重点检查否定、来源范围、状态更新和恢复结果；把实际失败固化为后续场景。

4. 待并行开发收敛后合并两个工作区，保留双方的工作流／发布记录，再验证组合版本与迁移 079、080。当前独立工作区尚未提交、推送或部署，iOS 继续暂停构建。

## 第三阶段：恢复契约验证（2026-11-09）

基于 `61bea407` 的本地工作区，补充失败／取消轮次恢复、最新轮次校验、账号与会话隔离、并发恢复去重、只读工具允许列表与整批非法工具拒绝、原产出／待采纳操作保留、租约失效执行器、旧实时状态覆盖、发送回执和保存失败分类。新恢复只创建查阅／答复轮次，不恢复执行检查点或重放业务生成。长消息无法压缩时关闭恢复入口；摘要、模型输出与保存失败分别标记。

API Agent 路由共 70 项，配合检索 17 项、任务租约 7 项；Web 对话 16 项、记忆 5 项、来源 1 项、任务状态 2 项和事件流 4 项。全部使用隔离 PGlite／模拟模型，新增恢复测试没有真实模型用量；测试结果与构建状态以 [发布记录](releasing.md) 为准。

真实 Edge 连接隔离 API 验证：旧实时运行状态遇到服务端中断后退出处理中；刷新读回聊天及未完成产出；待确认消息通过 GET 回执核对清除，无重新发送；390px 窄屏无横向溢出；恢复前弹窗确认，执行一次本地模型桩调用，保留新输入，刷新完成回复不增加请求。记录在忽略目录 `.tmp/agent-recovery-browser.ts`；所有临时服务和浏览器已关闭，无截图、真实上游请求或线上修改。

这些结果验证恢复边界和交互，不验证真实模型继续整理的语义质量；第二阶段首次摘要失败仍未复现，根因仍未知。以下保留此前模型样本和费用记录。

记录日期：2026-11-09。目标是验证持久记忆、确认边界、长对话连续性及可追溯的资料检索，不将模拟上游的回归结果当作实际模型质量评分。运行前固定源码、文本服务预设和模型名称，使用专门的测试账号／作品；同一组人工场景用相同输入和资料比较模型，并保存回复、实际工具调用、来源、耗时与真实用量。不要把生产用户聊天作为公开评估样本。
