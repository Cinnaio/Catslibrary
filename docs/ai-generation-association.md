# 失联草稿重新关联

书籍删除后重新导入可能得到新的书籍与章节 ID。旧产出依然保留，但无法通过原 ID 查询当前作品。API 1.9.0 与 Web 1.10.0 提供管理员人工修复入口，不自动按书名归并记录。

## 操作

1. 在「草稿与产出」列表的关联筛选中选择「关联失效」，或打开原任务的草稿列表；旧失联视图链接仍可直接打开。
2. 从记录菜单选择「重新关联作品」，也可勾选多条待审草稿后批量处理。
3. 搜索并选择现在书库中的作品。可选择同时处理原作品同批次的其他失联待审草稿。
4. 点击「预览关联」，核对目标书名、作者、草稿数、来源书名及已保存的原续写起点。
5. 点击明确标注数量的确认按钮。草稿继续保持待审状态，从目标作品查看并按原流程审阅、发布。

原始提示词和冻结生成参数保留。关联修复不会恢复旧的章节 ID、继续运行旧任务或自动发布。继续创作前应重新选择有效续写起点；对修复后的草稿重新检查时，界面注明使用当前作品的末章作为参考。

详情中的「作品来源与关联记录」按需展示已有来源、原起点及关联时间和目标。操作审计记录操作者与实际影响数量。未保存书名的旧产出明确显示未知，可查看原 prompt 后人工选择目标。

## 接口与数据

- `POST /api/ai/generations/association/preview` 接收 `ids`、`novelId`、`includeBatch`，返回实际范围与预览 `revision`。
- `POST /api/ai/generations/association/confirm` 使用相同范围、`revision` 和 `operationId`，在事务内校验并写入；响应不确定时重试同一操作 ID。
- `GET /api/ai/generations?association=missing` 精确筛选当前书籍 ID 不存在的记录，并在分页和分组前应用条件。原有 `novelId` 始终表示当前归属。
- 迁移 089 添加 `book_snapshot_json`、`association_revision`、`association_history_json`。已有可关联作品补录的是迁移时书目信息；新创作在模型调用前捕获快照，之后编辑或删除作品不影响该快照。

一次最多处理 500 条草稿，所有写入需管理员权限。有效关联、已发布或软删除记录不在此流程迁移；原作品有排队或运行中的任务时需等待完成或先停止。预览后内容、范围或目标变化会返回冲突并要求重新预览。

Web 入口需配套升级 API 并完成迁移 089。旧客户端可忽略新增响应字段，iOS 暂未增加修复界面。
