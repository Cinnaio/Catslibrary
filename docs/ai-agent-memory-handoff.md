## 检查范围与结果

Q17 使用独立本地 PostgreSQL 中新建的合成账号和作品，经实际登录、Cookie／CSRF及 Agent API 路由执行；路由通过进程内 `app.request` 调用，不是浏览器操作验收。确认动作由检查脚本对合成记录执行，不代表用户已确认或完成人工验收。没有向模型发送真实作品正文，也不修改用户试用的作品、账号或会话。

| 范围 | 本次证据 |
| --- | --- |
| 提议待确认 | 提议保留完整原句；确认前新会话的生效清单为空 |
| 确认后的新会话 | 生效清单带入完整原句，保留否定及条件；不重放来源会话，仍可回查记忆原文 |
| 已打开的会话 | 确认后的下一轮读取更新清单；同时发现下述错误归因 |

修正检查脚本后的完整链路通过27项程序条件，但语义存在一项失败：原会话称“我上轮误答为空”，而上轮清单确实为空，记忆是在两轮之间生效的。程序通过不能替代回复语义判断。

提示现已明确当前清单只代表本轮状态，不能反推上轮答错、编造变更时间或操作者；空清单也不能证明作者从未保存或讨论过约定。该真实失败改编为 Q18：先写入准确的空清单历史，再保存生效记忆，询问当前约定。一次复测的4项程序条件通过，回复没有再错误归因，但仍多了一句“本次未查证上一轮的清单记录”。只做这一轮定向复测，没有在最终提示修改后重跑完整Q17，不能宣称稳定修复。
