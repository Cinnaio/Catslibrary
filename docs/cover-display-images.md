# 封面原图与压缩展示图

原图继续保存在 `novel_covers`、`ai_cover_candidates` 与 `novel_cover_history`，不改变原始 MIME、字节、提示词及元数据。封面采纳、并发版本校验、历史恢复、导入回滚和 ZIP 导出仍使用原图，避免反复有损转码。

## 展示策略

- `GET /api/cover/:id?size=320`：书库、书架及管理列表的缩略图，宽度最多 320px。
- `GET /api/cover/:id?size=1024`：详情及管理预览，宽度最多 1024px。
- 不传 `size` 或传入其他值：使用 1024px 策略，兼容现有客户端；旧 iOS 无需更新即可在下一次实际下载时获得展示图，已缓存图片继续遵守现有过期规则。
- `GET /api/cover/:id?size=original`：读取原图；与展示图使用同一套作品可见范围、内容分级与账户权限检查，不能用条件请求跳过检查。

静态 JPEG、PNG、WebP、AVIF、GIF 使用 Sharp 转为 WebP，质量参数 85、effort 4、smartSubsample，自动处理 EXIF 方向并移除非必要元数据。质量参数并非画质保留百分比。按比例缩放、不裁剪、不放大小图；极长图片的高度最多为该档宽度的三倍。转码结果只有在字节数更小时才使用，否则返回原图，因此尺寸是优化目标而非所有图片的强制保证。动图、无法解码、超出 4000 万像素及不支持的格式沿用原图。

本地默认封面已经是 WebP，继续复用打包资源，不按每部作品重复入库。AI 候选列表与历史图片接口返回 1024px 展示结果，并根据实际字节设置 MIME；候选采纳和历史恢复始终读取数据库原图。

## 存储与缓存

新增迁移 `071_cover_display_images.sql`，在独立的 `cover_display_images` 表保存展示结果。键包含作品 ID、编码策略版本／原图 MIME／原始字节的 SHA-256 和尺寸。同一原图从候选变为当前封面或进入历史时复用展示图；替换图片及导入回滚自动对应不同哈希，不依赖修改原图版本。不产生体积收益或无法处理的图片只存 NULL 回退标记，不额外复制原图。

新生成候选、源站下载、本地上传与 ZIP 封面导入预热两种尺寸，编码安排在封面替换事务的行锁外；旧图、恢复及回滚后缺失的展示图在首次读取时补生成。进程内相同图片和尺寸合并并发补图，编码最多同时执行两项。预热失败保留原操作结果，后续读取可重试。

每次补图最多清理 32 条创建已超过 30 天的展示记录；清理不影响原图，仍使用的图片后续可重新生成。删除作品通过外键级联删除展示图。展示图属于可重建缓存，保留原图与展示图会增加数据库总占用；现有全库备份包含此表，升级后的备份迁移版本为 71，恢复仍需遵循现有迁移版本兼容规则。

公开作品沿用私有客户端缓存与 ETag，非公开作品和源图下载失败的占位响应继续 `no-store`。ETag 根据实际输出的 MIME 与字节计算；Web 封面 URL 新增尺寸并递增 `cover` 标识以避开旧的原图缓存。不同尺寸、原图下载各有独立 URL。访问校验始终先于读取展示缓存和返回 304。

## 发布与验证

本次为 API/Web `0.8.0` 源码候选，需先应用迁移 071 再运行新版 API，配套更新 Web 以使用列表缩略图。没有新增依赖，不改动根包及 iOS 版本，不交付 IPA。不在开发工作区批量改写旧封面或操作生产数据库；旧封面首次网络读取时逐步建立展示缓存。实际类型检查、定向回归与构建部署状态见 [发布记录](releasing.md)。
