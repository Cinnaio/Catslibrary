# 创作记忆：完整初始化与增量更新

情节状态、关系画像共用 `story-memory.ts` 的提取流程。风格画像继续使用原来的风格取样策略。

## 管理端使用

在创作工作台选择小说及续写起点，点击「更新情节档案」或「更新关系档案」。首次从第一章处理到所选起点；未指定起点时使用发起请求时的最新章节。界面自动继续下一批，并显示已覆盖章数。

「每批最多」控制单次处理的章节上限，不限制总覆盖范围。正文按顺序送入，正常批次控制在约 24000 字符内，超长章节连续分段读取，包括章末。每段均带章节 ID，提示词要求重要记录引用来源，并区分事实、人物认知、线索与计划。

后续更新先校验此前覆盖的全部正文，再用旧档案和新增章节增量更新。不因本批未涉及而删除长期线索，已解决事项保留解决记录与来源。已经覆盖且来源相同的档案直接复用，不重复付费调用。

关闭页面、网络失败或模型失败后，再次点击可从已完成章节的检查点继续。尚未完整处理完的超长章节会重新处理。检查点与续写使用的正式档案分开；只有覆盖目标的全部章节后才替换正式档案。

## 来源校验与正文边界

- 档案来源记录覆盖起点、实际章数、全量正文指纹及提示词版本。
- 已覆盖正文的内容、标题、顺序变化，或历史章节插入/删除，会导致指纹失效；旧档案可以查看，但不再注入续写。再次更新会从可验证的基底重建；没有有效基底时从第一章开始。
- 新增已发布章节使档案标记为 `stale`，更新后恢复可用。正文发布不会自动发起付费提取；由管理员点击更新。
- 向更早的起点提取时，不继承起点之后的档案。提取期间正文变化会阻止本次结果发布。
- 只读取 `chapters`，未发布草稿、备选版本和大纲不会进入故事记忆。
- 旧的近期取样画像仍保留展示，标记为 `legacy_unknown`，完成历史初始化后才恢复使用。
- 同书同类档案通过数据库租约防止同时提取；进程崩溃后的租约最长十分钟自动过期。

## API 协议

`POST /api/ai/writing/plot-state` 和 `POST /api/ai/writing/relationship-profile` 每次推进一批，仍接受 `novelId`、`afterChapterId`、`sampleChapters`。

响应新增 `complete`、`processedChapters`、`totalChapters`、`targetChapterId`。`complete=false` 时，调用方应使用首次回传的 `targetChapterId` 继续请求，直到 `complete=true`，以避免初始化期间新增章节使目标不断移动。中间响应的正文只用于进度，不是已生效的正式档案。

每次实际模型响应单独记录用量和上游成本，包括空回复、拒答与被截断的回复。已返回结果被拒绝时不会推进检查点。HTTP 请求超时本身无法证明上游未执行；这种情况下保留已有检查点。

## 上线与验证

先部署数据库迁移 `063_story_memory_builds.sql`，再使用新 API 和管理端。迁移只新增检查点表，不批量改写已有画像或小说正文。

隔离 PGlite 测试覆盖两种档案的全量初始化、增量输入、超长章末、来源修改、历史起点、插入/删除/重排、失败续跑、截断计费、并发租约及超过三十章的历史；面板测试覆盖自动推进、固定目标、中间结果隔离及失败重试。测试模型为桩，不消耗真实模型额度。

此阶段完成历史覆盖、更新和失效处理。逐条结构化证据库、自动检索历史原文、生成后一致性审查仍属于后续阶段。来源标记和条目保留由提取提示词约束，模型语义准确性仍需作者核对。
