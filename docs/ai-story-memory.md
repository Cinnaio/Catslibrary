# 创作记忆：完整初始化与增量更新

情节状态、关系画像共用 `story-memory.ts` 的提取流程。风格画像继续使用原来的风格取样策略。

## 管理端使用

在创作工作台选择小说及续写起点，点击「更新情节档案」或「更新关系档案」。首次从第一章处理到所选起点；未指定起点时使用发起请求时的最新章节。界面自动继续下一批，并显示已覆盖章数。

「每批最多」控制单次处理的章节上限，不限制总覆盖范围。正文按顺序送入，多章累积批次控制在约 6000 字符内，单个超长章节按 24000 字符连续分段读取，包括章末。每段均带章节 ID，提示词要求重要记录引用来源，并区分事实、人物认知、线索与计划。

后续更新先校验此前覆盖的全部正文，再用旧档案和新增章节增量更新。不因本批未涉及而删除长期线索，已解决事项保留解决记录与来源。已经覆盖且来源相同的档案直接复用，不重复付费调用。

关闭页面、网络失败或模型失败后，再次点击可从已完成章节的检查点继续。尚未完整处理完的超长章节会重新处理。检查点与续写使用的正式档案分开；只有覆盖目标的全部章节后才替换正式档案。

更新中可点击「暂停更新」。暂停请求持久保存在服务端，并取消当前上游请求和重试退避，不再等待模型完整生成。同进程直接发送取消信号，其他进程通过每 250ms 一次的串行状态检查接收暂停；实际响应时间还受数据库和网络影响。正在执行的租约在请求退出后释放，避免取消尚未结束时重复运行。若取消前已经拿到完整响应，仍记录真实用量并保留完整批次检查点。超长章节只完成部分分段时不推进该章，继续时从该章开头重新处理。最后一批已完整完成时正常完成更新。未收到完整响应时不虚构 Token 或成本记录，取消连接也不保证上游停止计算或不计费。

页面重新打开会显示「已保存 X / Y 章」与「继续更新」入口；仍在执行的批次会轮询状态，也能请求暂停。继续默认沿用持久保存的原目标，不把后来新增章节悄悄加入；显式选择其他续写起点时以新选择为准。恢复前重新校验正文，修改、删除、插入或重排后仅复用仍然有效的检查点。关闭页面会停止浏览器的后续批次推进，已发出的服务端请求仍可能完成。

迁移 `066_story_memory_pause.sql` 新增暂停标记与目标章节。`POST /api/ai/writing/memory/:kind/:novelId/pause` 仅管理员可调用，kind 为 `plot` 或 `relationship`。两类档案的 GET 接口返回 `progress`（已处理章数、总章数、目标、运行状态和暂停状态），不暴露中间档案正文。

## 来源校验与正文边界

- 档案来源记录覆盖起点、实际章数、全量正文指纹及提示词版本。
- 已覆盖正文的内容、标题、顺序变化，或历史章节插入/删除，会导致指纹失效；旧档案可以查看，但不再注入续写。再次更新会从可验证的基底重建；没有有效基底时从第一章开始。
- 新增已发布章节使档案标记为 `stale`，更新后恢复可用。正文发布不会自动发起付费提取；由管理员点击更新。
- 向更早的起点提取时，不继承起点之后的档案。提取期间正文变化会阻止本次结果发布。
- 只读取 `chapters`，未发布草稿、备选版本和大纲不会进入故事记忆。
- 旧的近期取样画像仍保留展示，标记为 `legacy_unknown`，完成历史初始化后才恢复使用。
- 同书同类档案通过数据库租约防止同时提取；进程崩溃后的租约最长十分钟自动过期。

## API 协议

`POST /api/ai/writing/plot-state` 和 `POST /api/ai/writing/relationship-profile` 每次推进一批，仍接受 `novelId`、`afterChapterId`、`sampleChapters`。

响应新增 `complete`、`processedChapters`、`totalChapters`、`targetChapterId`。`complete=false` 时，调用方应使用首次回传的 `targetChapterId` 继续请求，直到 `complete=true`，以避免初始化期间新增章节使目标不断移动。中间响应的正文只用于进度，不是已生效的正式档案。

每次实际模型响应单独记录用量和上游成本，包括空回复、拒答与被截断的回复。已返回结果被拒绝时不会推进检查点。HTTP 请求超时本身无法证明上游未执行；这种情况下保留已有检查点。

## 上线与验证

先部署数据库迁移 `063_story_memory_builds.sql`，再使用新 API 和管理端。迁移只新增检查点表，不批量改写已有画像或小说正文。

隔离 PGlite 测试覆盖两种档案的全量初始化、增量输入、超长章末、来源修改、历史起点、插入/删除/重排、失败续跑、截断计费、并发租约及超过三十章的历史；面板测试覆盖自动推进、固定目标、中间结果隔离及失败重试。测试模型为桩，不消耗真实模型额度。

来源标记和档案条目保留由提取提示词约束，模型语义准确性仍需作者核对。逐条结构化事实库与来源语义验证尚未实现。

## 提取失败诊断与档案输入

迁移 `064_story_memory_diagnostics.sql` 新增最近提取诊断记录。空回复、拒答、`finish_reason=length` 截断分别提示，记录模型、预算、输出/推理 Token、来源章节及时间，不保存上游密钥或完整原始响应。管理端在档案旁显示最近结果；拒答和普通空回复不会被一律解释成预算不足。此前截图那次失败没有记录结束原因，无法凭历史提示回溯确定根因。

情节与关系档案送入写作提示词时保留完整内容，不再按 8000/5000 字符静默裁剪。实际模型上下文容量仍由上游限制；材料预览显示字符量，不能把字符数当作 Token 数。

## 章节目标、人物与历史材料

创作面板支持本章目标、出场人物、视角、节奏、必须保留的事实、禁止事件和多章分别指定目标。切换小说时按小说保留输入草稿；只把本批章数内的目标提交给后端。

`POST /api/ai/writing/materials` 是管理员只读预览，不调用模型。与续写任务共用服务端材料构建器：从所选起点取得近期三章尾部、有效的完整档案，并按人物姓名、目标、事实和情节词检索历史已发布正文。字面检索最多返回八个匹配片段，每段最多约1600字符，附章节、位置、匹配词及正文指纹；不是全书原文注入或语义搜索。无命中时明确告知，作者可补充具体人物或事实。

预览展示大纲、近期正文、档案、作者要求、内容尺度及历史片段。多章生成会在基础材料上追加分章目标和本批草稿。返回的材料 revision 在提交续写时重新计算；预览后原文、档案或要求改变会返回409，需重新预览。任务保存历史材料快照，重试使用冻结材料；客户端无法注入自定义正文快照。

## 草稿质量检查

迁移 `065_writing_reviews.sql` 新增检查报告表。管理员在已生成内容的草稿审阅区点击「检查草稿」后发起一次独立模型调用，分类检查一致性、伏笔和关系发展。不会自动改写、发布或否决正文；伏笔提醒始终为参考，不要求本章必须回收。

`POST /api/ai/writing/drafts/:id/review` 要求草稿正文 revision。使用同书、续写起点之前的来源；不读取别书或起点之后的内容。报告中的草稿引句及证据引句必须能逐字匹配输入来源，否则整个报告不生效。逐字匹配只验证引用真实存在，不代表模型推论一定正确。近期来源、历史片段和档案仍是有限材料，空问题列表不代表全面验证。

同一草稿与来源版本复用检查结果，不重复计费；数据库租约避免重复并发检查。模型响应的真实用量独立记入 `writing_review`，解析失败、拒答或截断也记账。参数页提供「质量检查 Token」（默认8000）供截断后调整。`GET /api/ai/writing/drafts/:id/review` 返回最近报告；草稿或已引用正文/档案变化后标记过期，检查过程中变化也会拒绝结果。检查是手动触发，报告不承担自动发布闸门。

上线需先应用063、064、065、066迁移，再部署配套API与管理端。上述自动化验证与页面演示均使用隔离库、模型桩或模拟材料，未调用真实模型进行小说质量评测。

## 故事图谱

管理员可从创作工作台的「故事图谱」入口，或小说管理行内「更多操作 → 故事图谱」打开 `/admin/ai?sub=graph&novel=<小说ID>`；可选 `afterChapterId` 保留续写起点，未指定时使用最新正式章节。返回创作工作台时保留小说与起点。图谱不作为独立的顶层导航或常驻子页签；GET、POST `/api/ai/writing/story-graph/:novelId` 均要求管理员权限。

图谱只整理当前起点可用的关系画像与情节状态。人工校正仍须绑定有效的自动档案基底与来源指纹，满足条件时优先采用人工内容，否则按现有档案规则回退到可用自动内容；两类档案均不可用时禁止生成。风格画像、未发布草稿与完整章节正文不作为图谱模型输入。人物、关系与关联情节附档案依据；关系可有方向，区分已确认事实、人物认知、未解线索、可选方向和分析推断，不将推断默认为事实。

打开页面和「刷新状态」只读取已保存结果，不调用模型。管理员显式点击「生成故事图谱」或「更新图谱」才发起模型调用，以 `story_graph` 计入用量；收到的拒答、截断或校验失败响应也记录实际用量，但不替换已保存结果。同一小说与来源 revision 的有效缓存直接复用；重复生成请求仅在同一 API 进程内合并，没有跨进程的数据库生成租约。

图谱使用独立的 `storyGraphMaxTokens`（默认 16,000，范围 1,000–1,000,000）与 `storyGraphReasoningMode`，在「参数调优 → AI 创作」调整。默认关闭 DeepSeek 兼容模型的思考，避免思考耗尽预算后未输出完整 JSON；其他模型在「关闭思考」选项下不发送 DeepSeek 专属参数，跟随供应商。可显式选择跟随供应商，低/高强度思考仅适用于 DeepSeek 兼容模型。修改图谱设置不影响续写或关系/情节档案设置。输出预算仍受供应商和模型限制；截断返回 HTTP 422 与调整提示，记录实际用量但不保存半成品，不自动重发生成请求。生成仍是同步请求，单次模型等待上限为 120 秒。

缓存 revision 绑定起点、当前有效档案内容及其来源类型、可用状态、覆盖章数和截至起点的章节列表。有效内容、范围或章节变化后重新校验，不向当前页面返回过期图谱；无有效档案时返回不可用状态。生成结束再次比较 revision，变化时返回409。`novel_story_graphs` 每本小说只保存一份结果，切换起点后生成会覆盖此前结果，不保存历史快照。首版以人物关系为主，可展开角色状态、冲突、伏笔、物品与地点，不提供完整情节事件视图。

每个人物、关系与情节的依据必须逐字存在于对应的有效档案中。来源章节链接还须同时满足：摘录包含原样 `[章节ID:实际ID]` 标记，ID 属于本书且不超出该档案的覆盖范围；没有标记时不补造链接。该校验只能证明档案摘录及章节标记存在，不证明摘要、关系解释或档案本身与正文语义一致，仍需通过章节链接人工核对。首版容量上限为60个人物、120条关系、80条关联情节。

工作区使用 SVG：可拖动人物、平移画布、按钮缩放和重置，点击人物、连线或关联情节查看详情；支持键盘 Enter/空格选择及下方人物列表。搜索按姓名和别名筛选人物列表，周边筛选需先选择人物。画布通过容器尺寸自动适配可见人物、关系标签与关联情节，窄画布采用紧凑布局；≤800px 时详情移到画布下方。推断与可选方向关系使用虚线，详情明确标明认知与线索类别。页面复用既有 `Button`、`Input`、`Checkbox` 与 `--sh-*` / `--border` 语义颜色，沿用暖色明暗主题，不新增全局设计令牌；本次扩展不改写 `DESIGN.md` 或 `.impeccable/design.json`。

上线须在既有创作档案迁移基础上应用 `067_story_graphs.sql`，再部署配套 API 与管理端；该迁移仅新增派生图谱缓存表。自动化验证使用隔离数据库和模拟模型，页面截图使用示例材料，尚未验证真实模型的输出质量与实际调用表现。

## 档案分析等待与超时

关系画像与情节状态共用「参数调优 → AI 创作 → 档案分析超时（秒）」，默认300秒，允许30–600秒；旧设置缺少该字段时自动使用默认值，无需新增数据库迁移。该值控制每次模型请求的等待上限，不是整本小说后台任务的总时限；已经发出的请求不会因参数修改而追溯改变计时。

两类档案关闭本地请求超时与上游 HTTP 408/504 的自动重试，超时后任务失败并保留已经完成的章节检查点，由管理员核对中转请求记录、调整配置后手动继续。其他调用保留既有重试策略，档案对其他可重试错误的处理和内容截断恢复逻辑不变。分析期间定期续期数据库锁，继续支持暂停和取消，避免较长等待或其他网络重试使锁自然到期后产生重复分析。

超时诊断保存模型、输出预算、等待上限、实际耗时、输入字符量和本批章节ID。未收到完整响应时，输入与输出 Token 记为未知，不伪造零用量或判定未计费；上游是否继续生成或计费须核对中转站记录。页面将请求超时与空回复、截断、拒答分开，响应正文读取超时也不会作为空回复处理。更长的本站等待时间不能保证消除中转站或模型自身的超时。

## 指定章节或范围重新分析

关系画像和情节状态各自提供「重新分析」入口，可选择单章、连续章节范围或全部已分析章节，并可同时重建两类档案。默认重建至该类档案原来的分析终点，也可只建立截至所选结束章节的累计档案；后者完成后，更晚的续写起点会看到档案尚待更新。

这不是独立片段分析：所选范围表示需要重新核对的部分，正式产物仍是从第一章开始累计的档案。实际执行从最近有效且严格早于所选起点的快照继续；没有可复用快照时从第一章重建。历史版本不会凭空补齐，新快照在后续完整批次结束后逐渐积累。每类最多保留16份批次快照和8份旧正式档案；弹窗提供旧正式档案的只读查看，不自动恢复版本。

管理员先调用 `POST /api/ai/writing/memory/:novelId/rebuild/preview` 核对实际起止、依赖范围、快照和人工校正影响。预览不调用模型、不写档案。确认后调用 `POST /api/ai/writing/memory/:novelId/rebuild`，携带 `expectedRevision` 与 `operationId`；提交时重新检查正文、档案、快照和人工校正版本，变化返回409并要求重新预览。使用同一操作ID重试可取回原任务回执，避免丢失响应后重复提交。

确认事务同时保留旧档案、标记重建状态、清除原构建的受影响结果、种入有效前置快照并创建后台任务。存在运行任务或有效租约时拒绝重建，须先暂停并等待请求退出；两类同时选择时全部成功或全部不变。被明确要求重算的旧结果及其受影响快照不再成为有效续写材料或未来重建的种子，但旧版本仍可只读查看。新执行器完成来源核对后才替换正式档案；失败、暂停或服务重启后，旧正文与备份保留，可通过「继续更新」恢复重建目标。

人工校正不删除。重建会写入新的自动档案修订标识，即使生成文字与旧版相同，旧人工校正仍需复核并重新保存。重建开始时故事图谱缓存失效，需要依据后续有效档案重新生成。已生成草稿、已发布章节与既有用量账本不会被重建操作改写。

`GET /api/ai/writing/memory/:kind/:novelId/history` 仅向管理员提供该书该类最多8份旧正式档案。三个接口均要求管理员权限并禁止缓存。上线需先应用 `068_story_memory_rebuilds.sql`，再部署配套API与管理端；迁移只新增快照和重建状态表，不自动发起任何分析。测试与浏览器验证使用隔离数据、模拟模型及演示材料，未对线上书籍执行重建。
