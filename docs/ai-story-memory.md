# 创作记忆：完整初始化与增量更新

情节状态、关系画像共用 `story-memory.ts` 的提取流程。风格画像继续使用原来的风格取样策略。

## 管理端使用

在创作工作台选择小说及续写起点，点击「更新情节档案」或「更新关系档案」。首次从第一章处理到所选起点；未指定起点时使用发起请求时的最新章节。界面自动继续下一批，并显示已覆盖章数。

「每批最多」控制单次处理的章节上限，不限制总覆盖范围。正文按顺序送入，正常批次控制在约 24000 字符内，超长章节连续分段读取，包括章末。每段均带章节 ID，提示词要求重要记录引用来源，并区分事实、人物认知、线索与计划。

后续更新先校验此前覆盖的全部正文，再用旧档案和新增章节增量更新。不因本批未涉及而删除长期线索，已解决事项保留解决记录与来源。已经覆盖且来源相同的档案直接复用，不重复付费调用。

关闭页面、网络失败或模型失败后，再次点击可从已完成章节的检查点继续。尚未完整处理完的超长章节会重新处理。检查点与续写使用的正式档案分开；只有覆盖目标的全部章节后才替换正式档案。

## 来源校验与正文边界

- 档案来源记录覆盖起点、实际章数、全量正文指纹及提示词版本。
- 已覆盖正文的内容、标题、顺序变化，或历史章节插入/删除，会导致指纹失效；旧档案可以查看，但不再注入续写。再次更新会从可验证的基底重建；没有有效基底时从第一章开始。
- 新增已发布章节使档案标记为 `stale`，更新后恢复可用。正文发布不会自动发起付费提取；由管理员点击更新。
- 向更早的起点提取时，不继承起点之后的档案。提取期间正文变化会阻止本次结果发布。
- 只读取 `chapters`，未发布草稿、备选版本和大纲不会进入故事记忆。
- 旧的近期取样画像仍保留展示，标记为 `legacy_unknown`，完成历史初始化后才恢复使用。
- 同书同类档案通过数据库租约防止同时提取；进程崩溃后的租约最长十分钟自动过期。

## API 协议

`POST /api/ai/writing/plot-state` 和 `POST /api/ai/writing/relationship-profile` 每次推进一批，仍接受 `novelId`、`afterChapterId`、`sampleChapters`。

响应新增 `complete`、`processedChapters`、`totalChapters`、`targetChapterId`。`complete=false` 时，调用方应使用首次回传的 `targetChapterId` 继续请求，直到 `complete=true`，以避免初始化期间新增章节使目标不断移动。中间响应的正文只用于进度，不是已生效的正式档案。

每次实际模型响应单独记录用量和上游成本，包括空回复、拒答与被截断的回复。已返回结果被拒绝时不会推进检查点。HTTP 请求超时本身无法证明上游未执行；这种情况下保留已有检查点。

## 上线与验证

先部署数据库迁移 `063_story_memory_builds.sql`，再使用新 API 和管理端。迁移只新增检查点表，不批量改写已有画像或小说正文。

隔离 PGlite 测试覆盖两种档案的全量初始化、增量输入、超长章末、来源修改、历史起点、插入/删除/重排、失败续跑、截断计费、并发租约及超过三十章的历史；面板测试覆盖自动推进、固定目标、中间结果隔离及失败重试。测试模型为桩，不消耗真实模型额度。

来源标记和档案条目保留由提取提示词约束，模型语义准确性仍需作者核对。逐条结构化事实库与来源语义验证尚未实现。

## 提取失败诊断与档案输入

迁移 `064_story_memory_diagnostics.sql` 新增最近提取诊断记录。空回复、拒答、`finish_reason=length` 截断分别提示，记录模型、预算、输出/推理 Token、来源章节及时间，不保存上游密钥或完整原始响应。管理端在档案旁显示最近结果；拒答和普通空回复不会被一律解释成预算不足。此前截图那次失败没有记录结束原因，无法凭历史提示回溯确定根因。

情节与关系档案送入写作提示词时保留完整内容，不再按 8000/5000 字符静默裁剪。实际模型上下文容量仍由上游限制；材料预览显示字符量，不能把字符数当作 Token 数。

## 章节目标、人物与历史材料

创作面板支持本章目标、出场人物、视角、节奏、必须保留的事实、禁止事件和多章分别指定目标。切换小说时按小说保留输入草稿；只把本批章数内的目标提交给后端。

`POST /api/ai/writing/materials` 是管理员只读预览，不调用模型。与续写任务共用服务端材料构建器：从所选起点取得近期三章尾部、有效的完整档案，并按人物姓名、目标、事实和情节词检索历史已发布正文。字面检索最多返回八个匹配片段，每段最多约1600字符，附章节、位置、匹配词及正文指纹；不是全书原文注入或语义搜索。无命中时明确告知，作者可补充具体人物或事实。

预览展示大纲、近期正文、档案、作者要求、内容尺度及历史片段。多章生成会在基础材料上追加分章目标和本批草稿。返回的材料 revision 在提交续写时重新计算；预览后原文、档案或要求改变会返回409，需重新预览。任务保存历史材料快照，重试使用冻结材料；客户端无法注入自定义正文快照。

## 草稿质量检查

迁移 `065_writing_reviews.sql` 新增检查报告表。管理员在已生成内容的草稿审阅区点击「检查草稿」后发起一次独立模型调用，分类检查一致性、伏笔和关系发展。不会自动改写、发布或否决正文；伏笔提醒始终为参考，不要求本章必须回收。

`POST /api/ai/writing/drafts/:id/review` 要求草稿正文 revision。使用同书、续写起点之前的来源；不读取别书或起点之后的内容。报告中的草稿引句及证据引句必须能逐字匹配输入来源，否则整个报告不生效。逐字匹配只验证引用真实存在，不代表模型推论一定正确。近期来源、历史片段和档案仍是有限材料，空问题列表不代表全面验证。

同一草稿与来源版本复用检查结果，不重复计费；数据库租约避免重复并发检查。模型响应的真实用量独立记入 `writing_review`，解析失败、拒答或截断也记账。参数页提供「质量检查 Token」（默认8000）供截断后调整。`GET /api/ai/writing/drafts/:id/review` 返回最近报告；草稿或已引用正文/档案变化后标记过期，检查过程中变化也会拒绝结果。检查是手动触发，报告不承担自动发布闸门。

上线需先应用063、064、065迁移，再部署配套API与管理端。上述自动化验证与页面演示均使用隔离库、模型桩或模拟材料，未调用真实模型进行小说质量评测。
