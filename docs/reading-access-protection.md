# 阅读访问防护

默认保留公开书籍的游客阅读。服务端对成功通过作品可见范围和分级检查的正文请求记录访问量；对分钟限流拒绝只记拒绝量，不查询或保留目标资源。管理员正常阅读免统计与正文限流。

本次提供统计、分层限流和客户端等待重试；未增加阅读前验证码、登录墙、自动封禁或单独下载授权通道，未修改 Cloudflare 设置。

## 管理后台

在 Web 后台打开「安全与风控 → 阅读防护」。管理员可按游客、登录账号和可信 IP 查看近 6、24 或 48 个小时的请求概览、小时趋势、异常窗口和当前阈值。生效阈值跟随所选对象，在请求概览下方展示。小时趋势的异常和拦截仅对应 1 小时额度，10 分钟和每日额度的命中在「异常窗口」中查询。页面使用北京时间，小时汇总包括当前尚未结束的小时，每日窗口从北京时间 08:00 开始。

超级管理员可打开「防护配置」，切换对象调整分钟请求额度和 10 分钟、小时、每日的不同章节额度，也可调整全局模式。切换对象会保留未保存的编辑，保存时一起应用。选择默认模式或清空某个额度可撤销该项后台覆盖。各字段按有效环境变量、后台配置、内置默认值的顺序取值。由环境变量控制的字段在页面上只读。

后台配置写入已有的 `app_settings`，新的正文请求即时读取，无需重启 API。保存与操作审计在同一事务完成；其他管理员已保存更新时，旧表单提交返回冲突，需要重新读取。切换增强拦截或降低阈值会依据当前窗口内已有的计数判断。提高阈值后，先前因封顶而略过的条目不会追溯补记。

## 默认启用方式

`CHAPTER_PROTECTION_MODE=observe` 为默认值：新增十分钟、小时、天窗口仅记录和标记异常，不拒绝阅读。原有每账号 120 次／分钟、每可信 IP 240 次／分钟继续生效。游客另记匿名 IP 分钟桶，观察模式默认上限与 IP 聚合相同，故不额外收紧访问。

在后台选择「增强拦截」或显式设置 `CHAPTER_PROTECTION_MODE=enforce` 后，长窗口超限返回 `429 content_rate_limited`。在账号分钟额度保持 120 的情况下，游客默认收至 60 次，可信 IP 聚合默认维持 240。建议先部署观察一至两天并核对离线下载情况，再决定是否启用。切回观察模式即停止长窗口拦截，保留统计和分钟限制。

| 身份 | 十分钟不同章节 | 每小时不同章节 | 每天不同章节 | 不同书籍阈值（同三个窗口） |
| --- | ---: | ---: | ---: | --- |
| 游客，按可信 IP | 60 | 300 | 1200 | 6 / 20 / 80 |
| 已验证账号，跨会话和 IP | 180 | 1200 | 6000 | 10 / 30 / 120 |
| 同一可信 IP 下的所有访问 | 720 | 4800 | 24000 | 40 / 120 / 480 |

这些是初始观察阈值，尚待生产数据验证。不同章节阈值也可通过 `CHAPTER_{GUEST|USER|IP}_UNIQUE_{10_MINUTES|HOUR|DAY}` 设置，正整数且不超过 100000。不同书籍阈值固定。分钟阈值可由 `CHAPTER_READ_LIMIT_PER_MINUTE`、`CHAPTER_GUEST_READ_LIMIT_PER_MINUTE`、`CHAPTER_IP_READ_LIMIT_PER_MINUTE` 覆盖，登录仍受 IP 聚合限制。未单独覆盖时，可信 IP 聚合和观察模式的游客分钟额度是账号额度的两倍。增强拦截模式下，默认游客分钟额度取 60 和账号额度两倍中的较低值。后台可填额度为 1–100000 的整数。更改环境配置后按原部署方式重启 API。

重复读取同章增加请求次数，但不重复消耗该窗口不同章节额度；相邻预取正常计入不同章节。窗口按 Unix 时间对齐（天窗口为 UTC 零点），为固定窗口，边界仍可能出现突发。超限后以所有命中窗口中最晚恢复时间作为等待时间。没有可信 IP 时不采信伪造头部，也不将全部未知游客并入一个共享桶；有效账号仍计数。

## 查看统计

管理员可用既有 Cookie 或 Bearer 会话请求：

`GET /api/admin/reading-access?hours=24`

`hours` 为 1–48 的整数。返回当前模式和阈值、`byHour` 每小时各身份类型的请求、不同章节／书籍读取、分钟拒绝、小时额度异常与拦截数，以及 `signals` 三类长窗口的异常汇总。接口仅管理员可读，响应禁用缓存。超级管理员通过 `GET /api/admin/site-settings/reading-access` 读取配置，用 `PUT` 提交当前 `revision` 与 `overrides`。

同一次请求会进入账号／游客和 IP 两类桶，各行不能相加当作站点总量。不同章节／书籍计数是各主体去重后的合计，不是全站唯一数量。达到阈值加一后停止继续保留新资源摘要；在途并发可略超此值，因此返回 `countsAreCapped: true`。这些数值用于识别异常与调整阈值，不应当作精确下载排行榜。`flagged` 是超量请求次数，不是人数。

统计表只保存带稳定会话盐的 HMAC 身份与资源摘要，无原始 IP、账号 ID、书名、章节 ID 或正文。窗口结束后保留 48 小时；有阅读流量或管理员查询时，每进程每分钟至多进行一次有上限的清理，空闲期间可暂留过期行，查询不返回过期行。统计属于运行数据，新增阅读请求不使备份恢复影响确认过期。

## Web 与 iOS

响应在 `Retry-After` 头与 JSON `retryAfter` 字段同时给出秒数，CORS 明确暴露此响应头。Web 的当前章与相邻预取共享账号冷却；iOS 的正文读取和离线下载使用同一取消安全的冷却。只对明确的 `content_rate_limited` 重试，最多重试两次，单次冷却最多 65 秒、累计等待最多 125 秒；较长的小时／天限制直接保留错误，避免页面或下载队列长时间挂起。等待前后检查账号；iOS 同时检查缓存归属并响应取消。其他接口及写操作不会因此自动重试。

iOS 普通书籍离线下载继续受同一服务端额度控制，应用身份或 User-Agent 不提供免限流。此阶段没有伪装成下载即可获得更高配额的旁路。原生源码与测试已补齐，但需在 macOS/Xcode 编译验收后再交付 IPA。

## 部署边界

迁移为 `088_reading_access_protection.sql`，API 启动迁移器按现有方式应用。编号避开并行开发使用的 087。API/Web 复用当前未发布候选版本，具体来源和本轮验证见发布记录；旧客户端仍可读，但不能自动等待新的限流响应。

生产必须核对可信代理、Cloudflare Tunnel 或防火墙的源站入口限制。此实现不自动配置边缘 WAF，不在 JSON API 上增加整页挑战，不承诺阻止分布式低速抓取。书籍可见范围和既有受限内容验证继续先于正文统计；已经交付的内容无法远程收回。
