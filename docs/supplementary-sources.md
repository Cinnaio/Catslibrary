# 蓝奏附加更新源

入口为后台「小说管理 → 附加更新源」。一个共享目录可以绑定多本已有作品，一本作品也可以绑定多个来源或来源别名。单书的文件处理方式在「更新与来源 → 附加文件」设置。

## 使用流程

1. 添加蓝奏文件夹链接、来源名称和可选提取码。默认关闭定时检查；可手动开启，间隔为 1–168 小时，默认 6 小时。
2. 点击「检查目录」。扫描根目录及两层子目录，读取 TXT / EPUB 文件清单，排除推广链接；文件名中的更新进度只作线索。
3. 在「目录文件与绑定」中搜索书名或作者。列表按完整书名与作者归并，一本书只显示一行；展开「已发现版本」查看各日期文件，可选择任意已读取版本绑定站内作品。最高进度仅来自已读取文件名，不保证是最终版本。保存来源书名与作者作为别名，不修改作品信息。
4. 在「已绑定书籍」选择候选版本，点击「下载并预览」。需要浏览器验证或直连失败时，使用「原文件」在浏览器下载，再点击「上传对应文件」。上传文件名必须对应所选版本，允许浏览器添加 ` (1)` 等重名后缀。
5. 在既有导入预览中核对章节。默认只勾选新增章节；已有正文变化需手动选择，冲突章节不允许应用。确认后写入，并可通过既有导入结果或导入历史撤回仍可安全恢复的变更。

新版缺少本地章节时不执行删除。附加源预览固定到绑定作品，服务端禁止切换目标或修改书名、作者、简介、封面、分类、原书源及连载状态。导入的章节记录对应文件地址和章节编号，导入历史记录文件名称和地址。

融合修正过序号后，附加源保留已匹配章节的本地序号，确认的尾部新章按本地末尾继续追加，预览展示实际计划写入的序号。文件中段的新条目、以及没有可靠本地对应关系的整批条目标记为冲突，不默认追加；需先核对边界和映射。重新选择目标或人工修正边界后也保留此规则，作品信息始终不默认勾选。旧预览若会改回融合后的序号，提交时拒绝该条并要求重新生成预览。

来源文件重复收录同章时复用解析规则的确定重复合并及版本候选；不同正文版本默认不选，只能显式选择其中一个，后端提交时再次校验。不会为消除缺号而编造正文，也不会自动以文件后出现的版本覆盖已有正文。

「需确认」条目的复选框暂时禁用，条目下方提供「核对章节对应关系」：可以确认对应已有章节，或确认是新章并指定插入位置。保存只更新预览；对应已有章节时先比较正文再勾选，确认新章时展示预计位置和必要的序号顺延，最终仍需点击「确认导入」。也可以前往「核对章节边界」修正切分。具体操作与撤回保护见[导入冲突处理](import-conflict-resolution.md)。

## 定时检查与月份切换

多个书籍绑定共用一次目录扫描。目录定时检查开启后，后台按书处理最近一次完整清单。管理界面显示目录检查时间、结果和下次安排，并单独显示文件处理结果。目录与文件任务各自使用数据库租约，多个实例可安全分工。

- **手动确认**是新旧绑定的默认方式。通过候选列表打开文件，再确认章节变更。
- **自动生成预览**下载并比较新文件，发现章节变更时生成可打开的导入预览。之前生成的待确认预览在切换到自动追加后继续保留给管理员确认。
- **自动追加尾章**要求正文能对上本地最后一章，文件中后续正文的章节号连续。已有正文改动、重号版本、中间插章、跳号或解析证据不足时进入待确认。管理员可在导入历史核对来源、实际追加章数并撤回；重复出现的同一版本和内容一致的文件副本复用处理结果。

每本书只有一个自动入库来源。保存「自动追加尾章」会暂停该书的网页自动追更，切回手动或预览后可在网页页签重新开启网页追更。目录未读全时两种自动方式等待下次完整扫描，已读取的候选仍可手动预览。文件需要浏览器验证时，从候选版本打开原文件，下载后上传接续。

试跑时先给少量有稳定日更文件的书开「自动生成预览」，核对连续几个版本的末章对齐、正文和新增章数，再逐书切换到自动追加。日更优享版可使用 `?latest=2` 覆盖最近两个日期目录。

目录换月时，编辑来源链接，书籍绑定保留，旧目录清单清空；重新检查后按保存的书名、作者别名寻找候选。若发布者改了书名，可以从新文件再次绑定，保存新的来源别名。解除绑定不删除书籍或章节。

## 日更型大分享：限定扫描范围

蓝奏优享版的日更汇总分享通常按「汇总 / 月 / 日」分层，单个日包一百多个文件，整分享两万多个文件。直接填根链接会撞上 5,000 文件上限并报「目录文件过多」，只能手动改目录。

- `https://www.ilanzou.com/s/<shareId>?latest=N`：只扫最新的 N 个日期目录（1–5，按目录名自然倒序取），每次检查自动跟到当天/昨天的新包，适合挂成定时源。
- `https://www.ilanzou.com/s/<shareId>?folder=<folderId>`：固定扫某一个子目录；folderId 取自目录接口返回的 `folderId`/`sortId`，适合回溯某个具体日期包。
- 不带参数时保持全量扫描语义。范围参数随链接保存，文件记录地址形如 `…?latest=1&fileId=…`。

旧版本保留：本次未再扫描到的目录会被标为「旧清单」，每本书只留最新两个旧版本，其余清理，避免日更源几周后撞上累计 5,000 文件上限。

实测（2026-11-22，`https://www.ilanzou.com/s/RV1nly5l`，全分享 27,504 个文件）：根链接全量扫描 14.7 秒后报「目录文件过多」；改用 `?latest=2` 后 1.0 秒读回 235 个文件、用时稳定，`?folder=434571208` 读回 106 个文件。两种范围都能正常落库并参与绑定。

## 检查结果的边界

- **检查成功**：所有发现的目录和分页均完整读取。
- **部分目录未完整读取**：目录后续分页失败时，保留此前已读取的合法文件，并逐文件标注「目录后续分页未完成」；未读部分的旧记录继续保留并标注「旧清单」。这些文件仍可绑定及生成正文预览，但不能据此判断目录已检查完整或没有更新。根目录从第一页就读取失败时仍按检查失败处理。
- **检查失败**：根目录读取失败、总体超时或超过索引限制。保留之前的清单并显示失败，不能当作“没有更新”。

候选排序按目录名称的自然顺序及文件名更新进度排列，不承诺它就是最终版本；必须通过正文预览判断。每次最多 40 个目录、每目录 20 页、5,000 个文件；总体检查有时限。单文件最大 25 MB。TXT 当前要求有效 UTF-8，避免以乱码生成章节。

「目录文件与绑定」以书籍分页，每页 30 本；同书的历史版本不被文件分页截断。「查看目录读取情况」显示已索引文件数、旧记录数及完整性。绑定后的版本选择也保留全部已发现版本，不再截断到最近 10 个。接口的 `grouped=1` 返回书籍聚合结果，未指定时保留原文件列表接口；新 Web 发现旧 API 响应时提示升级，避免把不兼容数据渲染成空目录。

网络请求复用现有代理及逐跳 SSRF 检查，限制分享域名和下载域名、响应字节数及超时，不执行远端脚本。提取码不回显到前端，临时 Cookie 和下载直链不落库。自动下载不解决浏览器验证，遇到验证页明确转为手动接续。

## 部署与验证

API、Web 与迁移 `059_supplementary_sources.sql`、`060_supplementary_source_partial_status.sql` 需一起更新；现有启动迁移流程自动创建来源、绑定表和导入来源字段。060 单独扩充状态约束，兼容已经执行早期 059 的数据库；不能依靠修改已记账的 059 升级，否则保存部分目录结果时会被旧约束拒绝，并显示「目录检查失败」。

接口位于 `/api/supplementary-sources`，仅管理员可使用。手动下载预览与手动上传都进入 `/api/book-import/preview`，附带 `supplementaryBindingId` 与 `fileKey`。自动任务与手动导入共用解析、预览快照、章节应用与撤回流程。自动追加在应用事务锁定作品后重新核对来源、任务状态、本地末章和追加计划。上线先应用迁移 `100_supplementary_automatic_updates.sql` 并更新 API，再更新管理 Web。

已验证真实样本：《圈宠》254 / 255 两版 TXT 可由现有解析器识别，比较结果为 254 章未变化、1 章新增。2026-10-17 的服务端实测从给定月份目录完整读取了 `1016` 下 38 个 TXT；另外 14 个日期目录第二页返回要求刷新，因此本次索引是部分结果。浏览器下载成功；服务端直接下载仍遇到验证页，手动上传接续为可用路径，不能把浏览器结果推定为服务端自动下载已通过。

2026-10-17 的历史版本改进实测：目录已新增 `1017`，保留部分分页结果后读取 782 个合法文件，归并为 275 本书；其中 697 个文件所在目录未读全。《圈宠》可见 8 个已发现版本。第二页的上游「请刷新」限制仍存在，未将这些部分清单描述成完整扫描结果。此数字为当次样本快照，后续随目录变化。

自动验证覆盖目录分页失败、部分快照保留、别名绑定、权限、文件校验、重复预览、元数据保护、来源记录、撤回和定时检查不写章节。`scripts/check-supplementary-sources.mjs` 使用隔离接口样本验证桌面、手机及深色模式的添加、绑定、失败接续、预览和确认流程，不代表线上部署验收。
