## 供应商契约

重放第五阶段实际截断摘要的同一冻结输入：原提示／`json_object`／严格 `json_schema`，分别组合供应商默认思考和关闭思考，各请求一次；另加两个相反提示的 schema 约束探针。8 次请求，输入 22,684、输出 6,902 Token。六个重放通过本地格式校验；两个探针均 HTTP 200，却返回 `{"unexpected":123}`，没有遵守要求的六字段 schema。

因此不能把该配置端点视为支持严格 Structured Outputs，也不能推广为所有 DeepSeek 服务都不支持。客户端增加显式 `responseFormat` 透传，但**产品摘要默认契约与思考模式不变**，不根据模型别名自动切换或静默降级。继续拒绝截断、空白、拒答、字段类型错误及额外字段，原文保留，重试须显式发起。关闭思考的三个重放回传 reasoning_tokens=0，不代表语义更可靠。

首次契约实验保留了冻结输入和原始响应散列，未捕获运行时源码散列；后续脚本已补入，旧报告不改写。OpenAI 文档区分 JSON 合法性和 schema 遵循；DeepSeek JSON Output 文档要求 JSON 提示及适当输出预算，并说明可能出现全空白输出。官方文档不能代替当前中转端点实测。

- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)
- [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/)
- [DeepSeek Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)

## 代码改进

- 按 1–8 个消息号直接回查原话，校验账号、作品和会话；摘要引用中的早期限制与最近修正附带原始消息，超长片段明确标记截断，不把缺失原文猜成不存在。
- `propose_memory` 只接受本轮作者的完整连续原句，拒绝扩写、截去否定或删去句内条件；仍为待确认提议，作者可在面板编辑。这是字面边界检查，不宣称解决全部意图和语义判断。
- 摘要明确区分“未决定／未采纳”和“已否定”，最新决定同时更新 goal；收紧回答指导和取材范围说明，保留原始输出，不使用正则删改回复掩盖问题。
- 迁移 `081_ai_agent_summary_versions.sql` 将成功摘要及版本快照在同一 SQL 语句中原子保存。失败输出正文及有限诊断单独留档，不注入有效上下文、不通过普通事件接口返回，不记录请求头或思考文本。留档本身失败则标记 `failureArchived=false`，原错误仍保留。
- 迁移仅回填当时最新检查点并标记 `backfilled`，不伪造不存在的早期版本；删除会话级联清理审计内容。
- Q13–Q15 将先前真实的假设误归因、记忆扩写、未查询资源断言固化为合成回归，明确标注为失败改编。

## 复现与交付

以下入口默认只展示计划，不连接开发库或调用模型：

```powershell
npm run eval:agent:contract
npm run eval:agent:review
```

显式实验需要含真实截断输入的旧报告；报告文件和审阅目录必须是新路径：

```powershell
npm run eval:agent:contract -- --live --source .tmp/agent-evaluation/long-context-followup-2026-11-09.json --output .tmp/agent-evaluation/new-contract.json
npm run eval:agent:review -- --read-only --novel-title "作者指定的作品名" --output .tmp/agent-review/new-review
```

沿用 API 1.2.0／Web 1.4.0 未发布候选，完整候选需要迁移 079／080／081。改动继续留在 `codex/agent-quality-usage`，未提交、合并、推送、部署、迁移开发库、运行 GitHub Actions 或构建 iOS。整合前需与另一个 chat 核对迁移编号和文档增补。实际验证结果见 [发布记录](releasing.md)。
