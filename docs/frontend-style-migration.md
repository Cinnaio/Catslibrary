# 前端视觉体系迁移评估：cats-watching → 知舟

评估日期：2026-11-04。状态：已获授权实施；分支与逐模块进度见 [实施记录](frontend-refactor-progress.md)。

本次以本地 `cats-watching` 的 `a74f8b8`、知舟的 `d2dbb3c5` 为源码参考点，不代表线上版本。参考仓库位于相邻的 `../cats-watching`；没有修改其文件。

## 目标与范围

用户希望全盘采用 cats-watching 的前端风格，完整重构知舟前端。建议按 **Web 全站统一视觉体系** 实施，覆盖首页、书架、小说详情、个人中心、身份页面、阅读器、全部后台模块和共享浮层。

视觉基准包括配色、材质、字体层级、圆角、空间节奏、应用导航、组件外观、响应式和动效。知舟的书名、品牌、导航内容、权限、阅读状态及创作工作流仍由知舟业务决定。

本方案默认保留 React/Vite、React Router、现有 API 与业务状态管理；iOS 原生客户端不在本次 Web 迁移范围。明暗与跟随系统三态主题作为知舟已有能力保留；其中浅色直接对齐参考，深色需要适配同一套语义令牌。上述范围与保留约束作为本次实施基准。

| 项目 | 参考值 / 行为 |

| 页面 / 侧栏 / 内容表面 | `#faf9f6` / `#f0eee8` / `#fffefa` |
| 正文 / 次要文字 / 边线 | `#302e2a` / `#736e65` / `#dedbd3` |

| 按钮 | 常规桌面最低 44px，手机 48px；紧凑桌面 36px；主次同尺寸，以颜色区分 |
| 字段 | 桌面常规 42px、紧凑 36px，手机 48px；手机输入文字 16px |
| 排版 | 衬线内容标题 + 无衬线工具文字；页面标题 29px，分区标题 21px，UI 正文 14px |
| 材质 | 内容、表格与编辑区实色；轻磨砂用于导航和临时浮层 |

## 知舟当前结构与主要差异

- `web/src/components/Layout.tsx` 与 `SiteHeader.tsx` 承担公开页面导航；后台另有 `pages/admin/AdminShell.tsx`、`AdminSidebar.tsx`。参考项目在私有路由下使用同一套外壳。
- 前台的暖棕色令牌、后台的陶土色令牌和 shadcn 桥接层并存。后台大量控件采用全圆角胶囊，参考项目采用按角色分层的圆角。
- `styles/global.css` 集中引入大量页面和后台样式。`_admin.css`、`_admin-ui.css`、`styles/admin/` 与基础控件样式需要逐项确认职责，避免新样式继续依赖导入顺序覆盖。
- 后台在 `AdminShell` 的内容区域内部滚动，而参考顶栏监听 `window.scrollY`；收拢逻辑必须绑定真实滚动容器。
- `ThemeContext.tsx` 已提供亮、暗、跟随系统；参考令牌声明 `color-scheme: light`，播放器的深色仅是局部表面，不能当成完整暗色主题。
- 知舟导航包含内容库、抓取、AI、任务与用量、治理、备份、账户和站点设置，复杂度高于参考的六个后台入口。需要保留分组和子导航可达性。
- 知舟是 React Router 客户端应用，参考是 Next.js App Router；知舟共享控件以 Radix/shadcn 为基础，参考的部分复合字段使用 React Aria。直接复制 TSX 会带入路由和表单契约差异。
- 知舟已存在开发专用 `/dev/components` 组件展厅，可直接作为新体系的状态验收入口。

## 样式与组件架构

1. 更新 `DESIGN.md`，让 cats-watching 的视觉体系成为知舟新基准；同步 `GEMINI.md` 中与旧视觉相关的说明，保留开发与提交规范。旧规范中的全胶囊、前后台两套强调色和旧页面外壳约束需要明确替换。
2. 建立全站语义令牌，统一公开页与后台的颜色、字体角色、控件尺寸、圆角、层级和动效。旧 `--admin-*` 与 `--sh-*` 可在迁移期映射到新令牌，完成迁移后清理多余别名。
3. 全局仅保留字体、reset、基础交互、主题和无障碍规则；共享组件与业务页面逐步采用 CSS Modules，并由所属组件导入。
4. 保留现有 Radix 行为与组件 API，通过适配现有控件实现同样外观。视觉迁移不默认引入第二套复合控件库，不批量替换表单数据模型。
5. Tailwind 可在未迁移区域继续使用；已迁移组件明确样式所有者，移除与其冲突的旧规则和工具类。是否最终移除 Tailwind 根据完成后的实际使用量决定。
6. 避免在 `global.css` 末尾追加整站覆盖层；每完成一个组件或页面，就解除其对旧选择器的依赖并清理对应规则。
7. 明暗主题、Radix portal、菜单、对话框和 toast 使用同源令牌，防止后台浮层与页面主题脱节。

## 验收重点

- 布局：检查 1920、1440、960、700、390、320px；移动导航切换另检查 701px，后台过渡期间另检查旧 900px 断点，防止两套响应式规则叠加。正文不横向溢出，长表格与目录有明确滚动区域。
- 真实尺寸：按钮、字段、图标触控区、操作组间距、相邻区块留白和弹窗视口边界均需测量；不能只依赖颜色或视觉近似。
- 状态：初次加载、路由等待、搜索过渡、空内容、无权限、加载失败、保存失败、处理中与成功，均使用一致外观并保留下一步动作。
- 主题与浮层：亮、暗、跟随系统均检查；页面内切换后，菜单、tooltip、对话框、抽屉和反馈仍继承正确主题。
- 可访问性：键盘顺序、焦点可见、抽屉关闭后隐藏入口不可聚焦、Escape 和焦点返回、表单标签与错误关联、减弱动态及高对比回退。
- 业务：公开/登录/管理员边界、内容分级门禁、账号隔离、进度同步、后台任务持续执行、草稿保留、批量范围与破坏性确认均保留。
- 阅读专属：长章节、超长标题、大目录、用户字号与宽度设置、滚动及分页位置恢复；固定导航或控制区不能遮住正文。
- 性能：保持路由懒加载和展厅仅开发可用；页面样式不重新汇入全局大文件，不因外壳标题新增重复取数。

验证遵循 `GEMINI.md`：开发中使用现有 Vite 热更新检查，不主动截图或启动长时间单元/E2E 套件。实施产生代码后进行必要的定向检查；交付时记录 Web 类型检查与生产构建的实际结果。高风险交互如有逻辑变化，补充与变化对应的定向验证。
