# 导入预览中的需确认章节

原问题：对应关系冲突条目标记为「需确认」，复选框禁用，展开只有正文比较，缺少保存人工判断的入口。冲突保护本身仍然保留，通过单独的预览操作解除。

## 操作

1. 在条目下方点击「核对章节对应关系」。旧预览若缺少本地章节列表，先读取当前本地章节并提示重新核对勾选。
2. 选择「对应已有章节」，按标题或序号查找并指定本地章节。保存后显示正文比较，本地序号保留，有变化的正文默认不选。
3. 或选择「这是新增章节」，指定放在哪个已有章节或本轮已确认新增的章节之后，也可放在本书开头。新增候选标注「本轮新增」，可按标题或序号搜索。展示预计新增序号和需要顺延的已有章节。
4. 点击「保存确认并更新预览」。此时没有写入书库；保留其他章节的勾选，当前确认的新章可以勾选并参与最终导入。同章不同版本仍只允许选择一个。
5. 点击「确认导入」才执行新增、更新和必要的序号调整。取消勾选插章时不调整原顺序；其他尾章按实际选择重新计算位置。

可用「撤销人工确认」恢复冲突保护。如果是切分错误，可点击「核对章节边界」进入既有解析检查；重切或重选目标会清除人工对应关系，避免使用已经失效的条目编号。

连续补章可依次确认 A 放在本地第 57 章后、B 放在 A 后、C 放在 B 后，最后一次性导入。显式指定的前后关系优先于文件顺序，同一锚点的并列补章仍按文件顺序排列。移动 A 时后继整段跟随；取消勾选 A 时不导入 A，B、C 收紧到原位置；撤销 A 的确认或改为对应已有章节时，B 接回 A 原来的前驱位置。编辑位置不会提供自身和后继作为候选，接口也拒绝循环与悬空引用。

## 校验与撤回

新增管理员接口 `POST /api/book-import/:runId/resolve-chapter`，接收 `revision`、`chapterId` 及 `action`（`match`、`insert`、`clear`）。匹配使用 `localChapterId`，插入已有章节后使用 `afterChapterId`（`null` 表示本书开头）；插入本轮新增章节后使用 `afterIncomingChapterId`，仅允许引用同一预览中已确认的新增条目。此时请求省略 `afterChapterId`，存储时归一为 `null`，避免旧 API 忽略新字段后误插到书首。本地与导入条目的 ID 分别处理。

只允许预览创建者操作自己的未提交预览；校验版本、保留期限和 AI 复核租约。锁定作品及本地章节，拒绝跨书位置、重复占用已有对应关系。人工确认保存在预览 JSON 中，不新增数据库迁移。

提交时基于锁定的本地快照重新校验对应关系，并按最终勾选计算插入计划。有变化时要求重新生成预览；界面提供「重新读取本地章节」，读取最新预览版本后清除旧确认与勾选。

插章仅在必要时顺延序号，不修改既有章节标题、正文或 ID；有空编号间隙时优先使用。序号调整单独记录为 `reorder-chapter` 审计项。撤回时先检查关联变更是否仍能安全恢复；如新章或关联顺序已被编辑，整体保留本次插章及序号调整并报告冲突，避免只删新章却破坏顺序。

Web 与 API 需一起发布，旧版 API 不提供确认接口，也不理解新的顺序审计项。新 API 兼容没有人工确认字段的旧预览和旧导入记录。

浏览器使用实际组件、实际 Hono 路由和隔离 PGlite 数据库跑通“确认 → 导入 → 撤回”：本地原序号 57、58，补入后为 57、58、59，撤回后恢复原记录。桌面、手机及暗色模式均检查了表单可达性、横向溢出和底部按钮。原书库及线上数据未修改。
