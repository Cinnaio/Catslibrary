## 范围与隔离

经用户明确同意，使用现有文本供应商与开发库保存的 AI 设置，发起 26 次真实模型请求。创作思考设置保持 `inherit`，分析保持 `low`，没有更改开发库配置。API 经真实认证、中间件、业务路由、数据库和模型客户端执行；测试数据库使用独立的持久化 PGlite。开发库只在只读事务中读取 AI 设置，未写入作品、报告、草稿或会话。

普通题材使用已有温室回归样本前三章，另设未来章节和异书标记；这是已知样本，不是未见验收集。真实作品使用此前冻结的 99 个来源、180230 字符及已有分析报告，在隔离库重建归一化正文并重算副本来源修订；来源文本和编号逐项一致。该历史报告已有内容复核问题，本轮验证其作为参考的传递与使用，没有重新生成整书报告或宣布原报告语义正确。

请求通过 Hono `app.request` 进入业务接口，不是浏览器或真实手机操作。iOS 只做源码复核，未编译、打包或真机验证。原始正文、请求、结果、隔离数据库和带身份信息的记录均留在忽略目录 `.tmp`，公共诊断仅保留元数据、散列及非露骨结论。

## 已有证据

- 实际生成分析，保存人工修订，再预览、推荐情节、生成大纲及续写。四条实际模型请求（含质量检查）均包含修订标记，草稿保存报告内容与修订版本；旧档案标记、异书标记和未来章节标记没有进入请求或生成正文。
- Agent 实际调用 `list_novel_analyses`、`read_novel_analysis`，回读第二、三章，并正确回答铜牌由郁禾保管、东棚滤芯故障以及梅涔误认。返回的两个章节引用均对应实际读取的同书章节。随后调用 `generate_draft`，子任务完成、草稿保留为未发布状态，快照固定已读报告 v3。
- 显式空选择实际完成续写，冻结参考为空，模型请求没有报告修订标记。跨书、未来范围、旧修订和正文变化请求分别被 404／409 拦截，未触发模型；旧档案入口返回 410。
- 在供应商调用前注入一次 HTTP 400，任务失败且未产生草稿。通过正式重试接口后实际生成成功；报告进一步修订为 v4 后，再次重试返回 409，明确要求重新选择当前版本。注入故障不是实际供应商故障。
- 真实作品副本完成报告选用及一章非露骨续写；Agent 实际列报告、读报告、回读最后一章，答复区分了报告推断和最后一章原文。此项只核对所问结尾，不代表整书事实全部通过。
- 在第一轮隔离库的独立副本中，故意将草稿改成三个明确矛盾。质量检查返回 200，分别指出铜牌归属、东西棚水泵状态、封筒已打开的错误，三项引句均通过服务端逐字校验，输入中使用当前报告 v4。
- 另外明确要求 Agent 创建新分析：`analyze_novel` 实际调用，分析子任务完成且返回报告链接。协调 Agent 的下一次收尾调用被测试总预算拦截，没有发给供应商，最终答复未完成；不能将这一项父任务视为通过，也不能把预算拦截误记为供应商故障。

第一轮 49 项结构断言通过 48 项；额外离线核对 Agent 工具、证据引用、子任务、草稿快照及标记泄露共 17 项，全部通过。补测 10 项断言通过 7 项，三个失败断言对应两次情况：原草稿检查再次失败，以及预算拦截后的 Agent 收尾未完成。最初脚本的退出码未反映断言失败，现已修正，并补齐子任务、证据检查；第一轮原脚本副本和原失败记录保留，不把新脚本当作已重新完整实跑。

## 未通过与内容局限

1. **原草稿质量检查第一次 504**：草稿审阅服务的 120 秒上游响应读取超时，未获得完整正文或 Token 用量；上游账单仍回传费用。失败没有生成有效检查报告。这不是小说分析生成失败，也不是测试脚本总时限到期；单次记录不足以区分模型、网关或网络原因。
2. **补查原草稿返回 502**：完整返回约 2405 字符 JSON，共九项；其中一项 `draftQuote` 把非连续句子用省略号拼接，触发“引用的草稿片段不存在”。服务端没有放宽证据校验，也没有保存这些条目。此次输入采用当前 v4 报告，与第一次 v3 仅多出版本冲突测试说明，不冒称完全相同请求的重放。内容中还有道具衔接、措辞等低价值提醒，不能据故意错稿通过而宣布普通草稿检查可靠。
3. **真实小说续写未达到指定场景，但输入存在竞争约束**：测试要求白天公共场所的日常对话，原章节却停在家庭客厅对话中；服务又自动追加“紧密接续前文……严禁无故重置场景开局”。实际模型请求包含两者，输出延续家庭客厅。场景要求未通过，但测试没有明确转场安排，服务也未消解作者转场要求与默认承接规则，不能单独归因为模型忽视明确无冲突的指令。没有重演已结束事件或输出露骨内容。
4. **普通续写篇幅偏长，另一个用例存在长度输入错误**：按产品正文计数口径（去空白，保留标点），普通续写目标约 500 字、实际 890 字；此前 941 字符是含标题和空白的原始响应长度。真实小说续写为 576／500，Agent 草稿为 514／约 500。空报告用例指令写约 350 字，却继承 `targetWords: 500`，实际正文 655 字，不能作为单一 350 字目标的合格评估。产品长度要求为软提示，现有质量提示没有超长检测。保留实际结果，不反复生成直到命中目标。

上述场景约束与长度口径是在用户追问后离线复核实际请求、草稿和服务代码所得的归因修正；没有增加模型调用，也没有改写原始实测记录。报告传递与版本冻结的通过记录不能代替生成内容验收；这些内容问题也不能直接证明小说分析替换链路失效。

内容判断由实现助手逐项阅读，另有一个子代理独立检查 iOS 源码和 Agent 证据；不是作者实用验收或独立整书审稿。未覆盖浏览器交互、iOS 编译与真机，以及任意长篇的持续多轮表现。
