## 第二故事为何未通过

诊断共五次首章尝试：前两次因“山站管理员燕棠也叫小棠”的职务前缀被别名身份规则拒绝；第三、第五次引用了未声明的“三角符号”；第四次将“山站的电闸”归一成“山站电闸”，未通过新增实体的字面匹配。

职务前缀已增加有边界的支持并补充否定、猜测、问句和任意前缀的回归。随后在 `7dbd23f7` 上用空的隔离数据库清空重跑，首章仍因“山站电闸”与“山站的电闸”不完全匹配而失败。这是名称归一能力不足，不能笼统解释为模型编造了不存在的物品。

两个运行都保存了费用和失败原因，但没有保存任何有效章，第 2–10 章未执行。**51 条内容预期全部未获得有效输出验收**；空记录上的引文、认知主体和唯一性检查即使返回 true，也没有正面质量证明力。保留失败结果后停止追加付费尝试，没有为了提高完成数字放松身份校验或改写故事。

## 下一步建议

1. 补齐目标／计划的结束契约，明确完成、取消、替代与继续有效；重点覆盖“完成事件已写、旧目标仍 active”的漏关联，避免通过改标签或类别绕开更新。
2. 对名称归一增加可核对的来源映射，先处理“山站的电闸 → 山站电闸”等有限表达，同时保留不同实体和相近姓名的反例。不能简单去掉全文所有“的”或允许模糊别名合并。
3. 拆开认知、位置、进度与计划摘要，评估新增摘要是否包含原文未支持的信息；不能只依赖引文逐字匹配。
4. 修正后冻结代码、提示词和配置，新增未参与调整的故事，从空数据库评估首次通过及有限人工重试，逐条审查内容，再考虑长章、真实长篇和流式路径。当前短样本不足以证明生产成本、吞吐或长期质量。
