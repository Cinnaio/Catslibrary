## 人工复核发现

1. **模型依然会混写目标与进度。** 第二次抽取的目标摘要为“顾澜决定检修北塔的钟，尚未动工。”新守卫阻止它进入持续目标，但一次拦截不能证明长期目标进度已经可靠。
2. **复核范围存在理解偏差。** 第三次草稿已有的 3 个新目标已经进入普通 `checks`；`goalChecks` 应只审查 `goalReviews` 中的旧目标决定。本次空清单却产生 3 个新目标 ID，导致格式契约失败。这类过度复核不应通过放松目标结束关联解决。
3. **复核模型漏掉了真实的摘要遗漏。** 第三次草稿记录封箱存放在库房、尚未开启，但没有保存“箱内内容未知”。记录 `f_021158c07bb2d05c12d7262e` 的摘要只有“封箱未开。”，引文才包含“内容无人知道”。复核的 `cognition` 却判定 covered，理由声称草稿已保留“内容无人知道”。这是把引文信息误当成已保存摘要，属于人工确认的漏判。即使允许额外的 `goalChecks`，也不能把该草稿算成内容通过。
4. **名称映射没有证明全程稳定。** 第三次已解析草稿中，南塔的钟可有限归一；北塔的钟与北塔钟在首章都出现，既有双拼写保护保守保留原名。两座塔的钟与顾澜/顾岚没有合并，但后续不同写法的引用未运行，不能推断整书实体一致性通过。
5. 原始结构检查除 fullCoverage 外显示 true，但检查对象为空集。它们仅表示没有已保存的违规记录，不能当作引文、认知或状态唯一性的实测准确率。
