# v9 目标结构与覆盖映射开发诊断

本轮在 `codex/story-memory-semantics` 继续，父提交 `dd6bdf6d`。这是已知样本开发诊断，不是未见样本验收；v8 的原始失败和预算不变。

## 实现

- 新目标仅提交 `goals[{subjects, objective, quote}]`，程序生成稳定意图摘要；执行进度继续独立保存。旧目标的复核清单由服务端给出，空清单不允许填入本段新目标。原始目标中的多分句在名称整理前检查，替代目标引用与目标使用相同的有限后缀规则。
- 明确规范名与已核实别名是同一实体，不建立自身关系；保留原文别名证据、有限地点物品名称映射及相近姓名反例，不加入模糊合并。
- 覆盖复核逐项列出正文断言、原文片段和实际已保存摘要 ID/片段。程序验证来源、目标范围和摘要片段，禁止把引文信息冒充已保存摘要。事件不能替代当前状态；有旧记录关联的目标/约束结束可以用结束记录覆盖。
- 复核输入分开摘要和证据，保留历史标记与替换关系。来源逐字匹配及摘要映射仍不是语义蕴含证明；模型的遗漏和误判单独统计。
- 抽取规则升到 v9；暂停、失败保留检查点、手动重试、两阶段计账和整章原子性继续沿用。旧规则检查点不能直接作为新规则有效前缀，不自动重建任何真实小说。

## 八个成对复核诊断

原始上下文、输出、提示词哈希和用量见 [复核原始结果](story-memory-v9-review-development-2026-11-10.json)。每例一次调用、无重试；以下是人工逐条阅读后的判断。

| 用例 | 预期 | 实际 | 判定来源 |
| --- | --- | --- | --- |
| 内容未知漏存 | 拒绝 | 拒绝 | 模型指出未知内容没有对应摘要。 |
| 内容未知已存 | 接受 | 接受 | 与独立未知线索正确关联。 |
| 进度夹带人物位置 | 拒绝 | 接受 | 模型漏判；生产抽取前置的明确模式检查会拦截这条混写。 |
| 位置与进度拆开 | 接受 | 接受 | 未误拒正确拆分。 |
| 水池已排空的当前结果 | 接受 | 接受 | 未把动作完成等同记录失效。 |
| 排空事件缺少当前状态 | 拒绝 | 拒绝 | 模型判 covered；程序的状态类型检查拦截，不能算模型检出。 |
| 新目标且旧目标清单为空 | 接受 | 接受 | 正确省略旧目标复核。 |
| 换妥后旧目标仍 continue | 拒绝 | 拒绝 | 模型识别另一种完成措辞，指出旧目标过时。 |

运行结果符合预期 7/8；四个错误样例中模型自行识别 2/4，程序另拦截 1/4；四个正确样例全部接受。样本很小且已知，不估计一般准确率。共 8 次调用，8,126 输入 + 2,822 输出 = 10,948 Token，8 次均回报 USD 费用，累计 312.6 millicents = USD 0.003126。

这组诊断之后补充了已取消约束的覆盖规则、历史可见性和目标原始多分句检查。因此其提示词哈希是当时的开发版本，不能冒称最终冻结版本的八例重跑。
