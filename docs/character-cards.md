# 这个人，我见过吗？

Web 与 iOS 在线阅读时，选中同一段正文中的人名或称呼，点击「这个人，我见过吗？」打开人物小卡，再点「查看人物线索」开始查找。打开面板不自动生成，也不消耗 AI 额度。支持 1–40 个 UTF-16 单元；过长选区要求重新选择，不截成人名。

## 阅读体验

- 按「此前出现」「人物联系」「最近动向」整理原文线索，每类最多两条，证据不足时可以缺项或为空。不宣称是全书完整人物档案。
- 每条包含原文引用、AI 整理的说明及回读按钮。有身份或关系歧义的条目标注「身份或关系待确认」。同名不代表同一人，不自动合并别名或代词。
- 回读出处后可以「返回刚才的人名」。同章或跨章跳转均重新读取正文，并核对段落指纹；正文变动导致无法定位时提示重新查找。
- Web 使用共享 ReadingDialog，iOS 使用 ReaderPanelPage，沿用暖纸底、衬线引文、轻量阶梯入场与减少动态效果。iOS 滚动阅读与分页阅读均接入原生选词菜单，跨段选区要求重新选择。
- 面板打开时暂停阅读统计与自动滚动，关闭、切章、账号或内容权限状态变化后不接收过期结果。离线阅读不提供入口。

## 取材与判断边界

服务端核对当前章节、段落指纹与选中的文字，仅使用目录 `(sort_order, id)` 在当前章之前的章节，以及当前章选中名字之前的正文。同段有重复名字时，保守地采用最早一次出现位置；不会用较后同名位置之前的文字扩大取材范围。

模型不接收书名、章节标题、后文章节、全书摘要或故事记忆库。检索按选中名字的字面形式匹配，不拆词补全人名，也不自动搜索其他身份。带 HTML 标签、别名、省略称呼或不同书写形式的出现可能被遗漏，空结果不代表人物此前未出现。

最多检查 60 个相关前文章节。匹配较多时兼顾最早 20 章和最近 40 章；每章保留较早两处及较近四处候选，再从所有候选取最早四处与最近十六处，合计最多 20 处、每处最多 440 字符。另附名字之前最多 1,200 字符的上下文。界面说明筛选范围与截断，不把「此前出现」称为首次登场；「最近动向」只表示本次候选中的较近记录。

提示词要求仅依据候选整理、原文明示才标 supported，身份或联系不清标 uncertain，没有依据则省略。服务端逐条核验候选编号、分类、确定性标记、引用长度、原文连续逐字匹配、完整名字及重复条目。**这些检查只能验证引文出处和结构，不能证明模型的关系判断正确，也不能保证模型不会凭已有知识做出错误推断。** 实际人物识别与说明质量仍需真实模型阅读验收。

## 接口、额度与权限

- `GET /api/ai/status` 增加可选 `features.characterCards`。需要登录、已配置文本 AI 及现有 `recapEnabled` 开关。旧 API 缺少能力字段时两端隐藏入口。
- `POST /api/ai/character-card` 接收 `chapterId`、`paragraphIndex`、`paragraphHash`、`selectedText` 与可选 `sourceFormat: "text"`。原生端使用纯文本段落定位。
- 返回 `anchor`、`items`、`cached`、`generated`、`searchedChapters`、`candidateCount`、`limited`、`omitted`、`model`。条目包含 `source`、`explanation`、`kind`（appearance / relationship / recent）及 `certainty`（supported / uncertain）。响应为 `private, no-store`。
- 共用读者 AI 额度，审计类型为 `character_card`。无候选时不调用模型；完成调用后即使输出格式无效或正文变化导致丢弃，仍记录用量。上游异常沿用现有额度预留处理。
- 人物小卡与回声按用途分别缓存，按账号、选段、正文与目录版本、模型配置隔离；共用最多 128 条、30 分钟的进程内缓存。重启或跨进程可能重新生成，不落库保存人物档案。
- 相同请求合并，不同前文查询按账号限制并发。生成前后及缓存复用时核对内容版本，接口返回前再次验证当前作品权限；账号与内容模式变化时客户端丢弃迟到结果。
