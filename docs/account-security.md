## 权限边界

| 能力 | 读者 reader | 管理员 admin | 超级管理员 super_admin |
| --- | --- | --- | --- |
| 阅读、本人资料、密码、邮箱与 Passkey | 本人 | 本人 | 本人 |
| 内容、抓取任务、创作、审核、运营指标和 AI 用量 | 按原读者策略 | 可管理 | 可管理 |
| 邀请码、账号目录、登录和操作审计 | 无 | 可管理 | 可管理 |
| 禁用、恢复、删除账号；撤销会话；发送重置邮件 | 无 | 仅普通读者 | 读者及管理员 |
| 授予或撤销 admin / super_admin | 无 | 无 | 可管理 |
| 注册模式、站点设置、公告、内容访问总策略 | 无 | 无 | 可管理 |
| AI 供应商和运行参数、出站代理及日志、源站账号凭据 | 无 | 无 | 可管理 |
| 备份、演练和恢复 | 无 | 无 | 可管理 |

Web 隐藏受限入口并拦截深链、已保存的配置子页；iOS 同步分层。最终权限由 API 判定。运营指标 GET 对管理员开放，公告 PUT 仅超级管理员可用。原有 AI 读者策略中的 `admin` 选项包含超级管理员。

账号变更须提交 `reason`、`expectedRole`、`expectedStatus`；删除另须 `confirmUsername`。服务端在事务内取得账号锁、重读操作者与目标、核对快照，并保留最后一位启用的超级管理员。禁止禁用或删除本人。敏感管理写操作沿用近期身份验证要求，Web 使用现有验证弹窗，iOS 账号操作要求当前密码。

角色、状态、删除和会话撤销会清除目标全部会话及待确认邮件链接。邮件重置申请只发送链接，用户确认新密码时才使旧密码及会话失效。审计保存操作者、对象、原因、结果和前后状态；不保存密码或邮件令牌，快照不包含邮箱地址。

## 首次安装与旧站升级

全新空站的安装流程创建 `super_admin`。永久 `site_initialization` 标记防止删除用户后重新开放安装；已有用户的旧站也视为已初始化。迁移 `070_account_security.sql` 添加角色约束、邮箱、邮件令牌和账号审计表，**不会自动提升任何已有管理员**。

旧站升级需安排维护窗口，并由站点所有者明确给出已有账号的用户名：

1. 备份数据库和私有配置，保留匹配旧备份的旧版程序与恢复工具。停止旧 API 及后台写入进程；不要让旧程序继续写入已经迁移的数据库。
2. 准备包含本次改动的 API / Web 配套产物、依赖和原有数据库配置。确认恢复工具所在版本包含迁移 070。
3. 使用相同数据库配置和服务运行身份执行下列命令之一。命令先应用迁移，再将**明确指定的已有账号**设为启用的超级管理员，并撤销其会话、邮件链接，记录恢复原因。命令不创建账号、不设置密码。

```sh
# 源码环境，在仓库根目录运行；替换占位用户名和原因
npm run admin:recover -- --username EXISTING_USERNAME --reason "站点所有者确认的首次权限迁移"

# 已构建的生产产物；需保留整个 api/dist（含共享 chunk 和 migrations）及运行依赖
node api/dist/recover-super-admin.js --username EXISTING_USERNAME --reason "站点所有者确认的首次权限迁移"
```

4. 启动新版 API 与配套 Web，用被指定账号重新登录，并复核普通管理员、读者和超级管理员的入口与权限。
5. 配置账号邮件并进行经授权的实际投递验收；再交付与新接口配套的 iOS 构建。

已有站点没有启用的超级管理员时，新 API 会在迁移后拒绝启动并提示恢复命令。这是升级前置步骤，不应通过重新开放 `/install`、自动选择最早账号或跳过检查来处理。现有自动发布流程不会代替站点所有者指定账号；首次升级应先安排上述恢复步骤，再激活新版服务。

若站点所有账号已删除，永久初始化标记仍生效，而恢复命令不会创建账号；应从可信备份恢复已有账号，再明确执行权限恢复。遗失密码但没有已验证邮箱时，恢复超级管理员命令也不能替代身份核实或密码找回。

## 邮件配置

API/Web 0.6.0 起，超级管理员可在“站点设置 → 账号邮件”直接填写 SMTP 服务器、端口、TLS／STARTTLS、账号、密码／授权码、发件身份和邮件链接站点。保存后立即供账户邮件使用，无需编辑 `.env` 或重启服务。密码不回显，留空保留当前密码（包括首次保存时的环境密码），勾选清除才移除；输入新密码则替换。

后台保存的整套配置优先于 `SMTP_URL`、`MAIL_FROM`、`PUBLIC_WEB_URL`；尚未保存时继续使用这些环境变量，无需手动迁移原凭据。环境配置方式仍可使用，修改环境变量后须重启 API：

```dotenv
NODE_ENV=production
SMTP_URL=smtps://smtp-user:replace-with-secret@smtp.example.com:465
MAIL_FROM=知舟 <no-reply@example.com>
PUBLIC_WEB_URL=https://read.example.com
```

- `SMTP_URL` 支持 `smtps://` 隐式 TLS，或 `smtp://` 强制 STARTTLS；用户名和密码中的特殊字符需 URL 编码。拒绝 URL 查询参数，不允许用其关闭 TLS。
- `PUBLIC_WEB_URL` 仅为固定 origin，不带路径、参数、账号或密码；生产必须 HTTPS。不会从请求 Host 构造邮件链接。该地址应指向运行配套 Web 的站点，与 SEO 的 `SITE_URL` 分别配置。
- `MAIL_FROM` 为发送身份；SMTP 服务端及域名发信配置须由部署者配置。
- “测试已保存的连接”只检测 SMTP 连接、TLS 和认证，不发送邮件；有未保存修改时须先保存。配置齐全、连接通过、SMTP 接受与邮箱实际收到是不同状态。测试按超级管理员账号限流，每 15 分钟最多 3 次。
- SMTP 超时、认证和投递失败均转换为不含凭据的错误，不输出原始 SMTP 调试日志。关闭邮件内容的外部文件和 URL 读取。

后台配置写入服务器私有 `data/mail-config.json`（部署者可用 `MAIL_CONFIG_FILE` 指定持久化位置），含 SMTP 凭据，按部署密钥对待；采用临时文件、原子替换和 `0600` 文件权限，新建目录为 `0700`，Windows 仍须通过目录 ACL 限制访问。它不是加密文件，禁止放到网站静态目录、提交 Git 或上传构建制品。数据库备份不包含此文件，迁移和灾备须单独安全备份并恢复，多个 API 实例须使用同一持久化文件。文件损坏或不可读时拒绝发信，不静默回退旧环境配置；如需恢复环境来源，部署者应在维护期间安全移走该文件。

`GET /api/auth/mail-settings`、`PUT /api/auth/mail-settings` 和 `POST /api/auth/mail-settings/test` 仅超级管理员可用；公开 `/api/auth/mail-status` 仍只返回 `ready`。管理读取只返回非密码字段、来源、修订号及 `passwordSet`。保存通过共享数据库锁串行化并核对修订号，旧修订返回 409，草稿不会自动覆盖较新的配置；撤销后重新读取最新配置。分区切换保留内存草稿，刷新或关闭页面前对未保存修改提示。

本地开发可不配置 SMTP，而设置 `MAIL_OUTBOX_DIR=data/mail-outbox`；默认链接 origin 为 `http://localhost:5173`，也可显式设置。只有非 production 环境启用 outbox，且有 SMTP 配置时优先走 SMTP。outbox 包含可用的一次性链接，必须放在静态目录之外并限制访问，不提交 Git，不上传制品；仓库 `data/` 已忽略。文件创建使用 `0700/0600` 权限，Windows 仍需通过目录 ACL 限制访问。

## 用户流程与接口

保持用户名密码注册和登录、Passkey 登录，不把邮箱改为强制注册条件。

| 接口（相对 /api/auth） | 身份 | 用途 |
| --- | --- | --- |
| GET /mail-status | 公开 | 仅返回 ready |
| GET /mail-settings | 超级管理员 | 脱敏配置摘要 |
| POST /email/request | 已登录 + 当前密码 | 申请绑定或替换邮箱 |
| POST /email/verify | 邮件 token | 确认邮箱 |
| POST /forgot-password | 公开 | 使用 identifier（用户名或已验证邮箱）申请重置 |
| POST /reset-password | 邮件 token | 使用 password 设置 8–512 位新密码 |

邮箱按大小写不敏感唯一；验证新邮箱前，旧邮箱保持有效。验证链接有效期 24 小时，重置链接有效期 30 分钟。令牌随机生成、只保存哈希、限定用途且仅可使用一次；同用途再次申请使旧链接失效。确认邮箱或新密码后，所有旧会话和该账号的待确认邮件链接失效；Passkey 凭据保留。

链接令牌位于 URL fragment，Web 读取后清理地址栏；打开链接不会立即消费，用户需显式确认。刷新已清理令牌的页面需重新打开邮件链接。三条邮件页面路由在生产返回 HTTP 200，并带 noindex；访问统计不记录这些页面。

找回密码对不存在账号、未绑定邮箱、禁用账号和可发送账号使用相同响应文案。发送异步执行，SMTP 失败不会向匿名请求暴露账号存在性。使用数据库限流：每个身份键每 15 分钟 3 次，每个 IP 每 15 分钟 20 次，已解析账号另按用户 ID 限流。反代 IP 仅在可信代理配置正确时有效。

异步发信当前不是持久化队列，进程退出可能中断发送，用户可稍后重新申请。申请审计先记 pending，SMTP 接受或 outbox 写入后记 accepted/completed，失败记 failed 并失效对应令牌；重启中断的 pending 不代表已投递。

## 跨端与备份兼容

- API / Web 应配套更新。旧 `set-password` 操作返回 410；旧客户端的账号变更缺少原因和状态快照时会被拒绝，不能继续签发临时密码。
- iOS 支持三级角色、邮箱绑定、密码找回和新的管理员操作。邮件内确认在浏览器完成，然后返回 App 重新登录；本次未添加 App 内令牌深链。
- iOS 邮箱字段可选，旧 API 仍可解码；新邮件功能要求新版 API。旧 iOS 不识别超级管理员及新管理协议，应随本次更新。
- 新版备份与恢复仅超级管理员可用，恢复后清除会话及邮件令牌，并要求至少一位启用的超级管理员。
- **迁移版本低于 070 的备份不能直接在新版执行演练或恢复。** 在独立、无公网访问的环境中使用匹配旧版本及其恢复工具恢复备份，停止旧服务，升级迁移并明确执行 `admin:recover`；核对数据后再由新版生成备份。不要修改签名归档、伪造迁移版本或自动提升旧管理员来绕过预检。
- 数据库迁移和角色协议已变化，回滚程序前应使用升级前备份及其匹配版本；不能仅换回旧 Web/API 仍让其写入新数据库。
