# 小说分析事实与引用准确性修复方案

日期：2026-11-10。基线：`2a8e22bc`，分支 `codex/ai-writing-analysis-workspace`。

状态：已按用户授权完成首版实现与有界验证，并在当前分支本地提交。实际结果和限制见[验收记录](diagnostics/novel-analysis-evidence-2026-11-10.md)。下文保留批准时的设计，具体交付以验收记录为准。本方案只针对人物在场／知情等事实误判、概括冒充直接引语、跨章引用错位，以及这些问题向续写和 Agent 传递的影响。篇幅和此前内容要求偏离不列入本轮处理；场景遵循及草稿审阅耗时另行记录。

## 目标与证据

目标是让作者能定位、修正有依据的错误，并让后续创作识别报告中的已知疑点。报告继续以可读 Markdown 呈现，核对信息绑定这份报告及其版本，不恢复续写档案或另一套跨章节状态库。

已知样本见[有界核对记录](diagnostics/novel-analysis-acceptance-2026-11-10.md)和[引句诊断](diagnostics/novel-analysis-bounded-review-2026-11-10.json)：

| 问题 | 现有证据 | 修复应达到的结果 |
| --- | --- | --- |
| 在场范围误判 | 把“担心被父母看见”扩大为父母已经在场 | 区分担心、推断和实际在场；指出依据不足或原文冲突，不补造知情与后续反应 |
| 概括被当作直接引语 | Q02为17字符第三人称概括，原意基本一致但不是连续原句 | 保留准确概括时移除直接引文形式，或换成经核验的原句 |
| 跨章问答引用错位 | Q05的问题在S92，接续回答在S93 | 问、答分别定位各自来源，不靠整段出现过两个编号就算正确 |

12处已知引句中11处有对应连续原文，不能据此计算全书准确率。后续验收需要同时保留正确样本，避免靠删掉所有引文或把所有结论写成“无法确认”获得表面通过。

## 当前代码缺口

- `api/src/services/ai/novel-analysis-prompts.ts` 已要求区分事件、认知、推断与准确引文；继续叠加同义提示缺少验证收益。
- `api/src/services/ai/novel-analysis.ts` 的短范围和长范围出口在响应完整、非空且未超大小后直接保存 Markdown，没有逐项引用核验或事实审阅结果。
- `source_json` 已保存精确的归一化正文、章节、分段、偏移和修订，可直接作为核对依据。`checked_source_ids` 只表示回读过，不能代表结论已核实。
- `NovelAnalysisMarkdown.tsx` 只把存在的S编号转换成来源按钮，不能证明引用文本或段落判断受该来源支持。
- `analysis-reference.ts` 已有同书、起点、来源变化、报告修订保护，但可用性不包含语义核对状态。`agent-retrieval.ts` 返回章节映射，尚无逐判断的证据及疑点。
- `editAnalysis` 已保留模型原稿并使用修订冲突保护，适合承接作者确认后的局部修订。

## 推荐实施顺序

### 1. 先固定失败样本与正确对照

建立独立的报告核对用例，不混入场景或篇幅测试。保存报告版本、来源指纹、待核对段落、预期判断及人工判定依据。

- 现有私有样本只在忽略目录复现；公开仓库使用不含原书文本的等价合成样本。
- 事实组至少覆盖：担心被看见／实际在场、听说／目睹、人物误解／客观事实、计划／已完成、后文纠正早期判断。
- 引用组覆盖：连续原句、概括加引号、省略拼接、错误章节、问答分属相邻章、同一句在多处出现、概念性引号、同章分段边界。
- 每组包括应保留的正确版本，记录漏报、误报和修改后是否仍保留原意。
- 先整理已知三处问题的最小修订建议供核对；实施时不直接覆盖开发库现有报告。

### 2. 增加无需模型调用的引用核验

新增独立的 `novel-analysis-evidence.ts`，输入有效报告文本及其冻结 `AnalysisSource[]`，输出定位到报告片段的核对结果。

1. 识别明确的直接引文、来源标记及句／段边界。概念、术语、书名等引号不直接判为错误；无法确定是否为引语的项目标成待核对。
2. 先核验所标来源中的连续原文。直接引文保持原字词和标点；可诊断排版空白差异，但不能把近似匹配或省略拼接标成逐字一致。
3. 引文在所标来源未命中时，可在本报告冻结范围内定位候选出处；唯一匹配也只是出处修订建议，多处匹配须显示歧义。不能拿范围外章节补证。
4. 同章相邻分段可按连续偏移核对跨段引文；跨章问答分别列出证据，不拼成一个连续引句。
5. 每项至少包含问题类型、报告位置、原引用、实际匹配或候选来源及原文位置。范围和偏移由程序校验，不能直接信任模型给出的数字。
6. 扫描数量或文本预算达到上限时返回部分核对及覆盖范围；零条发现不显示“报告全部正确”。

新生成报告在保存完成前运行一次；作者保存修订时针对新文本重新运行。检查不修改报告正文，不因单个错引使整份已完成报告丢失，也不自动发起付费修复。历史报告按需检查，不后台批量重生成。

新生成报告的表达约定同步明确：逐字引用与概括分开，跨章事实分句附来源。旧报告中的歧义引号仍按保守规则处理，不能通过机械删除引号假装修复。

### 3. 对重要事实提供一次有界的原文核对

在报告已有操作区增加“核对主要结论”。第一版由作者显式触发；打开报告、自动选用报告和引用核验均不新增模型调用。先证明对已知问题有效，再评估是否在生成末尾自动启用。

核对输入：报告的主要结论段、引用核验发现的疑点段及作者选定段落。建议首版最多8段，全部限制在当前报告修订中；覆盖范围明确列出。程序组装这些段落引用的冻结原文，必要时附范围内相邻上下文，原文总量初始上限24000字符。预算不足时缩小本次覆盖，不能截断后声称已经核对完整。

模型只检查给定判断与实际原文的关系，返回：

- 被检查的报告原句及其位置标识。
- 发现类型：事实冲突、把认知／计划／推断写成事实、证据不足、引用位置问题。
- 支持判断的连续原文及来源，必要时分别给出不同章节的证据。
- 最小修订建议；证据不足时说明缺什么，不能编造人物在场、动机或交接过程。

候选初始预算为每次显式操作最多1次模型调用，沿用当前供应商、思考设置及分析超时设置，流式接收并正常计量，不自动重试。输出格式使用小型JSON对象；代码验证结构和每条证据，不把供应商声称支持严格schema当成正确性保证。结构非法、空响应、超时分别记录，逐条证据不合格时保留其余可用项并标记核对不完整。

引文确实存在不等于模型的判断必然正确。前端显示“可能存在事实冲突／依据不足”，展示原文及建议，由作者决定是否应用；不把模型自评包装成全书事实认证。原报告始终可阅读，失败不会覆盖旧核对结果或作者修订。

此步骤能修复已发现错误并降低重要判断误用，但不承诺一次检查覆盖整本长篇。未引用、未选中或缺乏充分上下文的判断仍属于未核对范围。

### 4. 修订、版本与下游使用一起收口

增加报告专属核对记录，建议使用独立 `novel_analysis_reviews` 表，避免把审阅结果塞进阅读笔记。键绑定 `reportId + reportRevision + effectiveContentHash + sourceFingerprint + checkerVersion`，区分纯引用检查与模型事实核对，并记录覆盖范围、问题、调用状态及用量。下一迁移编号在实施时重新核对，当前不创建或执行迁移。

- 核对状态与生成任务状态分开：报告已生成、引用已检查、部分事实已核对是三种不同信息。
- 核对操作使用独立任务及幂等请求标识，不替换原报告的生成任务，不套用原来的“继续分析”分支。
- 人工修订后旧核对结果过期；旧结果仍可查阅，但不能附到新文本上。模型原稿与有效人工版本分别按各自文本匹配，不共享错误的“已检查”标签。
- 核对请求与应用建议携带预期报告版本。模型调用期间发生修订时，迟到结果只保留为旧版本记录，不覆盖新报告。
- 接受建议时展示最小差异，复用现有修订版本保护；保留模型原稿。应用后重跑本地引用核验，原事实核对结果不能自动升级为新版本已通过。
- 原文变化时沿用已有失效机制；历史核对针对冻结快照仍可查看，但不能当作当前章节依据。

后续创作与Agent同步拿到当前版本的核对摘要和原文证据。自动推荐时先避开存在未处理重要事实疑点的报告；若没有其他参考，保持现有仅凭正文创作能力。手动选择仍允许作者阅读和决定，明确展示疑点；选用时把疑点及有界的对应原文一起冻结进本次上下文，不悄悄删改作者报告。

对存在疑点的Agent判断，返回具体来源和核对状态，继续以回读原文为依据；不能仅通过再次添加一句“原文优先”宣称防止了错误传播。旧任务快照保持不变，新增元数据以可选字段兼容，版本检查仍沿用原契约。

## 验证与交付门槛

先验证引用规则，再跑事实核对与下游使用。只做与改动直接相关的测试。

1. **确定性测试**：概括不能标为逐字一致；问答必须分别对应正确来源；已知11处正确引文仍保留；歧义匹配、概念引号、跨段、Unicode和空白处理均有对照。
2. **服务测试**：短／长生成出口、人工修订、旧报告、原文变化、跨书、版本竞争、超时、取消和迟到结果；检查失效不会擦除内容或重复记账。
3. **界面与集成测试**：问题跳转原文、修订比较、并发修订保护；自动推荐和Agent使用的是匹配版本的状态，报告疑点不会被显示成已核实事实。
4. **真实语义实测**：先冻结上述三类缺陷、对应正确版本及额外未参与提示调整的样本。先使用一个小批次（建议不超过8次调用），每个已冻结用例一次，保存成功、失败、成本和超时，不反复生成挑选结果。
5. **针对已知错误的验收**：在场范围不再被确认成事实；Q02明确区分概括与原句；Q05拆分S92／S93；正确事实与引文不被无依据删除。至少验证一条“报告有疑点→作者核对修订→续写／Agent使用新版本”的完整链路。
6. **改善证据**：报告漏报和误报，人工检查事实判断；引用字面匹配、JSON合法和HTTP成功单独记录。通过固定样本后才能称“这些问题已修复”，不得扩展为整书或所有模型准确率。

实测在独立数据库与冻结来源中运行；先确认新服务的单次请求成本与超时表现，再确定需要覆盖的长范围流程。候选若没有实际改善则撤回，原失败保留，不通过增加思考额度或更换模型掩盖本轮结果。

评测原则参考OpenAI官方评测指南关于任务相关样本、正确／边界样本和人工校准的建议；实际协议和能力以本项目供应商为准：`https://developers.openai.com/api/docs/guides/evaluation-best-practices`。
