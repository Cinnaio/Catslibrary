## 持久化与兼容

- 原 `zhizhou.readerProgress.user.*` 待发队列和 tombstone 格式保持不变。
- 新增 `zhizhou.readerPosition.user.*`，保存最新位置及已知删除时间。激活账号时合并旧待发队列，确认上传或删除后仍保留用于本地恢复和拒绝旧响应的信息。
- 服务端读取响应的 `tombstone` 是可选字段，兼容没有该字段的旧响应；合并不把远端已确认位置重新加入上传队列。
- 离线正文目录、缓存目录和用户命名空间不迁移。缓存索引仅在内存保存，重启重建；显式检查用量可校正系统清理 Caches 导致的偏差。
- 本地注销保留账号的待发数据，后续同账号登录继续补传。撤销请求使用捕获的 URL 和旧 token，不读取新会话，也不通过该请求的 401 清理新账号。

## 已新增、尚未执行的回归用例

`ZhiZhouCore` 新增六项：

1. 上传确认后重新创建 outbox，仍可离线读取最新位置，且不同账号隔离。
2. 较旧远端位置不覆盖本机位置，较新远端位置不被重新加入上传队列。
3. 删除确认后重启仍拒绝旧远端位置，同时间戳写入被拒绝，较新阅读可以恢复。
4. 旧 pending 数据迁入位置快照，远端删除只清除不晚于它的本机数据。
5. 覆盖写入与迁入离线目录后，缓存预算保持正确。
6. 缓存重启重建索引、跨账号淘汰与账号清理后，预算保持正确。

`ZhiZhouTests` 新增一项：在离线刷新等待文件校验时删除章节，恢复校验后旧清单不能把章节加回来，重建 store 后仍保持删除结果。用例通过注入文件操作隔离真实网络和其他账号文件。

当前 Windows 无 Swift/Xcode，以上七项 XCTest **未执行**。已有 Core 用例也未在本轮重新运行。macOS 上先运行 `ProgressReliabilityTests`、`CacheStorageTests`，并通过 `ZhiZhouReaderTests` scheme 执行 `OfflineReadingStoreTests`；再按审查报告场景覆盖阅读器和 iPad UI。发布前需完成 Release 编译和归档检查。
